# AlphaRap 自动化框架操作 SOP

版本 1.2　更新日期 2026 年 10 月 26 日

适用版本：AlphaRap 2.08 现有功能／条件节点版本。保留实际对象动作绑定，移除 C# 脚本和代码模块；旧 Word 版或历史截图可能仍显示旧入口。

本文面向应用工程师和现场维护人员，说明如何配置现有对象、编排流程、调试、保存配置和运行设备。首次使用建议先完成第 13 章的离线练习，再配置现场硬件。日常操作人员可优先阅读第 1、2、11、12、14 章。

阅读导航：开机和换型见第 2 至 3 章；资源配置见第 4 至 7 章；流程编排和调试见第 8 至 10 章；记录和练习见第 11 至 13 章；排障、备份和维护见第 14 至 16 章。Word 版可通过导航窗格按标题跳转。

## 1 开始前先认识五条规则

### 1.1 配置统一使用主界面保存

节点、轴、IO、常量和生产字段窗口中的【确定】，表示接受本次编辑到内存草稿。完成配置后，还要点击主界面【保存】，在确认窗口选择【是】，才能写入文件并发布运行版本。账号、型号文件、语言表、报警表和信号灯规则仍有原有独立行为，详见第 3、16 章。

【保存】确认窗口中，【否】表示放弃修改并恢复已保存配置；【取消】或关闭窗口表示保留草稿、暂不处理。不要把【否】理解为“以后再保存”。保存失败时先修正提示，不要按已保存处理。

### 1.2 型号和配方使用同一个管理入口

主界面的型号入口打开 ProductManagerForm。型号切换在这里完成，流程设计器不另选配方。Setting 是机器级数据；Recipe、轴点位及当前型号的视觉算法按各自配方配置切换。

### 1.3 先建真实对象 再绑定流程

轴在【硬件 → 轴资源】建立，输入输出在【手动 → IO 资源】建立，相机和 VPP 在【视觉】配置。在流程节点【现有功能 → 动作设置】选择这些已存在对象及方法；拖入节点不会自动创建轴、相机或设备。已有方法可通过选择参数和数据绑定编排，全新协议仍由开发人员先提供一次能力。

### 1.4 删除和属性优先找右键菜单

轴组合、IO 卡片及功能／条件 FlowChat 节点有右键属性和删除入口；代码节点不提供属性编辑，保留断点和删除。点位、条件、常量及生产字段在实际行上右键删除。被其他节点使用的对象或数据不能直接删除，应先解除引用。流程模块内还有节点时不能删除该模块。

### 1.5 配置保存与生产记录是两件事

主【保存】保存配置。生产 CSV、照片和 MES 记录由相应流程动作产生；只画好流程或点击主【保存】，不会自动生成一条生产记录。重启恢复设计和配置，不自动继续上次未完成的运动或点胶。

## 2 日常开机与关机

### 2.1 开机顺序

1. 从现场认可的完整程序目录启动 AlphaRap.exe，保持工作目录及依赖文件完整。开发调试的常用路径为 AlphaRap/bin/x64/Debug/AlphaRap.exe。
2. 等待启动加载结束，使用现场分配的账号登录。不要同时启动第二个实例。
3. 核对主界面当前型号、语言和报警。需要换型时，按第 3 章操作。
4. 核对设备当前状态、现场运动条件和必要的气源、通信。进入【硬件】或【手动】可能要求暂停设备，先读确认提示。
5. 有配置修改时先主【保存】并确认成功；退出所有流程模块的【编辑流程】状态。
6. 点击主界面【初始化】，等待所需模块完成初始化。初始化可能执行运动、回零及设备动作。
7. 排除未清报警后，点击主界面【启动】。观察首件动作、节点出口与实际数据。

正常结果：当前型号正确，初始化完成，启动后按已保存流程执行；相应生产保存节点执行成功后，才可查询到记录。

主工具条按图标悬停提示识别【初始化】【启动】【暂停】【停止】【清除报警】。旧语言包可能把前两项显示为【复位】【运行】，分别对应本手册的初始化和启动；不要与清除报警混淆。

### 2.2 暂停 停止与复位

- 【暂停】沿用流程节点边界语义。已经开始的动作可能继续完成；不要将界面暂停等同于轴或点胶立即冻结。节点执行及条件等待阶段的超时仍可能继续计时。
- 【启动】用于正常启动及按当前状态恢复。恢复前核对当前节点和现场产品状态，不重复手动发同一动作。
- 【停止】请求取消流程并停止相关运动。需同时确认模块已结束、轴已停止和资源已释放；仅看全局 IDLE 字样不足以确认所有旧任务已收尾。
- 【清除报警】用于清除已排除原因的报警，并复位当前报警轴；【初始化】用于重新建立设备/流程就绪状态。两者不是同一个动作。停止后通常需要重新初始化再启动。

### 2.3 关机顺序

1. 停止自动流程，确认运动结束，等待保存和上传调用返回。
2. 核对最后一件产品的实际加工状态、记录和必要的 MES 回执。超时或通信中断时保留待核对信息。
3. 处理未保存配置：主【保存】选择【是】提交，或明确选择【否】放弃。
4. 使用程序【退出】。若提示流程仍忙，等待并检查当前节点后再退出。

当前程序关闭仍包含强制结束进程的兼容路径，因此退出前要完成数据核对；不要依赖关闭窗口自动补传或保存运行中的工序。

## 3 登录 语言与型号管理

### 3.1 登录和权限

点击顶栏用户区域打开登录入口，使用本人账号。维护员或管理员还需要获授权的页面权限，才能编辑或测试流程。若【流程】不可进入或编辑不可用，先核对当前角色及原权限设置中的 Rapid／流程权限，不要通过修改 XML 绕过权限。

账号和权限由现场管理员在用户及权限页面维护。权限映射修改接入主【保存】；账号增删改按账户页面现有操作生效，不应把主【保存】当作账户撤销按钮。

### 3.2 切换显示语言

点击顶栏地球／CN 语言入口，选择中文、English 或 Español。检查当前页面标题、按钮和提示是否改变。语言选择即时写入 MachineSetup.ini，无需再主保存。用户自定义名称、参数键、条码、路径、VPP 名和生产字段保留原值，切换语言不会替用户翻译这些数据。

如需维护翻译，进入【系统 → Language】，使用该页面现有【修改 → 保存】处理；此页面目前保留独立保存行为。界面语言使用 Chinese.xml、English.xml、Español.xml；报警表的西语文件为 Spanish.xml。此类文件只由维护人员按项目规则修改。

### 3.3 使用已有型号

1. 停止设备并确认流程不再运行，处理当前配方中的常量、点位和 VPP 草稿。
2. 点击主界面型号入口，在型号列表选择目标型号。
3. 点击【使用选中型号】，确认主界面的当前型号已改变。
4. 检查该型号参数、轴点位和 VPP 是否成功加载。失败时不要继续初始化生产，应保留错误并核对整套配方。
5. 按需主【保存】，重新初始化后进行首件确认。

机器 Setting、轴/IO 的资源身份及驱动通道不随型号改变。流程工程目前属于机器配置；切换型号主要改变被流程引用的配方参数、点位和算法。

### 3.4 新建和删除型号

先保存当前作为模板的型号，在型号管理输入一个全新的型号名，再点击【新建型号】。当前实现以当前型号已保存的 XML 为模板，新建后还要选择新型号并点击【使用选中型号】。

新建名称不要与现有型号重复，当前复制实现可能覆盖同名 XML。新建型号不会完整克隆 VPP 算法，需要在新型号下逐一核对或配置视觉算法。不要据此认为新型号已经可以直接生产。

删除型号使用型号管理页现有【删除选中型号】按钮及确认框；当前使用的型号和 AllModel 基础型号受保护。型号删除是文件级操作，应先备份，不能按“主保存选否即可撤销”理解。

## 4 建立轴与维护点位

### 4.1 新增轴

1. 设备停止，进入【硬件 → 轴资源】。
2. 点击【新增轴】，填写便于识别的资源名称。
3. 选择实际驱动厂商及轴号，核对速度、加减速、脉冲当量、回零和限位等参数。不要用示例值直接替代设备参数。
4. 点击【确定】，检查轴组合出现在页面；这是草稿对象，此时不代表已连接。
5. 主【保存】成功后，在流程节点代码中安排实际需要的驱动连接和运动；主【初始化】只触发初始化流程，不自动连接或检测全部轴与 IO。

当前轴厂商支持 Adlink 和 Leadshine。Keyence、Omron 出现在 IO 的支持范围内，不表示当前已有相应轴驱动。现有雷赛轴实现没有 IP 初始化参数，不能按网口运动卡的方式填写。

轴号沿用当前 SDK 格式：雷赛一位数字 0–9；凌华三位数字且末位 0–3。不要重复添加同一物理通道。具体卡号、当量和限位由设备接线及驱动配置确定。

### 4.2 修改轴属性和手动操作

双击轴标题、右键【属性编辑】，或选中轴后点击【参数】，均可打开属性窗口。修改名称不改变资源稳定身份。已连接资源修改驱动参数后，需要主保存并重启，不能在线切换到另一物理轴。

在轴组合查看指令位置和编码器位置。回零、连续点动、定距离移动和【前往】都会影响实际设备，应在所选轴正确、资源空闲及现场条件允许时操作。点动方向和距离单位采用轴的实际配置。

### 4.3 建立和编辑点位表

1. 选择目标轴，使用受控手动操作到达待记录位置。
2. 点击【新增】，把当前编码器位置加入该轴表；填写易懂备注，例如取料位、拍照位。
3. 需要更新一行时先选中该行，再点击【替换】；替换使用当前编码器位置。
4. 点击【上移】改变整行顺序；在实际点位行右键【删除点位】删除该行。
5. 核对目标行后点击【前往】才会执行移动。新增、替换和上移是表编辑，不是运动命令。
6. 主【保存】写入当前型号的点位。切换型号后核对该轴表，再运行。

P1 对应内部索引 0，P2 对应 1。删除或上移会改变后续索引，必须核对相关移动节点的目标点位及配方输入绑定，再主保存。当前版本尚未全面使用稳定 PointId，不会自动修正已保存索引。

### 4.4 流程为什么只能看到一个点

轴方法只访问所选轴自己的绑定表。若轴页面只见 P1，确认该表是否只有一行，再检查坐标及限位。移动节点的【目标点位】列出本轴表的全部有效点，含序号、索引、备注和坐标；其他轴的点不会自动合并。新增点位后关闭并重新打开节点刷新选项，主保存后才参与正式运行。

## 5 建立输入 输出和设备对象

### 5.1 新增和查看 IO

1. 进入【手动 → IO 资源】，点击【新增输入】或【新增输出】。
2. 填写资源名称，选择真实厂商和点号或 PLC 地址。名称应表达设备含义，例如产品到位、点胶阀，不使用难以辨认的默认名。
3. 按厂商填写实际显示的参数。Keyence 使用 PLC IP、TCP 端口、软元件类型、数据格式和地址；Omron 使用 PLC IP、CIP 端口和地址；板卡 IO 使用点号及有效电平设置。
4. 点击【确定】，核对新卡片所属输入或输出分区并主【保存】；连接和读写由流程节点代码负责，添加卡片不会自动连接硬件。
5. 通过实际输入变化核对状态。输出卡片或开关可在权限、空闲和资源占用检查通过后切换输出。

板卡 IO 点号采用五位数字格式，前三位为卡号、后两位为点号。输入卡片显示输入状态，流程中读取输入；输出对象才提供输出设置等动作。两者不是任意互换的对象。

### 5.2 修改和删除资源

在实际 IO 卡片或轴组合上右键【属性编辑】或【删除资源】。右键目标就是操作目标，不依赖工具栏之前选中的对象。

删除前停止流程并解除节点动作、输入及条件中的引用。被占用、正在运动或权限不足时不能删除。删除后主【保存】才使下次启动不再生成该资源；历史配方点位表可能保留，不等于资源未删除。

### 5.3 Device 和气缸等其他对象

设备入口为【系统 → 参数设定 → 添加设备】。选择现有设备类，在生成的设备页签填写设备名及属性表中的 IP、端口等实际参数。点击【打开连接】查看状态和记录，按协议需要使用【发送】或【接收一次】核对响应，完成后主【保存】。气缸沿用项目原手动页面配置其关联 IO。

Device 手动断开使用【关闭连接】，移除使用页面【移除】按钮。先停止、解除流程引用并关闭连接，再移除；当前 Device 保护未与轴/IO 完全统一。Device 改名后要重新检查流程绑定。视觉和 Device 仍保留各自删除按钮，不能按“所有页面都已改成右键删除”操作。

节点【现有功能】的对象目录只列出当前已创建、可访问的实际对象及其已声明方法。

新建同类实例通常只需配置和绑定；全新的设备协议或新业务动作需要开发人员先为实际对象提供方法。出现空目录时先检查对象是否已在原页面建立、是否已登记，不要在节点中填写不存在的设备名。设备参数草稿也要使用主【保存】处理。

## 6 配置常量和托盘参数

### 6.1 Setting 和 Recipe 常量

进入【系统 → 系统设定 → 设计器常量】。默认系统子页可能是【参数设定】，需要再点【系统设定】。选择【Setting · 机器常量】或【Recipe · 当前配方常量】，点击【新增】，填写【常量键】【类型】【值】【说明】，再【确定】。

选中行点击【修改】或双击该行进入编辑窗口，列表本身只读；【查询键或说明】输入后即时过滤，清空恢复列表；在实际行右键【删除】。布尔编辑填 True 或 False，数值小数点使用英文句点。

- Setting：机器级值，切换型号保持独立。
- Recipe：当前型号的值，通过 ProductManagerForm 切换。
- 支持 Boolean、Integer、Number、Text。业务键应稳定、唯一且易读，显示说明用于解释含义。

以原有禁用扫码、空跑、禁用视觉等参数为例，它们作为常量存在，不会仅因填为 true 就自动跳过工艺；流程或既有业务代码必须明确读取并判断。

被节点引用的键不能直接删除、改名或改变类型。完成编辑后主【保存】；切换型号前先处理 Recipe 草稿。

### 6.2 在节点读取和设置表值

读取常量优先使用输入参数旁【绑定数据】，从【机器设置】或【当前配方】选择已有键；NEXT／CASE 条件也可直接选择常量。无需另加读取动作节点。

需要显式动作时，节点选【现有功能 → 常量表】、Setting 或 Recipe 及【读取常量值】或【设置表值】。在【表中参数】选键；设置时填写【新值】或绑定其他来源。返回【参数值】供下游直接选择，不需定义脚本端口。

设置表值修改实际表行，后续流程及新批次可以读取，保持原类型、不自动写文件。停止后主【保存】才持久化，主保存【否】恢复已保存值。模拟执行这种非硬件调用也会修改表值。手工页面草稿不会自动混入生产读取。

### 6.3 托盘偏移

先在【系统 → 平台设定】维护实际托盘行列数、行距、列距并主保存。节点选【现有功能 → 托盘计算】，选择实际托盘及【计算托盘穴位偏移】，穴位索引从 0 开始。

例如 3 行 4 列，行距 10、列距 20，序号 5 对应第 2 行第 2 列，返回 X 偏移 20、Y 偏移 10。下游 X／Y 轴移动节点可将 Offset 绑定到本节点的 OffsetX／OffsetY；轴基准点仍来自该轴自己的表，单位必须一致。

托盘方法只计算，不自动移动、不遍历整盘，也不管理穴位里的产品身份。完整搬运工艺和循环需明确编排，并遵守运行器产品周期规则。

## 7 配置相机和 VPP

### 7.1 相机和算法

1. 进入【视觉】，点击【添加相机】或选择已有相机配置，设置便于识别的相机名称。
2. 在 Camera SN／相机 SN 下拉中扫描并选择真实序列号，检查相机连接及曝光。无相机提示时核对电源、网线及枚举结果。
3. 在所选相机下添加或选择 VPP，核对 VPP 名称和当前型号路径。
4. 通过【编辑 TB】进入 ToolBlock 编辑器，配置实际算法及输入输出。关闭时【是】保留算法草稿，【否】恢复进入前状态，【取消】继续编辑。
5. 返回主界面【保存】，再重新打开相机/VPP 或切换并返回配方，确认保存结果。

新建相机配置不会生成真实相机，也不会自动得到可用算法。当前型号的 VPP 未成功加载、SN 未选或端口缺失时，应先修复原页面。

相机【默认曝光】影响新建 VPP 和标定；已有 VPP 修改自己的【曝光】。检查采集可用【实时显示】，结束后点击【停止实时】；实时、算法运行或编辑未结束时，相关修改和主保存可能被阻止。

### 7.2 流程执行视觉和保存照片

1. 添加【现有功能】节点，在【动作设置】选【视觉】及“相机名／VPP 名”，确认当前配方已正确加载该实例。
2. 方法选【拍照并运行当前 VPP】，按真实 ToolBlock 字段填写或绑定算法输入。节点发布视觉判定、坐标和声明的输出。
3. 需要读输出或保存照片时，另加相应方法节点，并选择同一个 VPP。
4. 参数【来源拍照节点】只列同一 VPP 的匹配执行节点。选择本次拍照来源，框架自动绑定其 RunId，不需手写编号。
5. 存图沿用该 VPP 页面配置，实际执行成功后核对返回路径及文件。

同一 VPP 再次运行后旧结果可能失效；当前没有无限图像历史缓存。不要引用另一 VPP 或上一产品的结果。页面勾选存图不表示所有手动拍照入口都自动存图，流程应明确安排保存方法。

### 7.3 补偿和节点输出

VPP 补偿表维护项目、上下限及补偿值，数值必须有限且下限不大于上限。节点选同一 VPP 的【读取本站补偿表项目】，选择实际项目键。

节点直接输出 Compensation、Min、Max。需要运动补偿时，在实际轴移动节点将【附加偏移】绑定到 Compensation；读取本身不执行运动，也不会自动叠加到坐标。VPP 字段缺失或类型改变时修复节点参数及下游绑定，不以改显示名绕过检查。

### 7.4 标定和删除

标定至少九点。每次【拍照】后【添加标定点】带入像素坐标，初始电机坐标为 0，必须填写实际位置，不能原样批量保留。核对后【应用到本相机】接受算法草稿，最终主保存。

相机、VPP 使用页面【删除当前相机】【删除当前 VPP】及确认提示。流程引用或生产定位绑定会阻止删除；删除移除配置但保留磁盘算法文件。普通流程调用不要求全部 VPP 勾选【生产定位】。

## 8 使用工具箱编排流程

### 8.1 打开和准备模块

1. 进入主界面【流程】，选择现有流程模块及其初始化页或自动页；新通用页可能显示 Initial／Auto。所有继承 Flow_BaseForm 的页面均沿用此模式。
2. 新增业务工位时使用【添加流程模块】，输入唯一名称。
3. 勾选【编辑流程】，工具箱用于添加，画布用于位置、连线和节点配置。
4. 勾选【启用流程】参加机器运行，不参加的模块取消勾选。所有模块统一使用混合节点流程。

旧工程加载后统一迁移，保留节点位置、连接、可精确识别的原生事件和已选入口。未选入口时只自动采用所在页唯一的无入边原节点；多个候选或闭环需手动选入口，失效或多播事件须明确修复。运行时不回退旧生命周期代码。

### 8.2 添加节点和配置输入

左侧【流程工具箱】按实际功能分组，条目来自当前对象及其方法；搜索对象或动作名称后拖到画布，也可双击／按 Enter 添加。另有【条件节点】。普通【添加节点】默认使用现有功能，需明确选对象与方法。

节点顶部仅保留【现有功能】【仅判断条件】。现有功能通过【动作设置】选功能类别、实际对象及对象方法；参数直接填固定值或点【绑定数据】选择机器 Setting、当前 Recipe、节点结果或上下文。轴目标点位只来自本轴绑定表，高级参数按需展开。

所选方法直接声明本步输出，下游可选择，无需编辑源码或定义脚本端口。【仅判断条件】不执行动作，只显示下一步和运行设置。

C# 脚本与代码模块入口及运行支持已移除。旧 Script／Code 节点可以加载，但校验和执行会拒绝。打开时显示提示，不自动选替代方式；需明确选现有功能重新配置或选仅判断条件，并检查旧出口及下游引用。取消不改变原定义，也可解除引用后删除旧节点。

### 8.3 配置 NEXT 和 CASE

1. 在【下一步】为 NEXT 选择【跳转目标】。新节点默认只有 NEXT，【无条件通过】适合顺序执行。
2. 需要判断时选【所有条件满足（AND）】或【任一条件满足（OR）】，选择左值、比较、右值。Boolean 可直接比较“是／true”，数值必须填写有效比较值。
3. 【+ 添加条件】增加同行条件，条件行右键删除。AND 要全部成立，OR 至少一条成立。
4. 【添加 CASE】依次增加 CASE1、CASE2、CASE3，各自配置条件和目标。右键 CASE 标题可移除该 CASE，NEXT 保留。
5. 【结束】表示本模块本次执行结束。画布连接用于呈现和编辑出口关系，保存前仍应在节点【下一步】逐一核对出口及条件。

动作执行一次后，按 NEXT、CASE1、CASE2、CASE3 顺序选择第一个满足的出口；均不满足则继续检查条件，不重复发送动作。无条件出口只能作为最后一个已配置出口；不要让无条件 NEXT 抢先遮住后面的 CASE。

动作完成后由这里的条件选择出口；条件节点使用同样规则。条件节点没有自己的采样结果，应选择上游节点结果或其他有效来源。

### 8.4 设置超时和报警

在【超时与调试】填写超时毫秒、异常报警号和可选执行前断点。超时从动作开始计时，包含动作执行及出口等待。

超时到达即请求报警，不需要再写一个“超时成立”条件；异常和超时停止当前模块，不会自动跳到某个 CASE。报警号留空使用框架兜底报警，现场流程应选择有明确含义及正确停机规则的报警号。

1 秒等于 1000 毫秒。先依据设备实际最大动作时间及工艺等待填写，避免用巨大超时掩盖永久不成立的条件。

### 8.5 选择入口 保存和删除

为模块设置【初始化入口】和【自动入口】。没有初始化动作时，可把初始化入口设为【结束】；正式启动仍先使用主界面【初始化】。

点击【校验】，根据提示修复未配置节点、失效对象、缺失输入、出口和类型。节点【确定】后主【保存】选择【是】，成功后退出全部模块的【编辑流程】。

功能和条件节点右键可【属性编辑】；代码节点双击不编辑，右键不显示属性入口。所有节点仍可【设置／取消断点】、【删除节点】。有其他节点引用它的输出时，先解除引用再删。删除会清理有关入口和连线，必须重新校验并主保存。页签右键【删除流程模块】只允许空模块；会隐藏并停用模块，不删除项目中的 C# 类型。

删除最后一个节点后，可把空模块保留为待编排页面并主保存；空模块不执行动作。有节点的初始化或自动页必须明确选定入口。不参加运行的模块可取消【启用流程】。

【重新加载】会放弃未保存流程修改，先阅读确认；它只处理流程，不是全部轴、常量或 VPP 草稿的统一恢复。放弃整套配置使用主【保存 → 否】。

## 9 节点方式和生成源码

### 9.1 两种节点如何选择

【现有功能】用于调用当前实际对象的方法，包括轴、IO、VPP、Device、常量、计算及本地保存。【仅判断条件】只判断数据并选择去向，不重新采样 IO，也不执行上游动作。

C# 脚本与代码模块已移除。旧 Script／Code 节点须明确改为现有功能／条件重新配置，或解除引用后删除；不会自动改写其业务逻辑。取消编辑保留旧定义。

### 9.2 确认动作与数据

1. 双击节点，在【现有功能 → 动作设置】核对实际对象和方法，不使用未创建的默认名称。
2. 为每个业务参数填写固定值或【绑定数据】；核对类型、单位和当前配方。
3. 读 VPP 输出或存图时，选择同一 VPP 的来源拍照节点；移动轴时只选本轴绑定表的点。
4. 在【下一步】选本步结果及合适的条件，按需添加 CASE。
5. 在【超时与调试】设超时、报警、断点，节点确定，流程校验并主保存。

### 9.3 保存位置和生成源码

流程随机器 Setting 目录的 FlowPrograms.xml 保存，格式 V3，可读旧 V1／V2；兼容读取不表示允许执行旧 Script／Code 节点。

主 Save 同时生成所属 Form 的 .Flow.g.cs 和 FlowSources.manifest.xml。开发目录通常为 AlphaRap/GeneratedFlows，发布环境通常为机器 Setting/GeneratedFlows，用【查看生成源码】及提示核对。

生成文件是同一运行器使用的流程定义，重新加载仍以 XML 为准。删除节点后再次主保存同步移除对应生成定义；末节点删除后保留空定义。手写 .cs／.Designer.cs／.Custom.cs 不覆盖。不要修改受管理文件，手改会触发冲突保护。

保存配置、生成源码和编译部署是不同动作。参数和绑定主保存后供后续运行使用；修改宿主或 SDK 方法实现仍需重新编译部署，主 Save 不会重建当前 EXE 或热替换 DLL。

## 10 校验与节点调试

1. 停止设备，确认原页面资源、配方、字段和流程已主保存。
2. 在节点右键设置断点，或在节点【超时与调试】勾选【执行前断点】，再次主保存。
3. 退出全部模块编辑，在流程页开启【节点调试】。
4. 使用主界面原有【初始化／启动】，调试执行先停在入口节点。
5. 选中当前模块，使用【单步执行节点】执行一个完整节点，观察本次输入、输出、状态及出口。
6. 点击【继续】运行到下一断点；需要结束时使用原【停止】。

单步可能执行运动、输出和拍照，一个节点内部可以包含多个设备动作。节点前等待不计入该节点超时。正常生产关闭【节点调试】，避免入口等待被误认为卡死。

这是节点级调试。当前没有脚本编译或脚本行级调试入口；宿主方法源码调试由开发人员使用匹配的 EXE／DLL／PDB 和 Visual Studio 完成。

模拟使用当前工作目录 MachineSetup.ini 的 [LogicSetup] Simulation。离线测试应复制完整程序和配置，设 Simulation=True 后重启；当前不应寻找流程页的独立模拟开关。模拟不保证所有客户自定义业务代码都不会自行通信，练习只使用明确无硬件调用的计算方法。

## 11 本地生产记录 查询和 MES

### 11.1 定义生产字段

进入【数据 → 生产表字段】，在表格新增业务字段，选择 Text、Number 或 Boolean。建议字段键表达清楚，例如 Barcode、GlueWeight、AoiHeight，项目内保持稳定。

字段名唯一，不能使用框架保留的 Time、RecordId、CycleId、ModelName、Simulated。实际行右键删除字段。【确定】产生草稿，主【保存】后写入 DataForm.Production.xml。

修改表结构后必须检查全部相关保存节点；保存动作需要提供当前定义的每个业务字段。已有字段有用途时保留，不为演示随意删除。

### 11.2 用保存节点写入本地记录

1. 先确认生产字段已主保存。添加【现有功能】节点，命名为保存记录。
2. 在【动作设置】选【本地数据保存】、DataForm 的 Production 对象及【保存 DataForm 生产记录】。
3. 参数按当前生产表字段显示。对 Barcode、Weight、Accepted 等实际字段逐项填写固定值或【绑定数据 → 节点结果】；实际表有更多字段时也要完整配置，不为演示删除已有业务字段。
4. 节点自动提供文本输出 RecordId 和 Path，下游可直接选择，无需定义端口或读取字典。
5. 设置下一步及超时报警，节点确定、校验、主保存，再运行并核对返回路径和记录。

框架自动附加时间、记录身份、周期、型号及模拟标识。默认路径为程序工作目录下 ModuleData/ProductionData/yyyy/MM/yyyy-MM-dd.csv；实际根目录可能配置过，以返回 Path 及查询提示为准。

主【保存】不执行生产保存动作。模拟也实际写 CSV，带 Simulated=True；不会自动给首页实时表加一行，应在查询窗口核对。已有日文件去重不等于跨重启、跨日期的产品追溯保证。

### 11.3 查询和导出

进入【主页 → 生产信息区域 → 查询】，在【生产数据查询】选起止日期，或使用【今天】【近 7 天】【近 30 天】，填写可选【内容关键字】，点击【查询】。点击【导出】选择 CSV 位置，导出当前筛选的全部记录；明细只显示前 5000 条，导出不限于可见行。查询窗口只读。

查询无结果时核对时间范围、实际保存路径和保存节点是否执行成功。页面缓存或模拟的结果不能代替文件核对。

运行日志、错误日志、操作记录和 MES 日志沿用各自已有入口及路径。排障应保留时间、型号、模块/节点、报警号和相关日志，不只记录“无法运行”。

### 11.4 MES 使用边界

【MES／数据上传】页面是项目具体客户接口的参数与调用配置。按现场接口协议核对地址、站点、工序、设备号及条码字段，在已有流程或模块中明确调用，分别核对接口返回和本地日志。现有客户 MES 页面并非全部已接入通用工具箱；新项目需要开发人员先做一次协议能力适配。

本地保存成功不代表 MES 成功，通信返回也不必然代表业务接收成功。当前没有统一持久待传队列和自动多产品台账。遇到超时，应先核对 MES 是否已接收，再按现场补传规则处理；不要反复重跑点胶等加工步骤来补上传。

## 12 数据在节点间传递

上游动作发布方法声明的输出；下游参数旁【绑定数据 → 节点结果】选择来源模块、节点和字段。无需编辑取值代码。来源必须已完成，并属于当前运行关联和同一产品周期；修改显示名称不改变稳定引用。

条件节点可直接读取有效上游结果，但没有自己的采样动作或输出。它等待已有数据来源，不重复触发前一个节点。全部消费者读取及保存完成前不能释放相关结果；缺失、旧批次、取消或其他产品结果会报错，不以 0 代替。

连续生产可明确安排【开始产品周期】并以条码等作为产品标识，本件相关消费者及保存完成后【结束产品周期并释放结果】。这是当前运行中的结果关联和有效期机制，不能用一个固定批次值代表同时在制的多件产品。

转盘产品随行、治具穴位、多产品并行、迟到结果归属及断电恢复仍需额外产品模型；不能仅靠节点连线自动完成。MES 的提交回执及补传状态也要单独设计。

## 13 离线练习 计算与重量分支

### 13.1 准备练习环境

使用完整程序和配置的离线副本，不覆盖生产目录。在副本 MachineSetup.ini 的 [LogicSetup] 设 Simulation=True 后启动，以有流程编辑权限的账号登录。

本例只有一个纯计算动作，不调用轴、IO、相机或 DataForm，也不生成记录。其他模块设为【停用此流程模块】，不混入原回调。记录副本路径及当前型号。

### 13.2 配置计算节点

1. 在【流程】添加重量练习模块，选择 Auto／自动流程页，勾选【启用流程】并启用编辑。
2. 从工具箱拖入【流程与数据 · 数值计算】，命名为重量判定；或添加普通节点，选【现有功能 → 流程与数据 → 数值计算】。
3. 参数左侧数值 A 填 2.5，运算符选 +，右侧数值 B 填 0。本例单位为 g，输出【计算结果】为 2.5；这里只用加零来产生可观察的重量结果，无需写代码。
4. 【下一步】NEXT 选【所有条件满足（AND）】，添加两行：当前动作结果 Value 大于等于 2，且 Value 小于等于 3；跳转目标【结束】。
5. 【添加 CASE】建立 CASE1，将其设【无条件通过】并跳【结束】，作为最后的超限出口。NEXT 必须保持条件模式。
6. 超时可保留默认 10000ms，节点确定。初始化入口【结束】，自动入口重量判定；校验并主保存，退出全部编辑。

### 13.3 运行和核对

1. 开启【节点调试】，主初始化完成后主启动，先停重量判定前。
2. 单步核对输入 A=2.5、B=0、运算符 +，输出 Value=2.5，出口 NEXT；本例此时结束，不等待下一节点。
3. 停止并确认空闲，重新编辑把 A 改 3.5，节点确定、主保存、退出编辑，再初始化和启动。
4. 单步后 Value=3.5，NEXT 范围不成立，走 CASE1。关闭副本重启，核对参数、两行条件和出口仍在。
5. 学会分支后再按第 11.2 节增加保存节点，把其重量字段绑定本节点 Value，按实际生产字段配置完整，再将出口指向保存节点。

两条出口都结束是为了先核对条件优先级，实际生产可分别接合格和不合格处理。此练习不使用已移除的重量代码模块或 C# 脚本。

## 14 常见问题处理

| 现象 | 先检查什么 | 处理方式 |
| --- | --- | --- |
| 找不到工具箱或不能添加 | 当前模块、编辑权限、编辑流程状态 | 进入流程页，选模块，勾选编辑流程；确认角色和 Rapid 权限 |
| 点击启动没有执行 | 是否初始化、入口、模块模式、调试等待 | 全部退出编辑，核对自动入口；检查是否停在入口断点 |
| 提示入口未选择 | 对应页面是否存在多个起点或闭环 | 明确选择初始化或自动入口，校验后主保存 |
| 找不到旧脚本或代码模块 | 当前版本的两种节点 | 两入口已移除，人工改为现有功能／条件或解除引用后删除 |
| 旧脚本／代码节点不能运行 | 是否明确选择新执行方式 | 备份并人工配置现有功能／条件；取消保留旧定义 |
| 节点配置重启没了 | 是否只点节点确定 | 节点确定后还需主保存选择是 |
| 轴只有一个点 | 当前轴自身绑定表及有效行 | 原轴表新增有效点，核对限位，再重新打开节点 |
| 点位改后移动目标不对 | 当前配方本轴表、Index、Offset | 核对移动节点参数及配方绑定后主保存，不使用其他轴点位 |
| 看不到实际相机/VPP | 视觉页对象和当前型号加载 | 在原页面建立并加载，修复SN/算法，再重新打开节点 |
| 读取视觉或存图失败 | 对象一致、来源拍照节点、结果有效性 | 选择同VPP的本次拍照来源，不引用已失效旧结果 |
| 找不到常量或不能删除 | Setting/Recipe作用域、键、类型、引用 | 选对表和配方，先解除引用；不要用行号当键 |
| 条件一直不跳转 | 本次结果、比较值、出口顺序 | 调试查看实际值；检查NEXT是否遮住CASE及单位/类型 |
| 停止后仍忙 | 动作/驱动是否实际返回 | 等待实际收尾，保留节点和驱动信息，禁止抢占同一资源 |
| 主保存失败 | 当前提示、文件可写、对象/字段/出口 | 保留草稿，修正后重试；不要把失败当成功 |
| 生成源码冲突 | 是否手改过受管理文件 | 备份修改，交开发人员合并到业务模块，解除冲突后再保存 |
| 查不到生产记录 | 保存节点、时间、实际CSV路径 | 先看节点成功及返回路径，再查文件和查询时间 |
| 本地有记录MES没有 | 接口调用、业务应答及MES日志 | 单独核对上传，按客户协议补传；不要重复加工 |

## 15 备份 发布与扩展

### 15.1 备份和恢复

设备停止、配置保存并退出后，备份完整程序与配置目录。至少包含 EXE 和配套 DLL、MachineSetup.ini、机器 Setting 目录、配方目录、VisionData、语言和报警目录、账户权限数据及生产记录。现场使用自定义路径时一并备份对应目录。

FlowPrograms.xml、HardwareResources.xml 和 DataForm.Production.xml 通常在机器 Setting 目录。点位和 Recipe 常量在当前配方 XML；当前配方 VPP 在相应视觉目录。文件旁的 .bak 是前版辅助恢复，不能替代整套一致备份。

恢复时使用配套程序、DLL、配置和算法，先在离线副本校验。文件损坏时先保留原件和错误信息，再由维护人员恢复匹配备份。不能只回退 EXE 而继续使用不兼容新版流程格式。

### 15.2 新功能由谁完成

应用工程师：建立现场实例、维护参数点位、拖入实际对象动作或条件节点、配置参数与数据绑定、设置出口报警、调试及保存。已有能力不需要编写节点 C#。

软件开发人员：新增驱动协议，为已有实际对象通过 IFlowObject 提供清晰的方法契约和结果字段；外部应用的已有实例可通过 FlowExternalResources 登记供节点绑定。当前没有代码模块自动扫描和拖入入口，不再按 FlowCodeNode 方式扩展工具箱。重复业务可在手写业务文件封装，再通过实际对象声明必要方法；不要把手写代码放进受管理生成文件。

修改业务代码和核心 DLL 后重新编译发布，核对配套版本，再执行离线及现场验收。当前 DLL 不支持主 Save 热替换业务实现。

## 16 辅助页面和维护

### 16.1 主页报警与日志

在主页查看当前报警及记录时间，使用已有筛选和历史查询入口核对发生顺序。排除原因后点击【清除报警】，仍重复出现时检查对应节点、IO 或驱动，不只重复复位。

【数据】中的运行、错误、用户操作及 MES 日志分别用于核对调用和错误；【日志】页面维护原有路径设置，修改后按主保存处理。通信日志有请求内容，不代表服务端业务已接受。

### 16.2 报警表维护

维护人员进入【系统 → 报警设定】，通过页面现有添加、修改、移除、保存操作维护报警 ID、Type、DoStop 和三语内容。ID 必须唯一；Type 使用 E、W 或 I，DoStop 使用 True 或 False。不要随意重编号已被流程使用的报警。

此页面目前使用自身【保存／Save】，不属于主保存事务。运行停机规则以中文主表为准，语言切换只改变显示内容。修改后重新核对现场需要的加载或重启步骤，再验证实际触发，不能仅检查翻译。

### 16.3 信号灯和寿命

【信号】当前页面用于配置不同机台状态下的红、黄、绿灯和蜂鸣器规则。先选择机台状态，再分别选择运行／维护模式中的关、开或闪烁。当前实现点击后直接写信号规则数据库，主保存选择否不能撤销，维护前先备份。

实际输入输出点状态在【手动 → IO 资源】查看。不要将信号灯规则页理解为全部 IO 的实时列表。

【寿命】使用项目已有寿命组件。按现场已定义的部件项目核对累计使用和维护记录；更换后的复位或调整按该组件及设备维护规范执行，不能把寿命页面操作当作生产记录清除。

## 附录 操作确认单

### 配置交付前

- 已核对现场轴、IO、Device 和 VPP，显示名称与实际对象一致。
- 当前型号、点位、常量类型和视觉端口正确。
- 所有出口、入口、超时和报警经过校验。
- 本次配置运行没有混用旧回调；无关模块已明确停用。
- 主保存选择是并成功，重启后配置和生成定义一致。
- 完成正常、超限、超时、停止及必要的恢复测试。
- 本地记录内容和实际路径可核对，MES单独核对业务回执。

### 每班生产前

- 当前型号和账号正确，必要报警已排除。
- 配置已保存，全部流程退出编辑，正常生产关闭节点调试。
- 初始化完成，现场运动条件确认，首件记录与实物一致。

### 班末退出前

- 停止实际完成，最后一件产品状态及数据已核对。
- 未保存配置已明确提交或放弃。
- 未确认的上传和异常产品已按现场规则交接，必要日志和备份已保留。
