# 原生代码 FlowChat

复杂逻辑可以写在现有 `Flow_BaseForm` 派生窗体中，使用原来的无参 `NPSDK.Flow_Chart.ResultType` 方法。方法自动出现在当前页面工具箱【代码流程】中，与轴、IO、视觉、常量表、数据保存节点共用同一流程运行器。

不需要新建代码模块工程、实现新的节点基类、编写动作目录或注册工具。代码仍在 Visual Studio 编译后部署，运行时编辑器不编译脚本。

## 写法与入口

在已有工位 Form 的业务 `.cs`，或同一个 partial 类的独立 `.cs` 文件中添加方法：

```csharp
private bool productReady;
private bool productPassed;

/// <summary>等待本产品检测完成，然后按实际结果分流。</summary>
private NPSDK.Flow_Chart.ResultType CheckProduct_FlowChartRun()
{
    if (!productReady)
        return NPSDK.Flow_Chart.ResultType.IDLE;

    return productPassed
        ? NPSDK.Flow_Chart.ResultType.NEXT
        : NPSDK.Flow_Chart.ResultType.CASE1;
}
```

两个示例状态需由项目实际业务更新，或替换为已有对象的读数／状态。

重新编译和启动后：

1. 打开【流程】，选择实现该方法的工位页面，启用编辑。
2. 在工具箱【代码流程】找到 `CheckProduct`，拖到画布；也可双击或按 Enter。
3. 代码节点为只读绑定，双击不打开编辑窗口，右键不提供【属性编辑】。函数实现由开发者在所属 Form 的源码中维护；已有布局和连接加载时保留。
4. 运行界面仍可拖动、右键设置执行前断点或删除节点，变更使用主界面【保存】持久化。从工具箱新增的代码节点如尚未配置连接，目前没有专用界面连线入口，不能按普通功能节点的【下一步】配置流程。

`private`、`protected`、`public` 方法均支持，包括业务父类的方法。契约是“实例、无参、返回 `Flow_Chart.ResultType`”，不强制方法后缀。默认显示省略 `_FlowChartRun`，保存身份仍使用完整方法名、声明类型和程序集简单名。

只有已创建的当前工位实例会提供代码工具。切换工位后工具箱跟随页面，不会新建另一个 Form 代替实际对象。跨工位复用可通过共同业务父类，或把通用算法放在原设备／轴／IO对象的公开业务方法中。

画布每个节点上方分别显示【功能】【代码】【条件】标记，和节点名称独立；运行状态刷新不会擦掉类型。鼠标停留可以查看绑定对象或原生函数名。功能和条件节点可双击或右键【属性编辑】配置；代码节点不开放界面属性编辑，其已有出口、超时和报警定义继续保留。同一个节点不会同时执行对象动作和原事件。

## 返回值与运行

- `NEXT`、`CASE1`、`CASE2`、`CASE3`：直接选择对应已配置出口。
- `IDLE`：留在当前节点。运行器检查暂停、停止和原有超时，短暂异步等待后再次调用；超时从首次进入开始，不因 IDLE 重置。
- `End`：结束当前工位的这次流程。

返回未声明的 CASE 会报错；已有定义中显式配置为“结束”的出口会结束本次流程。代码节点不在运行界面添加或修改出口。函数异常或超时使用原报警入口，不自动跳 CASE。普通拖拽动作继续使用原 AND／OR 条件。

函数应短时返回，等待设备时返回 IDLE，避免无限循环或长期 Sleep。停止和超时不能强杀同步 C#：在途调用必须实际返回后才能释放占用，不发布迟到结果。代码在后台线程运行，通过原对象的线程安全业务接口访问数据，界面更新使用 Invoke。

每次调用持有所属 Form 及该 Form 目录内实际资源的租约。任意 C# 可以访问别的页面、静态字段或外部硬件，框架无法从签名推断这些依赖；跨页面硬件操作仍需遵守既有互锁／对象访问规则。IDLE 间隙不持续锁住所有硬件。复杂运动优先使用现有轴节点，由适配器负责完成等待、限位和占用；不要在事件里重新启动旧流程控制器或另建生产循环。

## 数据、保存与调试

代码访问当前 Form 已持有的实际对象。普通节点的输入输出、Setting／Recipe 和生产数据服务保持原规则。

无参原生方法仅产生 `Result` 枚举观察字段，不自动把局部变量、全局变量或 DTO 变成输出端口。产品条码、重量、高度等仍写入已有产品数据对象，或把普通节点输出绑定到 DataForm。混合流程会保留上游节点的数据，在原生分支之后继续保存。

主 Save 保存节点位置、所属页面、方法身份、NEXT／CASE连接、超时、报警和断点，不保存委托、窗体实例或重复源码。下次加载解析到新实际实例。方法删除、改名或移动声明类型后会提示绑定失效，需明确重选。

代码方法只定义行为，不定义坐标。代码节点与功能节点共用原页面画布，启用编辑后均可拖动；已有节点保留原位置，不自动重排。画布滚动范围按全部节点恢复，重启后仍可滚动到下方或右侧的节点。滚动视口不会改变主 Save 保存的节点位置。

删除画布节点只删除该绑定，不删除手写函数；函数可以在当前页面被多个节点复用。已启用的节点定义源码生成仍随主 Save 更新或删除自动生成部分。

流程页断点先停在节点执行前；单步执行该节点全部 IDLE 检查，到下个节点再停。C# 行级断点仍使用 Visual Studio 调试器。

旧节点唯一绑定当前 Form 的事件时会自动导入并保留连接。绑定多个事件时须由开发者在所属 Form 源码中明确绑定一个函数，或在一个函数里顺序调用所需逻辑，不静默取最后一个处理器。

## 源码节点删除与连接同步

流程定义记录节点来源及原生控件四个出口的源码基准。加载 Form 时先读取编译生成的节点和连接，再恢复保存布局；重新加载始终使用这份源码快照，避免把运行界面已经覆盖的连接误认为源码。

- 源码删掉的节点不再无条件按旧 XML 重建。其前驱仍指向该节点时，按当前源码的 NEXT／CASE 连接修复；没有剩余连接、入口或数据引用后清理旧定义。
- 源码连接改变时，仍沿用旧源码目标的保存连接随之更新。已明确接到拖拽节点的混合流程连接保留，源码没有变化时也不覆盖保存的连接。
- 拖拽的功能、条件和代码节点保留自己的身份、绑定、布局及参数。旧版没有来源字段时，先按实际 Form 控件及框架生成的动态节点名称兼容识别。
- 删除的源码节点仍被其他节点、入口或输出数据引用时，保留带提示的失效占位。相关执行路径校验会明确报出控件名称；先修改引用或入口，再删除失效节点。

同步仅修改内存草稿，配置继续使用主界面【保存】写入。Save 失败时文件和已发布版本沿用原事务规则，重新加载旧文件会再次按当前源码同步。不要通过清空整个流程文件处理单个节点删除问题。

例如源码把 `UPConveyInit_Flow2_0 → UPConveyInit_Flow2_01 → UPConveyInit_Flow2_1` 改为直接连接 `UPConveyInit_Flow2_1` 后，加载旧文件会清理没有其他引用的 `UPConveyInit_Flow2_01` 并同步 NEXT。其他工位和页面配置保持原值。更新程序后重新加载，确认初始化／自动入口，再使用主界面【保存】。

模块统一使用混合节点运行器，界面只保留【启用流程】。加载旧工程保留已选入口；没有入口时，分别从初始化页、自动页唯一的无入边原节点推断。有多个候选或闭环时需手动选入口；不再回退调用旧的 Initial／StartRun 生命周期方法。原方法中的准备逻辑应放到明确的代码节点中，取消启用的模块仍由统一控制器接管。

## 可选名称、隐藏与模拟

默认方法名属于业务名称，不自动翻译。可选 `FlowTool` 标记提供三语标题，例如：

```csharp
[AlphaRap.FlowProgramming.FlowTool("产品判定", "Check product", "Comprobar producto")]
private NPSDK.Flow_Chart.ResultType CheckProduct_FlowChartRun()
{
    return NPSDK.Flow_Chart.ResultType.NEXT;
}
```

采用同签名的辅助方法可用 `[FlowToolIgnore]` 隐藏。实际运行不要求任何标记。

未知代码默认按可能访问硬件处理，模拟运行不会直接执行。纯计算函数可选择 `UsesHardware = false`，或使用 `SimulationMethod = "PreviewMethod"` 指定当前 Form 内同签名模拟函数。模拟函数可标 `[FlowToolIgnore]`，无需另建工具。
