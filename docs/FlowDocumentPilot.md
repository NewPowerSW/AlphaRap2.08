# Gantry 心跳页：统一流程文档试用版

本版先改造 Gantry → 自动流程 → 心跳。其他页面继续采用现有兼容方式，轴、IO、视觉及配方管理保持原入口。

## 本版的唯一保存内容

心跳页的节点集合、位置、尺寸、连接和删除状态由 FlowPrograms.xml 保存，页面和节点使用稳定 ID。源码里的四个原生节点只提供首次迁移模板，之后不能把已删节点重新补回来；节点全部删除后，空页面也会保存。

原来的 C# FlowChartRun 方法保留在 Gantry.cs 中，仍返回 NEXT、CASE1—CASE3 等 ResultType。运行时将方法绑定到文档节点，并复用已有运行器。源码函数、文档节点、屏幕上的控件分别承担业务逻辑、流程定义和显示职责。

配置统一使用主界面【保存】。沿用 ProductManagerForm 的配方管理及既有配置保存事务，不增加独立保存按钮。新增命令及提示支持中文、English、Español。

## 试用步骤

1. 使用更新后的 Debug 程序，进入【流程】→ Gantry → 自动流程 → 心跳。
2. 勾选【编辑流程】，从工具箱拖入已有功能、原生代码方法或条件节点。代码节点的函数正文仍在 VS 编辑，双击及右键属性不会打开功能配置页。
3. 拖动节点调整布局。代码节点右键【连接设置】可选择 NEXT／CASE1／CASE2／CASE3 的目标，【结束】表示该出口没有后继节点。执行函数返回哪个出口，运行器就采用对应连接。
4. 功能节点仍通过原属性窗口配置动作、数据绑定和条件；它们与代码节点在同一个图里执行。
5. 节点删除统一使用右键【删除】，随后使用主界面【保存】。重新加载或关闭重开后检查位置、连线及删除结果。
6. VS 重开 Gantry 设计器，心跳页的 FlowDocumentCanvas 从同一个已保存文件读取预览；可选中画布使用设计器动词【刷新流程预览】。首次迁移必须先在应用中保存一次，尚未保存时显示提示。

## VS 与应用如何分工

VS 编辑 Form 外壳、业务方法及资源实现；应用编辑试点页面内的流程图。VS 内的节点是只读预览，不再作为独立控件写入 Gantry.Designer.cs。当前版没有实现从 VS 原生设计器直接增删、拖动该预览图中的节点，也没有改写用户的业务方法。

新增 Flow_BaseForm 页面可放置 FlowDocumentCanvas，设置唯一 DocumentKey、所属 ModuleId，以及一次迁移使用的 LegacyParentPath。已有原生控件可通过 RegisterLegacyNodes 登记，保留原 C# 字段引用所需的实例。DocumentKey 是页面身份，请保持稳定；容器 Name 改变不会使节点丢失。新建后仍需宿主正常注册到 FlowPrograms。

默认预览文件为源码项目目录下 bin/x64/Debug/ModuleData/SettingData/FlowPrograms.xml；也可通过画布 PreviewFile 指定文件。移动整个项目后应重新编译，或明确设置预览路径。VS 预览不执行业务事件、不解析硬件资源，也不写配置文件。

## 升级与兼容边界

首次加载采用有效旧配置，并尊重已有删除记录；没有历史配置时才导入源码模板。首次主保存后，有文档页面的工程升级为 V5；没有文档页面仍保存为 V4。升级必须同步替换 EXE 与 NPSDK.dll，旧版 SDK 无法读取 V5，回退时需同时恢复旧配置备份。

不要在 VS 删除承载已保存文档的画布后期待流程自动迁移到其他页。本版会报告宿主缺失，避免把生产节点放进错误页面。完整页面增删、页面迁移及全框架迁移尚未作为本次试点开放。

## 验证范围

离线验证包括：新增/删除/移动/连接后往返，全部节点删除后不复活，容器改名与稳定页面身份，旧 Gantry 配置迁移，原生代码与功能节点混合运行，同一文件的预览布局，主保存事务及源码生成回滚。现场设备未运行，VS 专有 C# 设计器的交互加载仍需在实际 VS 环境确认；自动设计器探针不代替该项。
