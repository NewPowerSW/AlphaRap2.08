# FlowChat 功能工具箱

入口：主界面 **流程** 页面左侧的 **功能工具箱**。选择工位，启用 **编辑模式** 后，可拖入功能；双击工具箱条目或按 Enter 也可以添加。所有继承 `Flow_BaseForm` 的页面共用此入口。

## 应用工程师操作

1. 在原轴、IO、视觉和设备页面创建实际对象。点位仍在轴绑定表中维护，配方仍由 ProductManagerForm 切换。
2. 在流程页选择工位、初始化或自动流程页，启用编辑。工具箱按功能分组，可以搜索对象名称、动作名称或模块 ID。
3. 拖入“X轴 · 移动到绑定表的点位”等现有动作，双击配置参数和下一步。普通动作继续支持 NEXT / CASE 的独立 AND、OR 条件。
4. 拖入 **代码模块** 组的模块，双击选择它需要的实际对象、VPP 字段和输入值。模块输入可绑定固定值、Setting / Recipe 表值、上下文或其他节点输出。
5. 在 **下一步** 页面选择模块各出口的去向。代码模块自己决定 NEXT / CASE，界面只设置去向；每个声明的出口都要选择目标，或明确选择“结束”。空白表示尚未配置。
6. 点节点窗口“确定”只修改草稿。使用主界面 **Save** 统一保存，再沿用原初始化和启动按钮运行。需要采用新流程的工位，其执行模式应为“流程工程”，并配置正确入口。

右键节点可编辑属性、切换执行前断点或删除。删除有下游数据引用的节点会被阻止，应先解除引用；有 FlowChat 节点的工位页面也不能直接删除。

原有配置节点、C# 脚本节点、代码模块可以混合使用。已有工位回调不自动转换成代码模块；迁移旧流程时应逐个配置节点，未迁移工位可保留原回调模式。

## 内置的两个代码模块

**重量判定**：输入实测重量、上下限；合格返回 NEXT，不合格返回 CASE1。输出重量和合格状态，可供后续 DataForm 保存节点绑定。该模块不操作硬件，适合先验证拖入、数据传递和出口。

**到位后视觉测高**：依次等待产品到位输入、移动到指定点位、执行检测 VPP、判断高度。绑定定位轴、产品到位输入、检测 VPP，并将“高度输出”映射到该 VPP 的数值输出。检测点位的下拉项只来自所选轴的绑定表；合格走 NEXT，不合格走 CASE1。

这两个模块是可复用功能条目，不会自动创建相机、轴、IO 或生产流程。必须选择现场已有对象。示例的高度上下限需要按工艺填写，轴单位采用原轴配置。

模块输出在下一节点选择“其他节点输出”时可见；本地记录继续使用 **DataForm** 的生产字段和保存动作。工具箱不自动新增 MES 或转盘产品跟随服务。

## 保存、生成代码和重新加载

主 Save 从同一流程快照保存 `FlowPrograms.xml`，并生成每个所属 Form 的 `.Flow.g.cs` 和 `FlowSources.manifest.xml`。文件名含稳定模块摘要，改节点标题不改变归属。

- 本工程的开发 EXE 位于工程 `bin` 下时，输出到 `AlphaRap/GeneratedFlows`，已在 csproj 中纳入编译。
- 发布 EXE 找不到对应开发工程时，默认输出到机器 Setting 目录下的 `GeneratedFlows`。流程页“查看生成源码”打开此目录；路径和当前模式显示在该按钮的提示中。
- 存在实际源码 partial Form 时，生成相同命名空间和类的 partial 文件；运行时新增的通用工位没有自己的源码类，生成关联的独立定义类，不修改 NPSDK 的基类。

生成代码是平铺的流程定义：每个节点一个工厂方法，保存动作、输入引用、绑定、出口和布局；由现有运行器调度。它不把硬件对象实例写进源码，不增加第二套调度器。程序重新加载仍以保存的 XML 为准。

删除节点后再次主 Save，会移除它的生成方法及连接；最后一个节点删除后保留空定义文件，手写 `.cs`、`.Designer.cs` 和 `.Custom.cs` 不受影响。生成文件有所有权及内容校验，手工修改会阻止主保存，避免覆盖；手写业务放到独立模块或 Custom 文件中。

**保存配置、生成源码、编译 EXE 是三个不同动作。** 已部署模块的参数、绑定、布局通过主 Save 后可运行；修改模块 C# 实现或使用导出的源码需要重新编译并部署，主 Save 不会在运行中重建 EXE 或热替换 DLL。

外部宿主可以在初始化时指定 `FlowSourceGenerator.SourceProjectPath`；空串强制导出，null 使用安全的自动探测。导出模式还可指定 `OutputDirectory`。这些路径作为机器设置由主 Save 保存；外部工程需要自行将 GeneratedFlows 加入编译。

## 开发一个新模块

参考源码：

- [WeightCheck.cs](../AlphaRap/FlowProgramming/Modules/WeightCheck.cs)：直接重写 `Execute`，使用类型化输入输出及原 FlowChat 返回值。
- [InspectAtPoint.cs](../AlphaRap/FlowProgramming/Modules/InspectAtPoint.cs)：重写 `ExecuteAsync`，绑定实际轴、输入和 VPP。
- [NPSDK 代码节点契约](https://github.com/JeffreyWub/NPSDK/blob/c655605da5b8fbcee5a20a71903d07fbfaf147ea/docs/FlowCodeNodes.md)。

模块需为 public、非抽象类，继承 `FlowCodeNode<TInputs,TOutputs>`，提供无参构造器，并以 `FlowCodeModule` 声明稳定 ID、分组、三语名称、版本和出口。输入输出 DTO 支持数值、布尔、文本和枚举；`FlowCodeField` 提供三语标题、初值和单位。

`FlowCodeResource` 声明资源角色，应用工程师在节点窗口绑定真实实例；`FlowCodeResourceField` 把 VPP 端口映射成稳定业务字段。Int32 输入的 `ResourceSlot` 指向轴角色，编辑器据此提供该轴点位列表。

本工程及入口程序集的模块自动进入工具箱。外部程序集在部署后由宿主调用 `FlowToolboxCatalog.RegisterAssembly(assembly)` 明确登记；不扫描任意目录或构造业务节点。缺依赖、无效元数据、重复身份会提供目录诊断，受影响模块不可执行。

框架页面已管理的资源自动进入目录。外部应用拥有的实例可调用 `FlowExternalResources.Register(id,name,kind,instance,points)` 登记，重建后 `Replace`，不再使用时 `Unregister`；框架不会构造、连接或释放替身对象。登记在初始化或空闲的主界面线程完成，运行或占用时禁止替换。资源被节点引用时不能注销、删除。

## 运行和调试约定

模块可以返回 IDLE、NEXT、CASE1～CASE3 或 End。IDLE 每 25ms 再检查一次；一次发送动作放到 `OnEnterAsync`，不要在重复检查中发送点胶、运动或扫码指令。End 发布本节点输出后结束当前工位流程。

通过 `context.Axis/Input/Output/Vision` 访问实际对象；设备、气缸、数据对象可经已声明角色的 `context.CallAsync` 调用其原方法契约。每次实际调用使用同一资源锁；代码模块外层不重复锁定其内部资源。

停止和超时发出取消信号，等待实际调用结束才释放资源；迟到输出不发布。`OnCancelAsync` 仅用于本地收尾，此时资源调用入口已经关闭。模块不能自行创建脱离管理的后台硬件任务。

暂停沿用节点边界语义：已开始动作继续，下一节点等待恢复；动作超时继续计时。调试模式支持节点执行前断点、单步、继续及输入输出查看。源码行断点需要匹配 DLL/PDB 和 Visual Studio，未实现内置行级调试器。

轴表的点位值、注释或行序改变后，代码模块需打开节点确认当前配方绑定，再主 Save；各配方确认分别保存。VPP 端口在保存、启动时按当前配方检查，缺失或类型改变不会自动改选其他端口。

流程保存格式为 V3，可读旧 V1/V2。回退旧程序时同时恢复匹配程序、核心 DLL 和配置备份。
