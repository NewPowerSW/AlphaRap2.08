# FlowChat 流程工具箱

入口：主界面【流程】左侧的【流程工具箱】。选择模块及初始化／自动子页，勾选【编辑流程】，再把条目拖到画布；双击条目或选中后按 Enter 也可添加。所有继承 `Flow_BaseForm` 的页面共用此入口。

当前工具箱只有两项：

- 【C# 脚本】：编写小段 C#，计算结果或调用已经配置的真实对象。
- 【条件节点】：节点窗口显示【仅判断条件】，不执行脚本或设备动作，只按 NEXT／CASE 条件选择去向。

【现有功能】和【代码模块】已经移除。工具箱不再列出轴动作、VPP 动作或自动发现的代码模块。实际轴、IO、VPP、Device 和 DataForm 的方法仍可从脚本的【输入输出】页选择并插入调用。

完整设备操作见 [AlphaRap 操作 SOP](AlphaRap操作SOP.md)；脚本接口见 [节点 C# 脚本与调试](FlowScripts.md)。

## 添加并配置节点

1. 设备停止，以有流程编辑权限的维护员或管理员打开【流程】。
2. 选择模块和子页，勾选【编辑流程】，拖入上面的一个条目。普通【添加节点】默认建立 C# 脚本节点。
3. 双击节点或右键【属性编辑】。脚本节点的同级页签为【C# 脚本】【输入输出】【下一步】【超时与调试】；条件节点只显示后两个页签。
4. 脚本在【输入输出】定义端口，并在下方参数行输入固定值或使用【绑定数据】。新脚本默认提供数值端口 Value，源码为 `Outputs.Value = Inputs.Value;`。
5. 需要轴、视觉或数据保存时，在【输入输出】选择【对象】和【方法】，点击【插入对象方法】。窗口回到源码页，插入 `await Context.CallAsync(...)` 并登记【已绑定对象】。按工艺修改参数，并把需要传递的结果赋给已声明输出；插入调用不会替你完成这些 C# 编辑。
6. 在【下一步】配置 NEXT，按需添加 CASE1～CASE3。条件按 NEXT、CASE1、CASE2、CASE3 顺序判定，选第一个满足的出口；脚本本身不通过返回 NEXT／CASE 控制跳转。
7. 在【超时与调试】填写超时、报警号和可选执行前断点。节点【确定】只修改内存草稿；主界面【保存】成功后，退出全部模块编辑，再沿用【初始化】【启动】运行。

右键节点可编辑属性、设置／取消断点或删除。有下游数据引用时先解除引用；模块内还有 FlowChat 节点时不允许删除模块。

## 真实对象和配方

轴、IO、相机、VPP 和设备先在各自原页面建立。脚本目录只读取已有实例声明的方法，不为浏览或拖拽新建设备。外部应用的已有实例仍可由开发人员通过 `FlowExternalResources.Register` 登记；更换实例使用 `Replace`，退出使用 `Unregister`，遵守空闲及引用保护。

脚本允许访问的对象由【已绑定对象】明确登记。删除绑定不修改源码，必须同时处理其中的调用。被引用对象不能直接删除；显示名称不是稳定对象 ID，不要用设备名称替换生成代码中的身份。

配方只从 ProductManagerForm 切换。流程工程和脚本属于机器配置；需要随型号变化的上下限、索引等，通过脚本输入绑定当前 Recipe。Setting 保持独立。轴点位使用该轴自己的绑定表；脚本调用参数中的索引由工程师按原轴表核对，当前脚本页没有已移除动作界面的专用点位下拉。

## 旧节点如何处理

旧 XML 可以加载，但旧 Action 节点和 Code 代码模块节点不能执行。打开时两种新模式均不自动选中，并显示停用提示。请先保留配置备份，查看原业务，再明确选择【C# 脚本】人工改写，或选择【仅判断条件】重新配置；不再需要的节点可解除引用后右键删除。

节点【取消】保留原定义；明确选择并【确定】后才清除旧动作目标及代码模块绑定。原条件、出口、超时、报警与断点供继续核对，原动作实现不会自动转换成脚本。不存在自动迁移工具，配置流程入口可达的旧节点会被主保存和启动校验拒绝；停用模块保留旧定义不代表已经迁移。

模块执行模式【保留原流程】仍表示原业务回调，与旧节点执行方式不同。采用可配置流程的同次机器运行中，其他模块应明确选为可配置流程或停用，避免混用。

## 保存、源码和重新加载

主【保存】从同一流程快照保存 `FlowPrograms.xml`，生成所属 Form 的 `.Flow.g.cs` 和 `FlowSources.manifest.xml`，统一处理文件提交失败。节点【取消】或主保存【取消】不会写入生成源码。

- 开发 EXE 实际位于对应工程 `bin` 下时，默认输出到 `AlphaRap/GeneratedFlows`；本工程已纳入编译。
- 发布环境没有对应源码工程时，默认导出到机器 Setting 目录的 `GeneratedFlows`。【查看生成源码】打开目录，其提示显示实际路径和模式。
- 有源码的 partial Form 使用原命名空间和类型；动态通用模块生成关联定义类，不修改 NPSDK 基类。

生成文件是可读的流程定义，包含脚本、端口、输入引用、出口与布局，仍由同一运行器调度；加载以已保存 XML 为准。删除节点后再次主保存，相应方法和连线消失；末节点删除后保留空定义文件。手写 `.cs`、`.Designer.cs` 和 `.Custom.cs` 不覆盖。受管理生成文件被手改时阻止保存，先备份并处理冲突。

保存配置、生成源码和编译部署是不同动作。主保存不会重建运行中的 EXE 或热替换 DLL。开发人员修改宿主／SDK 的业务实现后需重新编译部署；编辑节点脚本使用编译检查、节点确定和主保存。

## 调试与边界

流程页【节点调试】配合原【初始化】【启动】在入口暂停；【单步执行节点】执行整个节点，【继续】运行至下一节点断点。源码行断点使用匹配源码／PDB 和 Visual Studio 附加调试。

脚本为同进程 C# 5，需要工程人员维护代码；不是无需编程的完整自动化生成器。调用对象应使用框架入口并响应取消，不另建轴、相机或脱离管理的后台硬件任务。当前没有自动产品跟随、MES 持久待传队列或任意回跳重试。本页历史截图和旧代码模块计划不代表当前可用入口；验收及验证结果以当前交付记录为准。
