# FlowChat 功能工具箱

主界面进入【流程】，选择模块和初始化页／自动页，勾选【编辑流程】。所有继承 `Flow_BaseForm` 的页面共用工具箱和节点编辑方式。完整开机、换型和调试顺序见 [AlphaRap 操作 SOP](AlphaRap操作SOP.md)。

工具箱默认收起。点击画布左侧的工具箱图标展开，再次点击收起；收放保留当前搜索、选择和展开宽度，不改变节点位置。收放不切换【编辑流程】，只读或运行状态仍可查看，新增仍需空闲和编辑权限。页面不再常驻操作说明，真实操作错误仍会显示。

模块统一使用混合节点流程，勾选【启用流程】参与机器运行；不再区分旧模式。代码工具只显示函数名称，搜索可使用对象身份或方法名，临时筛选后清空可恢复原选中项。

## 工具箱中有什么

当前 `Flow_BaseForm` 中实现的无参 `Flow_Chart.ResultType` 事件方法会自动出现在【代码流程】分组，可以拖入并与设备动作混合执行。代码节点为只读绑定，不开放双击或右键属性编辑；实现由开发者在所属 Form 源码中维护，已有布局和连接加载保留。已保存工程的连接优先于 Designer 定义；当前没有代码节点专用连线界面，新拖入节点不会自动完成连接。具体写法、NEXT／CASE／IDLE 和保存方式见 [原生代码 FlowChat](NativeFlowEvents.md)。

工具箱按轴、数字输入、数字输出、气缸、视觉、设备、常量表、托盘、流程与数据、本地保存等功能分组。具体条目来自当前已经建立的实际对象：标准动作沿用框架能力，设备、轴和 IO 派生类的公开业务方法自动发现；可以搜索名称并拖到画布，节点统一通过工具箱拖放新增。

例如，选择“X轴 · 移动到绑定表的点位”时，节点已经绑定这个轴和方法；双击只需确认目标点位、参数及下一步。工具箱不会另外创建轴、相机或设备。只需要判断已有数据时，添加【条件节点】。

**当前仅保留【现有功能】和【仅判断条件】。C# 脚本、独立代码模块及其专用编辑入口已移除；原生事件属于现有功能。** 旧 Script／Code 定义可读取，但校验和运行会拒绝执行；需明确选择现有功能或条件重新配置，或解除引用后删除。取消编辑保留原定义，不会自动把脚本解释成别的设备动作。

## 最短操作顺序

以下步骤适用于工具箱中的普通对象动作；代码节点不使用此属性编辑流程。

1. 在原轴、IO、视觉、Device 和常量等页面建立并配置实际对象；型号只用 ProductManagerForm 切换。
2. 在工具箱找到所需实际对象的动作，拖到当前模块画布；不再提供单独的【添加节点】按钮。
3. 双击节点。在【动作设置】核对类别、实际对象、方法，为参数填固定值或点击【绑定数据】选择 Setting、Recipe、上下文或上游节点输出。轴点位只显示本轴绑定表中的有效点。
4. 在【下一步】设置 NEXT。只需顺序执行时保持【无条件通过】，选择目标；需要分支再添加 CASE，为各出口设置独立 AND／OR 条件。
5. 在【超时与调试】设置超时、报警号和可选执行前断点。
6. 节点【确定】提交内存草稿，流程【校验】通过后用主界面【保存】落盘。退出编辑，沿用主【初始化／启动】运行。

功能和条件节点右键可编辑属性、切换执行前断点或删除；代码节点右键保留断点和删除，不提供属性编辑。有下游输出引用时先解除；模块页面仍有 FlowChat 节点时不能删除页面。

## 数据、配方和资源

节点输出由所选方法声明，应用工程师无需另外编写输出函数。下游参数或条件通过【绑定数据 → 节点结果】选择模块、节点及字段。必须是当前运行及产品周期中已完成的有效结果；缺失、过期或其他产品的数据会报错，不以零代替。

Setting 独立于型号；Recipe、轴点位及 VPP 按 ProductManagerForm 当前配方加载。流程工程与对象身份是机器配置。先在原页面修改资源、配方参数和点位并主保存，再运行；启动使用已提交快照。

视觉读输出／存图的【来源拍照节点】只选择同一 VPP 的匹配执行节点，自动绑定它的 RunId。DataForm 保存动作直接列出当前生产表的业务字段，需要逐项绑定，成功后返回 RecordId、Path；主保存配置不会代替实际生产记录写入。

## 主保存与生成源码

主【保存】从同一快照保存机器 Setting 目录中的 `FlowPrograms.xml`（V4），并生成所属 Form 的 `.Flow.g.cs` 和 `FlowSources.manifest.xml`。开发环境通常生成到 `AlphaRap/GeneratedFlows`，发布环境通常生成到机器 Setting 的 `GeneratedFlows`，【查看生成源码】在程序内只读显示文件内容，支持选择文件和复制文本，不提供编辑、删除或打开资源管理器的入口。

生成文件是平铺的流程定义，由现有运行器调度，不建立第二套执行器。重新加载以 XML 为准。删除节点后再次保存会同步删除生成定义；末节点删除后保留空定义。手写 `.cs`、`.Designer.cs`、`.Custom.cs` 不覆盖。受管理文件手改会阻止覆盖，应先处理冲突，不能直接删保护标记。

保存配置、生成源码、编译部署是不同动作。节点配置主保存后供后续启动使用；修改宿主或 SDK 方法实现仍需重新编译部署，主 Save 不会重建正在运行的 EXE 或热替换 DLL。

## 如何扩展实际能力

继承 `AbstractDevice`，完成设备原有的连接实现，再编写普通 `public` 业务方法；重新编译后，在原 Device 页面创建该类型的实际实例，方法就会进入工具箱。无需实现 `IFlowObject`、重写 `GetFlowMethods()` 或编写工具箱登记代码。仅有类、没有实际设备实例时，不会生成虚构对象。

轴、输入和输出同理：继承 `NP_Motor`、`NP_Input` 或 `NP_Output`，编写公开业务方法，将该派生控件作为原轴／IO 页面的实际控件使用。框架复用这个实例，标准轴移动仍只使用它绑定的点位表，不额外暴露任意坐标 `Goto(double)`。标准动作和派生动作共用资源占用与运行入口。

输入来自方法参数，返回值成为 `Value` 输出；异步、取消和 `ref/out` 按统一规则适配。可选 `[FlowTool]` 提供三语名称，`[FlowToolIgnore]` 排除不应提供给流程的方法；没有这些标记也能发现。特殊结果字段、专用参数约束和模拟实现仍可用 `IFlowObject` 高级契约，不是普通工具接入的必需步骤。完整示例、支持签名和驱动层边界见 [继承类并自动生成工具](InheritedTools.md)。

节点调试使用原断点、单步和继续入口。暂停在节点边界生效；停止或超时请求取消，等待真实调用结束再释放资源。现场动作、超时、断线及数据写入仍需联调验证。

## 同一阶段并行启动多条流程

点击【初始化流程】或【自动运行流程】右侧按钮，勾选该阶段需要同时启动的节点入口。【确定】提交草稿，主【保存】提交文件；不选当前阶段有节点的页面会阻止校验和启动。新窗口按初始化页和自动页分别筛选，旧单入口原样保留为一个选中项。

入口组并发调度，初始化必须等待全部入口完成。各流程拥有独立的当前结果、局部变量和计时，仍通过同批次的具名节点输出传递数据。需要等待其他流程输出时，使用条件节点等待该输出有效；动作参数不会自动等待未产生的数据。

各并行入口必须对应独立节点链，不能重复选中同一节点或共同经过一个下游节点。公共能力可以用不同节点绑定同一方法，实际资源仍沿用原有互斥；原生代码方法保留原 Form 及本地对象的资源租约。没有硬件就绪预检查。

初始化报警后，处理原因、清除报警，再点主【初始化】，仅恢复等待中的流程；已完成流程不重跑。主【停止】取消全部入口、清空耗时和恢复位置，收尾后再次初始化从所有入口重新开始。节点调试面板可选择当前观察的并行流程，单步和继续只作用于所选流程。

V4 的 FlowPrograms.xml 和生成的 .Flow.g.cs 都保留完整入口集合。兼容读取 V1/V2/V3；主保存后升级格式，旧版程序不能用于读取 V4。入口组属于机器流程设置，配方仍由 ProductManagerForm 管理。
