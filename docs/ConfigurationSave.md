# 主界面统一保存

配置编辑沿用主界面左侧的“保存”。页面修改和算法编辑确认产生内存草稿；生产数据与生产照片仍由流程业务动作保存。

## 保存范围

- 模块 Setting、当前 ProductManagerForm 配方、轴点位与常量。
- 硬件资源定义、生产表字段和流程工程。
- VPForm 相机、VPP、补偿与标定配置，以及当前配方中编辑过的 ToolBlock。
- DeviceControl 设备清单及其离线参数。
- 现有机器数据库中的 PermissionSetup 权限映射；用户账户增删改沿用账户管理行为。

机器 Setting 不随配方切换。当前配方的视觉算法有草稿时，切换配方前必须先保存或放弃。轴、IO、相机和设备仍使用原页面的真实对象。

## 工程师操作

1. 在原页面编辑参数，或在 ToolBlock 编辑器确认保留修改。
2. 点击主界面“保存”，选择“是”提交整套配置。
3. 选择“否”恢复上次保存的配置；选择“取消”或关闭确认窗口保留草稿。
4. 保存失败时修正提示中的文件或参数后重试，草稿和未保存标记保留。

权限页和 VPP 页不再单独写配置文件。ToolBlock 编辑器中的“保留修改”只确认内存草稿，退出编辑器并不代表已经保存到磁盘。底层显式的 VPP 导出/保存 API 继续可用，配置页面不通过这些 API 绕过主保存。

## 提交边界

主保存先校验并捕获所有参与配置，在目标文件的同目录使用短文件名暂存。数据库暂存副本仅更新 PermissionSetup，不修改正式数据库或用户账户。所有暂存文件写入成功后才替换正式文件；替换失败时恢复已替换文件，并把错误返回主入口。全部成功后才接受草稿和发布流程版本。

放弃前先检查设备 XML 和权限数据库，已保存算法的源文件丢失或损坏时保留可恢复的算法草稿。放弃流程仍依赖现有模块加载路径，并不保证外部文件在恢复过程中再次被改写时整包内存原子恢复。

此处提供的是可报告异常下的回滚。突然断电或强制结束进程后的跨文件恢复日志尚未实现；原 DLL 生命周期、配方整体切换及稳定 PointId 仍属于后续工作。

## 验证

Debug/x64 隔离构建通过，使用仓库固定的 NPSDK 发布 DLL；未包含其他未提交的页面和项目文件改动。

- 104 项流程/脚本回归、7 项启动与原主保存检查通过。
- 新增 17 项真实主保存检查：视觉、Device 和权限共同提交，三语保留草稿，暂存/中途/末尾提交失败回滚，新 VPP 回滚删除，放弃/重新加载及 Setting/Recipe 作用域。
- 覆盖真实“是/否/取消”按钮、窗口关闭、源 VPP 丢失、损坏 XML/MDB 预检、删除算法后配方草稿保护和原站实例恢复。
- 权限更新在隔离 MDB 副本测试，核对 UserData 保持不变；测试未初始化硬件或启动生产线程。
- 62 项视觉兼容回归通过；其中两项更新为“编辑后磁盘不变，主保存提交后重载新值”，使用实际保存引擎。
- 最后的页面离开补丁后，重新运行 7 项启动和 17 项保存检查，确认从托盘页取消保存仍保留草稿及修改标记。

新增检查位于 `tests/FlowProgramming/ConfigurationCases.cs`，随 `tests/FlowProgramming/Run.ps1` 运行。实际轴、相机和设备通信未做实机验收。
