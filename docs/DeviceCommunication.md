# 设备通信优化与验证边界

## TCP 与基恩士 3D

`NPClient.TCPCLient` 保留原来的连接、发送、接收签名，异步入口使用 `CommunicationResult<T>`。排队、连接和一份事务共用总时限，停止关闭捕获的旧 Socket，真实收发及清理退出后才释放占用。改变端点、故障和停止会撤销旧队列。没有自动重连、重发和生产恢复。

`ReceiveAsync` 返回实际收到的字节，不补零，也不宣称原始二进制报文已经完整。行协议用 `ReceiveLineAsync`，跨网络分包累计 CR、LF、CRLF；原始 `Sent` / `Receive` 保留分步语义，设备适配器的完整协议事务在一个租约中执行。只有真正的共享会话握手，不再用另一条 TCP 探测连接冒充目标设备连接确认。

扫码枪和通用 TCP 共用连接所有权及完整行缓冲实现，扫码枪仍单独提供其 LOFF 停止协议，3D 不发送未经确认的硬件停止命令。已使用的测量连接在下一次事务前轮换，旧连接上的额外帧不进入新一次测量。连接频率和设备侧主动转移旧数据的行为仍需现场确认。

3D 的每份事务至多发送一次 EXW 和一次 T1，去掉原有十次重复触发、重复 EXW 和固定等待。位置 0 只发送测量；1–6 先发送 `EXW,位置-1`，匹配确认后才测量。保留原测量的纯数值或 T1 前缀标量，拒绝空值、设备错误、多输出拼接、NaN 和无穷大。

现场型号和应答样例尚未提供，因此不猜测 EXW 成功格式。设备参数 `ProgramAck` 默认空；使用位置 1–6 前须填写**现场确认的完整成功应答**，可用 `{position}` 代表实际零基位置。空配置不发送切换，错误应答返回未确认并禁止继续触发。`MeasurementPrefix` 默认 `T1`，可按实际输出格式配置；未知应答进入明确故障。`TimeOut` 默认 1500 ms，范围 1–60000。新增设置沿用 DeviceControl 的机器 Setting 和 MainForm Save，不新增保存或配方入口。

`Triger3D` / `Change3D` 的旧字符串接口仍保留，失败返回 ERROR；流程方法改用类型化结果，ERROR 不再成为成功数据。故障日志保留通信原因、未确认命令和原应答。停止关闭连接不等于撤销控制器已经接受的动作，设备侧停止逻辑仍需按实际型号验证。

验证入口：`tests/TransportReliability/Run.ps1` 使用真正的 TCP 栈和配置的实际实例，只连接回环服务器。覆盖共享连接、分包、字节长度、队列时限、取消、单次触发、切换应答、有限高度和旧连接隔离；同时运行扫码枪回归以检查共享实现兼容性。离线结果不替代现场型号、EXW 应答、测量前缀、连接频率和生产节拍验证。

## 串口

`SerialOperation` 将原生调用、取消关闭及关闭失败分别保留为真实占用。读写设置有限时限，协议读取在小段原生等待间检查取消。取消回调独立关闭当前请求捕获的端口，不阻塞 UI 或其他端口；原生 Open 迟到返回时还会再次关闭，不能留下已停止会话的新句柄。只有原生调用及关闭实际结束后才释放租约；驱动级 Open/Close 卡死不会被一个超时任务伪装成已经停止。关闭失败阻止复用，须显式成功重试清理。

`NPSerialPort` 在连接时重新建立实例，不复用已 Dispose 对象。校验串口参数及成对十六进制字节，不再在每次写入时清空输入和待发输出；原始读取返回实际字节，而不是 ReadBufferSize 大小的零填充数组。原有方法签名保留，取消抛出，其他旧式失败标记可通过 LastStatus 区分。FFU 无有效应答不再伪装成 0 风速，等待也能取消；FFU 物理帧格式未提供，未猜测新的响应结构。

Modbus 03 一次发送后按头部及字节数收齐完整正常或异常帧，校验站号、功能码、长度和 CRC。寄存器范围及数量按 [Modbus 协议规范](https://www.modbus.org/file/secure/modbusprotocolspecification.pdf) 校验，CRC 使用低字节先发。`GetResultData` 不再读取两次，单寄存器不会越界。原来双寄存器取第二个值的兼容行为保留。

气密仪读取完整终止行，不把即时缓冲半行或多行拼接成一次结果，不在读取失败时自动打开端口。电阻计只注册一个接收事件，事件不使用阻塞 ReadLine；跨事件拼接完整行后才校验全部有限通道值。打开、关闭及 READ? 前清除旧缓存，用接收代次拒绝迟到回调。公开 SerialPort 字段保留兼容，直接绕过设备方法操作这些字段仍不受事务保护。

所有新增 TimeOut 设置继续通过既有机器 Setting 和 MainForm Save；电阻计无效的数据位默认值从 0 修为 8，已有明确配置不静默修改。Modbus 和气密仪保留原参数键。串口台架未连接：离线用阻塞函数验证真实占用、迟到 Open、关闭失败及队列时限，用固定 Modbus 向量验证帧校验，用完整/半行/旧代次数据验证电阻结果；实际驱动、波特率、DTR 行为、物理帧间隔和设备端旧数据仍需现场验证。

## 手动设备页与整机停止

框架 6.3.0 为模块增加可等待的手动动作入口，为设备 UI 增加 `DeviceOperations` 全局任务登记。打开、关闭、发送、接收及 AutoOpen 在后台执行，UI 只处理输入快照、日志、状态和 Received 事件。原同步公开方法保留兼容；固定控件仍来自 Designer，按钮忙碌状态不增设新的状态条或保存入口。

操作期间禁用同一面板的重复打开、收发、切换设备和参数编辑，关闭仍可中断当前操作。同页多台 AutoOpen 各自登记，不因模块的单一手动动作锁漏开第二台设备。整机命令从受理到准备、派发完成期间预留设备入口；生产流程运行或整机正在停止时，也不派发新的手动 IO。用于解锁旧 IO 的关闭任务仍可执行。

整机停止和暂停手动操作会独立取消所有登记任务；启动及主保存、配方切换以登记的实际占用为准。窗口或模块已经释放时登记仍保留，真实 IO 和取消回调全部结束才移除；控件释放不会让系统误以为旧驱动已经退出。停止代次还会撤销尚未交付到 UI 的旧接收事件，不把迟到值显示或交付到其他设备。

语言和原有配置保存机制沿用既有入口。离线 UI 检查使用真实 WinForms 消息泵和不访问硬件的阻塞设备，覆盖心跳响应、关闭取消、重复打开、窗口释放、取消回调阻塞、忙碌拒绝、多个自动连接及停止后的接收事件作废；不替代现场设备和 Visual Studio 交互设计器验证。
