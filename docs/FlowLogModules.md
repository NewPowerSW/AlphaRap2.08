# 界面配置日志模块与 FlowChat 写日志

## 1. 在数据页新增日志

打开左侧【数据】→ 上方【日志模块】→【新增日志模块】。

填写模块名称和保存目录，然后在右侧字段表增加需要记录的字段。Time 由程序自动记录，无须添加；每条记录的其他字段由 FlowChat 提供。

点胶日志的一个例子：模块名 `DispenseLog`，目录 `D:\Log\DispenseLog`。

- Barcode：Text，条码。
- DispenseTimeMs：Number，点胶时间。
- WeightG：Number，点胶重量。
- X、Y、Z、Height：Number，定位和 AOI 检测结果。
- Result：Boolean，判定结果。

字段名称属于业务数据，不参与语言翻译。模块或字段右键可删除。内置 Alarm、LogRun、LogError、MESLOG、UserLogin、OperationLog 保留，通过这个窗口不能改写其结构或删除它们；自定义模块也不能占用它们的名称和保存目录。

窗口【确定】只提交内存草稿；之后点击主界面【保存】，日志定义和流程工程一起保存。取消窗口不更改草稿；主保存失败保留草稿及原文件；主界面选择放弃恢复已保存的定义。

## 2. 在 FlowChat 中写入

1. 进入【流程】并勾选【编辑流程】，打开工具箱的【日志模块】分类。
2. 将目标模块的【写入一条日志】拖到画布；也可在已有自定义功能节点中选择功能类别【日志模块】、实际对象和【写入一条日志】方法。
3. 双击功能节点，为每个字段选择数据来源。可以是固定值、Setting/Recipe 参数、流程上下文，或其他 FlowChat 的输出。
4. 例如 Barcode 绑定扫码节点的输出，WeightG 绑定称重结果，Height 绑定 AOI 节点结果；不要把界面上的显示文字作为测量值手动复制。
5. 配置 NEXT／CASE，连接该节点，最后使用主界面【保存】。

写日志是一个独立的流程动作，可以和原生 C# 节点、轴运动、视觉等节点混用。代码节点仍保留原 C# 事件入口。每次运行到日志节点追加一条记录，记录成功后输出 `Path`，后续节点可绑定该文件路径。写入失败或缺少/不匹配字段时节点报告失败，不能按已保存处理。

删除仍被流程绑定的自定义日志模块时会提示先修改节点；改名保留模块身份，现有绑定不会按名称重新猜测对象。

## 3. 查询和文件位置

新模块立即进入数据页的查询下拉框；配置保存后重启仍能找到。选择模块、日期范围，再点【查询】；导出沿用现有数据页。

文件目录为 `{保存目录}\{yyyy}\{MM}\{yyyy-MM-dd}.csv`。支持中文、逗号、引号、字段内换行和跨年月查询。同一天修改字段结构时，使用带结构标识的 CSV 文件，保留旧文件；查询按文件表头合并显示历史字段。

相对目录以程序目录为基准。模拟运行写到所选模块目录下的 `Simulation` 子目录，与正式记录分开；模拟节点返回的 Path 指向该文件。

## 4. 配方和配置作用域

日志模块定义保存在机器 Setting 目录的 `DataForm.LogModules.xml`，不会随配方切换重建。配方仍由 ProductManagerForm 管理；日志字段如绑定 Recipe 参数，执行时使用当前配方的已保存值。配置持久化只有主界面【保存】入口，运行记录由日志节点自动落盘。

界面支持中文、English、Español。旧 C# 的 TypeCollection1.SaveDataToFile 接口继续可用，并使用相同的 CSV 编码及串行写入规则；IO 失败会抛给业务调用方，调用方应按照原流程异常处理约定处理。
