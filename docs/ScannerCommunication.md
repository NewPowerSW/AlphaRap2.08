# 基恩士扫码枪 TCP 通信

本轮只改 AlphaRap 应用侧的 `ScannerKeyenceTcp`，继续使用已经配置的设备实例和现有框架 6.2.0。扫码、设备工具箱、手动发送接收共用一个连接及请求租约，构造和浏览工具箱不连接设备。基恩士 3D、其他 TCP 设备和串口尚未迁移。

## 配置与协议

保留设备类型、构造函数和 `IP`、`Port`、`TimeOut`、`length` 属性名称及默认值，兼容现有 DeviceControl.xml。仍由 MainForm Save 写入机器 Setting，ProductManagerForm 继续负责配方；没有新增配置文件或保存入口。连接状态和最近结果是只读诊断，不进入参数保存列表。固定错误说明提供中文、英文和西班牙文，设备名、地址和输入值不翻译。

- `IP` 支持原有 IP 地址和主机名；DNS 的迟到结果不会继续建立已被停止的设备连接。
- `TimeOut` 为每次连接或完整命令的总上限，单位 ms，范围 1–60000，含排队、连接、发送和接收。排队超时或取消不会关闭另一条正在执行的请求。
- `length` 为一条应答在行结束符之前的最大字节数，范围 1–65536。完整数据在收齐后解码，不能把多字节字符的半包当成文本。超过上限返回协议错误，不返回截断的条码。
- 沿用现有 `LON\r\n` 触发和 `LOFF\r\n` 停止命令及 `Encoding.Default` 编码。接收支持 CR、LF、CRLF，跨包累计；同包多行在手动接收中逐行返回。单次扫码只交付一行，空条码和 `ERROR` 都是明确失败。

不再使用固定 50 ms 睡眠或读取一次即认定收齐。没有配置行结束符的设备会超时，须核对现场扫码枪的输出设置，不能依靠网络空闲间隔猜测报文结束。

## 连接与停止

`ConnectAsync`、`ScanOnceAsync`、`ReceiveAsync` 返回 `ScannerResult`。结果分别表示成功、未连接、手动应答占用、配置无效、超时、取消、远端断开、设备拒绝、协议错误和网络失败。失败的 `Value` 为 null；`RequireValue` 在流程中抛出对应异常，取消使用取消异常。连接成功只表示 TCP 握手成功，不能证明设备已准备好或扫码成功。

保留 `Open`、`Close`、`StartRunning`、`StopRunning`、`ScanOnce`、`Send`、`Receive` 旧入口。同步入口继承 NPSDK 当前执行令牌；`ScanOnce` 的旧调用保留 `ERROR` 哨兵，手动接收保留空串约定，具体原因见 `LastResult`。流程的 `scanner.once` 和 `device.receive` 使用结果接口，不再将 `ERROR` 或接收失败视为成功输出。连接异常交给现有页面及流程统一显示，不另开后台错误弹窗。

重复打开同一端点共用一条连接；连接、扫码及原始收发串行执行。原始 `Send` 保留应答占用，接收或停止前不允许另一次发送或扫码抢走它的结果。手动发送 `LOFF` 走停止路径，不遗留一条等不到回应的原始命令。

成功扫码后发送 `LOFF`。由于当前条码应答没有请求编号，下一次扫码或新的原始发送会先关闭已经使用过的旧连接，再建立新连接并发送命令。旧连接的多余行、迟到包和停止应答不能被下一次触发读取。连接轮换增加一次握手，需要在现场确认设备允许的连接频率及实际节拍；去掉固定睡眠不等于已经证明现场吞吐提高。该机制不能识别设备主动移交到新连接的旧扫描结果，设备侧事务编号或触发模式仍须按实际型号确认。

停止立即撤销旧队列并取消当前操作。取消回调只关闭本次捕获的 Socket，不会关闭随后创建的连接。已经确认触发且没有写入正在进行时，清理会尝试一次 LOFF，最多等待 100 ms，然后关闭套接字；不并发插入第二条发送。挂起收发及清理实际退出后才释放请求租约和 `IsRunning`。并发停止合并为同一个完成任务，连接中的迟到回调不能恢复已停止状态。

失败、超时和取消后关闭连接并撤销旧队列，不自动重连、不自动重新触发、不自动恢复生产。停止结束保持未连接，需要显式 `Open` / `ConnectAsync`。若命令可能已发送却没有确认结果，保留 `CommandMayHaveExecuted` 并写入报警日志；先核对设备状态，不能把中断当作命令未执行。更改端点期间返回的旧数据也不会发布到新配置。

## 验证

`tests/ScannerCommunication/Run.ps1 -AssemblyDirectory <实际构建目录>` 使用真实设备类和真实 Socket，只连接回环测试服务器，覆盖十八个场景：无副作用构造及配置校验、重复连接、主机名与连接失败、中文多字节分包及分开的 CRLF、旧条码隔离、空/ERROR 应答、半包超时、EOF、最大长度、读取中取消、停止与重启、排队时限、手动应答占用、修改端点、连接关闭竞态、流程异常与实际实例、旧同步入口令牌、三语诊断及参数保留。

完整 FlowProgramming 回归中的主保存、保存失败、放弃修改、设备重建、语言和配方切换用例继续检查现有配置集成。离线验证不连接真实扫码枪，不替代设备输出终止符、LOFF 行为、连接频率及实际生产条码的现场验证。
