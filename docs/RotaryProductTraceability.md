# 转盘点胶项目：产品随行数据设计

2026-10-25 设计提案。基于 AlphaRap `ab8f69f` 与固定 NPSDK `4e21ed4` 复核；以下产品台账、位置映射与可靠上传属于拟新增能力，本轮未修改程序或 DLL，未连接设备或 MES。

## 核心做法

每件产品拥有一张持久的电子随行卡。入料确认时先分配内部 ProductId，绑定实际治具和穴位；扫码向这张卡写 Barcode。点胶、称重和 AOI 各自向同一产品追加工序结果，装盘确认后形成最终记录。转盘运动改变工位和治具的对应关系，产品数据一直归属于 ProductId。

不能等到扫码后才创建内部产品身份：上料确认到扫码成功之间也会发生停机和人工处理。条码重复、补扫或返工应按业务规则核对，不自动并入上一件产品。

例如，C03 治具的第 1 穴装入产品 P000127。它先在点胶工位，再随转盘到 AOI。点胶和 AOI 读到的都是 P000127；最后装入托盘 T20261025-008 的第 12 穴。治具 C03 之后装入新产品时分配新占用代次，不能继承 P000127 的结果。

## 当前框架能复用什么

- FlowResultHub 已按运行批次、CycleId、模块/节点身份保存与读取结果，可同时保留不同产品键；当前每个执行上下文只有一个 CycleId，宿主默认是 `batch`，没有实物治具/穴位映射。
- `cycle.begin` 按传入键修改当前关联；同一件产品经过各工位时必须共享同一个产品关联身份，并行的不同产品使用不同身份。输入留空会各自产生新 ID，扫码在 batch 下产生的输出也不会在切键时自动迁移。真正释放结果的是 `cycle.end`；现有 begin 帮助文案与此实现不完全一致。
- FlowChat 的真实 IO、轴、VPP、扫码设备和类型化结果可以继续使用；产品台账不另建设备连接。
- DataForm 能定义 Text/Number/Boolean 生产字段，`data.save` 能保存条码、点胶参数、AOI 等一行记录，并有同日同 RecordId 去重。
- RecordId 当前取运行/模块/调用身份，跨重启或重新执行不能代表同一件产品。CSV 索引会从目标日文件恢复，但跨日不查上一日，同 ID 不同内容也未检测冲突。
- 当前托盘对象只计算行列偏移，没有本地产品占位清单。LENS 等客户 MES 类含托盘绑定等协议，但没有框架级持久待传任务和确认闭环。

因此，现有基础适合扩展；直接把多个节点输出一直拉到装盘节点，还不足以承担多件同时在制的追溯。

## 产品卡需要保存什么

应用工程师看到的业务字段：

- 产品：条码、型号、批次、入料时间、当前状态。
- 点胶：实际开始/结束时间、实际耗时、胶路/通道、实际重量和判定。配方设定时间与实际耗时分别保存。
- 称重：前重、后重、净胶重、单位、稳定/有效状态。未测、设备错误、跳过和实测 0 分开表达。
- AOI：高度、X/Y/Z、单位、坐标系、OK/NG、检测时间、照片路径。
- 装盘：托盘实例编号、穴位、实际装盘时间、装盘操作号。
- 追溯：总体判定、本地记录状态、MES 状态、失败原因。

框架自动维护 ProductId、加工轮次 ProcessRunId、工序 Attempt、OperationId、配方/字段/流程版本、占用代次和记录版本，工程师不手填 GUID。

同一次工序的多个测点用测点 ID 和测量明细保存，不为每个点硬编码一个 C# 字段。DataForm 保留常用 CSV 列配置；复杂测点另导出明细表，使用 ProductId 和工序次数关联。

XYZ 必须说明属于哪个坐标系；胶重必须说明单位与是否为净重。产品卡捕获本件开始时的配方版本，后续落盘不再读取当时全局型号来覆盖它。

## 转盘和工位如何关联

位置层维护两个关系：`治具编号 + 穴位 -> ProductId + 占用代次`，以及 `已确认转盘相位 -> 工位对应的治具`。同一治具随转盘运动时，其穴位内产品的身份不变。

每个工位流程入口自动取得当前工位的产品句柄，并为一次设备动作分配 OperationId。结果返回时沿用这个句柄，不重新查“现在工位上是谁”。写入校验该操作和加工轮次仍有效；超时、人工移除或结案后的结果进入异常履历，不能覆盖新产品或已封存记录。

位置代次用于起始占位与转移校验。正常转位不等于治具换件，也不应因此丢弃同一产品仍有效的异步测量。

转位的顺序是：

1. 确认当前各工位动作与取放互锁允许转动，记录本次转位意图及编号，状态由 Ready 进入 Moving；Moving 和 Unknown 都禁止新工位绑定及新任务。
2. 调用轴页面绑定的真实转盘轴及点位/运动方法。
3. 依据实际到位与定位确认，提交新的相位和工位映射。
4. 动作超时、结果不明或重启后位置不符时标记当前位置未确认，保留上次已确认相位作历史依据，禁止新工位绑定；不能继续拿旧映射开工，也不能凭已发送指令或经过延时就移位数据。

空穴有明确空状态；多穴治具逐穴关联。实际载具可以通过固定工装序号、RFID 或可验证的相位识别，取决于设备硬件。启动和回零不清空在制品，须核对最后确认相位、占位和实际有料状态。

## FlowChat 怎么让工程师少写代码

每个工位配置一次自己的工位/穴位来源。流程节点继续选择原来的真实设备能力，输入来源增加“当前产品”，如“当前产品 / 条码”“当前产品 / 点胶净重”。

工位任务由已确认相位派发：各站执行一次当前产品工艺，完成后汇合转位互锁，下一次分度后再派发新任务。工位未完成前不能重入加工下一件。现有运行上下文和周期需要接入这个调度，不能只在选择器里加一个“当前产品”字符串。

可见操作收敛为五类：

1. **产品进入**：入料确认后绑定治具/穴位，生成本件身份；扫码写条码。
2. **记录工序**：设备输出绑定产品字段，常见映射如称重值到点胶净重、VPP 输出到 AOI 高度。
3. **确认转位**：运动到位与定位信号满足后提交相位。
4. **确认转移/装盘**：记录来源、夹爪临时位置、托盘实例和穴位，确认后更新占位。
5. **产品结案**：检查必填工序、保存终态、登记日志导出和 MES 待传任务。

常用采集节点可配置“结果记录到当前产品”，由框架在收到真实结果时落盘，工程师不必每个字段再拖一串写值节点。特殊计算仍可用小脚本，结果也通过同一产品接口写入。

**工序事实与流程出口分开。** 当前运行器在出口条件通过后才发布普通节点输出。点胶已完成但后续条件超时，不能因此认为产品未加工。新的产品记录入口应在动作开始前保存意图，在真实动作返回时记录完成或异常，再进行 NEXT/CASE 放行判断。OK、NG 和未知事实均可追溯。

设备若支持请求号，应关联本次操作回执；否则项目驱动需明确握手、清旧完成信号及单个未决请求规则。框架里的 ProductId 无法单独识别设备返回的旧完成信号。

## 工序间自动保存，装盘时提交终态

条码、点胶、称重、AOI 各自确认后就保存检查点，不能全部留在内存等装盘。照片先确认文件写入，再登记路径/摘要；必需照片未保存时不能把本件标为资料完整。图片和设备动作不与数据库构成同一个物理事务，失败需要明确待处理状态。

建议新增一个独立本地事务库，例如 SQLite，集中存储在制品、位置、工序履历、最终记录与待传任务。保留 DataForm 的字段定义、查询与 CSV 使用方式；用户和权限 MDB 不混入大量生产数据。具体 .NET 4.8/x64 驱动、写入同步与恢复参数在实施时选择并验证，本方案不承诺只换存储名称就具备掉电恢复。

SQLite 的事务原子性可用于让一组本地状态共同提交，但其文档同样说明了磁盘刷新、锁和硬件假设；不能把 MES、CSV、照片或实际运动算入这笔数据库事务。[官方事务说明](https://www.sqlite.org/atomiccommit.html)

最终装盘的顺序：

1. 预留目标托盘穴位，记录产品、来源和装盘操作号。
2. 实际取料确认后将位置记为夹爪/搬运中，放料确认后才确认目标穴位；动作不明进入待核对，不能自行重放。
3. 在同一笔本地事务中保存装盘清单、不可变最终产品记录、CSV 导出任务和 MES 待传任务。
4. 事务成功后，转盘的原治具可按已确认转移释放；本地产品历史持续保留。
5. 按项目要求确认 CSV 导出和 MES 业务应答。若要求二者成功才放行，托盘保持待放行；是否允许经授权离线生产由项目规则决定，默认不自动绕过。

CSV/日志继续提供给现场使用。从已提交记录按固定业务日期和 RecordId 导出、补写或重建，记录导出状态；写 CSV 失败不能丢产品记录，也不能假报日志已生成。日志必需时，放行条件应检查导出确认。

## MES 的可靠提交

上传任务捕获固定 MessageId、ProductId、最终 RecordId、记录版本、目标接口/映射版本和不可变内容。重试不从当前界面或“最新一件产品”重组数据。

- 只在本地记录提交后发送，按约定 JSON/XML/协议适配客户 MES。
- 校验业务成功码与对应条码/记录/消息身份，保留回执。HTTP 200 不等于业务接收成功。
- 超时可能意味着服务器已接收而应答丢失，进入待确认；不能直接当未发送。
- MES 支持幂等键或回执查询时，使用同一 MessageId 重试/核对；不支持时由双方确认补偿规则，不能单方面保证外部系统只记一次。[HTTP 重试语义](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2)
- 明确拒绝与通信不明分别处理；待传队列有次数、间隔、容量和人工处理记录，不无限占满磁盘。
- 返工新增加工轮次/工序次数；已经上传的快照不原地改写，新的记录版本按客户协议补传。

产品可以已装盘但 MES 待确认，所以实物位置、工艺判定和上传状态分别保存。释放运行结果缓存不删除本地产品记录。

## 配置与运行边界

字段定义、单位、工位布局、治具/穴位定义、静态相位规则、MES 映射与策略属于配置，接入主 Save 和放弃路径。当前相位、实时占位、映射版本、生产记录、装盘清单和上传回执属于运行数据，由流程自动持久化，不要求操作员点主保存。

ProductManagerForm 继续唯一配方入口。建议默认有在制品时禁止切换生产配方，即使机器已暂停/待机也一样；需要混流时应另做每件独立工艺版本调度，不能仅靠读全局型号支持。设置切换与各字段显示沿用三语，字段业务键不翻译。

界面只需一张在制品看板：当前工位/治具/穴位、条码、工序状态、关键测量、本地状态与 MES 状态。点开一件可看完整履历。人工取料、报废、返工、换盘需通过有权限的确认操作留痕，不能直接改表格里的 ID。

## 建议实施顺序

1. 产品身份、位置占用和本地检查点：先用三件不同数据走完整转盘，验证不串件、失败转位不移动数据。
2. 工位上下文与类型字段绑定：接点胶、称重、AOI，记录真实结果及工序次数；复用原真实对象和 FlowChat。
3. 装盘确认、最终记录和 CSV：加入夹爪临时位置、目标穴位预留及失败恢复。
4. MES 适配与持久队列：使用客户测试接口验证业务 ACK、去重、断线与跨日重试。
5. 重启/人工操作恢复验收，再按现场节拍测量持久化和查询性能。

工程师只配置对象、字段与工艺规则；产品编号、占用代次、检查点、幂等和重试由框架统一负责。这是新增业务能力，而不是把各工位的变量复制到一张全局 Setting 表。

## 关键验收

- 三件不同条码、重量和 AOI 同时在制，连续多圈及空穴、NG 穴不串数据。
- 已点胶但确认丢失、转位未到位、点胶后掉电，重启不自动再次点胶或把相位推进一格。
- AOI 超时后旧结果返回，不能污染下一件或已封存产品；保留异常履历。
- 人工取料、治具换件、多穴与返工均能说明当前产品的去向。
- 机器人取走后掉电、放料完成但确认丢失时，夹爪和目标盘穴位进入待核对。
- MES 成功但响应丢失、跨午夜/重启重试、重复 MessageId 和同 ID 不同内容均有明确处置。
- 磁盘满、CSV 写失败、照片写失败或队列达到上限时不假报成功。
- 在制品恢复核对完成前不自动放行；在制品存在时不能静默换配方。
