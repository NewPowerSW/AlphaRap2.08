# 按实际对象配置流程节点

设计器继续使用 NPSDK 的 Flow_Chart、Flow_BaseForm、NEXT / CASE 和既有运行器。对象负责声明自己能做什么，节点编辑器负责选择与绑定，运行器负责顺序、结果、取消和报警。设备类型与执行动作不再集中维护在设计器的大段判断中。

## 应用工程师的操作顺序

1. 在原页面配置轴、点位表、IO、Device、相机及 VPP；型号由 ProductManagerForm 管理。
2. 进入【流程】，选择任意 Flow_BaseForm 模块并启用编辑；添加或拖动节点，双击配置。
3. 选择【实际对象】及【对象方法】。类别只用于筛选对象；方法来自选中实例，不会把另一台仪表的方法套过来。
4. 在业务参数行直接输入固定文字 / 数值，开关选择是 / 否，有选项的字段直接选择点位或参数名称。需要 Setting / Recipe 参数、节点结果或上下文时点击该行【绑定数据】，在同一个可搜索窗口中选择；界面显示业务名称，工程文件记录稳定身份。
5. 用本次结果配置 NEXT；需要其他路径时再添加 CASE。超时独立报警。最后把业务字段映射到 DataForm 的保存方法。
6. 校验并点击主界面【保存】，退出编辑后使用主界面【初始化 / 启动】。修改配置、放弃修改、语言与配方切换继续沿用原入口。

## 轴、VPP 和其他对象

【轴运动】只列出轴页面的真实轴实例；MTR_H1_X 等已有轴与新增 Axis_1、Axis_2 均可复用，托盘计算在独立类别中。先选轴，再选【目标点位】，不再填写或另选 Table。组合轴直接绑定自身点位表，其他恰好引用该轴的表不会混入；旧轴由 ParameterSet / WorkMotor 识别唯一绑定，多重绑定必须先在原页面修正。当前选中行不会决定流程位置。节点提示本轴绑定表、总行数和可选点位数；点位列表遍历该表所有有效行，空值、非有限数值或超限行不可选，不会将其他轴的点位混入。若只出现 P1，先在所选轴页面核对绑定表是否确实只有一行；添加或编辑后关闭并重新打开节点刷新目录，主保存后才供正式运动使用。

轴移动默认只显示【目标点位】，勾选【显示高级参数】再设置【附加偏移】和【到位允许误差】。点位选项显示序号、内部索引、备注与坐标，内部字段仍为 Index；偏移仍为 Offset，不会自动叠加视觉补偿。旧非默认高级值或已绑定高级参数会自动展开。位置、指令位置、停止、回零及报警复位均调用同一个轴实例。回零遵循驱动的状态机，Goto 返回 false 不视为拒绝运动；取消时停轴并等待静止后才释放占用。

当前 SDK 的运动驱动只有 Adlink 和 Leadshine；Keyence、Omron 提供的是 IO 驱动，不在轴厂商中显示。雷赛的现有轴与 IO 驱动不读取 PLC IP。IO 属性编辑按实际厂商显示字段，输入输出的可见名称使用原控件 Text，内部 Name 和稳定 ID 保持不变。轴、IO 和节点均可通过右键【属性编辑】打开同一配置入口；节点需先启用流程编辑。

【常量表】类别提供 Setting 和 Recipe 两个实际表对象，方法【读取常量值】在【表中参数】按名称选择并输出【参数值】，【设置表值】选择同一参数并填写【新值】。新值可以来自固定值、另一常量或其他节点输出。设置直接更新所选表的数据行，页面立即显示新值；后续读取节点和同批次输入 / 条件绑定读取新值，新批次也继续使用流程明确设置的值。内部 Key / Value 不变，Boolean、Integer、Number、Text 保留原类型，整数拒绝小数，数值拒绝 NaN 或无穷。

节点只改内存中的表值，不调用 AcceptChanges 或写文件。停止后通过主界面【保存】持久化；保存失败保留当前表值和旧磁盘文件，选择“否”放弃修改或重新加载则恢复已保存值。DisScann、UseTryRun 同步更新 PSet 的当前数据行，旧业务接口仍在主保存成功后使用新的 Original 版本。普通页面的未保存编辑继续与生产快照隔离，不因这项设置能力自动发布草稿。

Setting 独立于配方；Recipe 使用 ProductManagerForm 当前配方，切换配方前沿用未保存修改处理。旧配方已排队的设置动作会被拒绝，不写入新配方。后台节点通过界面线程更新绑定表；已取消或过期批次不修改数据。读取、设置节点和直接绑定均参与引用保护，不能删除、改名或改变已使用常量的类型。方法 ID 仍为 constant.set，已有节点无需换成另一种动作。

VPP 对象按 VPForm 原有的相机 / VPP 名称显示，使用持久化 VPP ID 定位。运行方法的输入和输出直接来自该 ToolBlock，界面显示真实端口名，工程仍使用 `TB:端口名` 作为内部键，不翻译或更改端口。执行方式遵循 VPP 内部工具配置；设计器不自行创建采集器或替换算法。【视觉判定通过】的内部键仍为 `Accepted`，可用于 NEXT / CASE 条件；算法异常、超时或取消走原报警处理。流程执行的 NG 不再额外弹出手动拍照的消息窗口。

存图方法使用该 VPP 页面已有的存图设置；存图与单独读取 VPP 输出都通过【来源拍照节点】选择结果。统一选择窗口只列同一 VPP 的 `vision.run` 节点，并自动绑定该节点的 `RunId` 输出，不要求手写运行编号，也不会把其他 VPP 的结果混入。内部结果校验不变：若这个对象已被再次运行，旧编号会被拒绝，防止读取或保存另一产品的结果。未启用存图、没有图像或写入失败时，不返回虚假的成功路径；本阶段不提供延后存图的历史图像缓存。

补偿读取方法选择该 VPP 补偿表中的 Item，输出 Compensation、Min、Max。若运动需要补偿，把 Compensation 显式绑定到轴方法的 Offset。读取补偿本身不执行运动。编辑器可以浏览补偿草稿，正式运行读取主保存后的快照；未保存的相机绑定或 VPP 参数会阻止正式视觉调用。

其他现有能力同样按所属对象提供：DI 读取 / 稳定等待、DO 设置 / 状态读取、气缸动作与到位、实际设备连接 / 状态 / 支持的原始收发、扫码、气密结果、电阻多通道结果、3D 控制器、Modbus、已实例化 PLC、托盘穴位计算，以及 DataForm 生产记录保存。仪表专有方法由对应类声明，父类只提供通用能力。

流程基础对象保留取值、计算、计数、等待、人工输入、报警和产品周期管理。其他节点的输出以模块 / 节点 / 业务字段标识，统一选择器可直接搜索；运行批次和产品周期隔离、重复保存保护及本地 CSV 存储继续复用原实现。

视觉对象目录只从 VPForm 的实际相机 / VPP 配置生成；旧公共字段中默认名为 Camera1 的兼容对象不会列入。旧节点若误绑这些字段，需重新选择实际 VPP 并保存，不能自动猜测替换。

DI、DO、气缸各自分类，不在一个混合对象列表中选择。【读取输入】只采样一次；需要等待变化时选择【等待输入稳定】，设置【等待状态】，高级参数【稳定保持时间】控制连续保持时长。出口等待只重新检查条件，不重复执行动作或重新采样旧的本次结果。

条件编辑采用“左值 — 比较 — 右值”：本次结果和其他节点结果显示业务字段名，右侧候选按已选左侧类型筛选，也可直接输入固定值。布尔结果默认与 true 比较，Empty 禁用无意义的右值要求；新增条件通过【+ 添加条件】，删除仍使用行右键。内部运行编号不再默认列入普通条件，旧工程已绑定的高级字段保留供核对。配置文件继续保存原有结构化来源和比较代码，语言或显示名称不改变引用。

## 参数编辑与数据选择

`FlowInputRow` 复用一种固定布局，根据字段声明显示文字 / 数值输入、布尔选项、固定选项或只读绑定名称。高级字段使用默认值时可收起，已有非默认值或绑定时自动展开；收起不改变数据。失效旧选项和引用会保留供修正，不能用第一项替换。节点窗口编辑的是副本，【取消】不影响原节点，【确定】只提交草稿。

每行的【绑定数据】打开统一 `FlowSourceForm`，在固定值、机器设置、当前配方、节点结果和高级来源中搜索。候选按目标字段类型推荐，数值类型之间可选择，整数性、限值和具体业务约束仍由原有保存及执行校验处理。选择器保存 Source / Reference，不把显示名称写入引用；语言切换保留选择、搜索和未完成固定值输入。当前失效或类型不符的旧绑定可见，但必须修正后才能确认。

## 框架开发者的接入边界

核心契约位于 NPSDK 的 `IFlowObject`、`FlowMethod`、`FlowField` 和 `FlowCall`。

- `GetFlowMethods(includeDraft)` 只读取元数据，禁止连接硬件或执行业务。方法 ID、参数键和输出键保持稳定。
- `FlowMethod` 声明三语标题、类型化输入输出及绑定本实例的 Invoke；可选 ValidateInputs 检查表与点位等组合约束。
- `FlowField` 保留 Name、Type、DefaultValue、Options，并可声明三语 DisplayName / Help、明确单位 Unit 及 Advanced。显示名与说明只服务界面，不改变参数键、类型和执行语义；用户字段、真实 VPP 端口和表中业务键按原名显示。输入与输出同名时使用不同的标题语言键：`field.方法ID.input.字段名` / `field.方法ID.output.字段名`；输入帮助使用 `fieldHelp.方法ID.字段名`。
- 需要绑定特定生产节点的字段可声明 OutputSourceMethod / OutputSourceField。视觉消费者使用 `vision.run` / `RunId`，选择器还按当前实际 VPP 的对象 ID 限定候选；保存校验也检查来源对象、动作和字段，防止旧 XML 绕过界面。旧 API 的固定编号仅为兼容保留，参数表和上下文不能替代受约束的拍照输出。该元数据不创建另一个拍照实现，也不序列化运行对象。
- UsesHardware 为 true 的方法必须提供独立的 Simulate；没有模拟实现时明确拒绝模拟，不能落入真实硬件方法。
- `FlowCall` 提供已解析输入、产品上下文与取消信号。阻塞通信尚未返回时保持资源占用，取消后不得发布迟到结果。
- AbstractDevice 和 VisionproInterface 提供虚方法；设备子类扩充自己的声明。既有 SDK 轴与 IO 通过薄适配器使用同一契约，不创建第二份驱动。
- 已注册模块本身或其已有字段实现 IFlowObject 后，可以进入目录。发现对象仅读取字段，不调用任意属性、构造器或未声明的 .NET 方法。DeviceControl、VPForm 等原有对象优先使用原来的稳定身份，避免重复列出共享实例。

新 MES 协议、自定义算法或特殊硬件仍需框架开发者先声明实际可调用的能力，应用工程师随后选择、传参和连接。此版没有伪造通用 MES 上传接口，也没有把整个 Form 的所有公开方法直接暴露为流程指令。

## 保存与旧工程

工程仍保存对象 ID、方法 ID、输入来源、节点布局、出口条件、超时与报警，不序列化实例或委托。MainForm Save 完成校验和写盘后发布运行版本；放弃修改恢复上次保存。

旧工程中的点位目标保留解析能力，新建节点的对象列表不再单独展示点位表。之前版本带 Table 输入的移动节点会要求重新打开、核对 Index 并确定，再使用主界面【保存】；不会静默更换绑定。VPP 端口或 DataForm 字段改变后，保存 / 启动校验同样要求重新确认节点输入，不会猜测补齐缺失字段或选择另一对象。

此版保持原有顺序流程和跨模块结果交换语义，尚未增加多产品自动队列、任意回跳重试或断电后自动续跑。现场硬件与 MES 协议仍需按实际设备联调。
