# 按实际对象配置流程节点

设计器继续使用 NPSDK 的 Flow_Chart、Flow_BaseForm、NEXT / CASE 和既有运行器。对象负责声明自己能做什么，节点编辑器负责选择与绑定，运行器负责顺序、结果、取消和报警。设备类型与执行动作不再集中维护在设计器的大段判断中。

## 应用工程师的操作顺序

1. 在原页面配置轴、点位表、IO、Device、相机及 VPP；型号由 ProductManagerForm 管理。
2. 进入【流程】，选择任意 Flow_BaseForm 模块并启用编辑；添加或拖动节点，双击配置。
3. 选择【实际对象】及【对象方法】。类别只用于筛选对象；方法来自选中实例，不会把另一台仪表的方法套过来。
4. 为每个输入选择固定值、Setting / Recipe 参数、其他节点输出或产品上下文。输入和输出显示类型；选择项通过按钮选择，界面显示名称，工程文件记录稳定身份。
5. 用本次结果配置 NEXT；需要其他路径时再添加 CASE。超时独立报警。最后把业务字段映射到 DataForm 的保存方法。
6. 校验并点击主界面【保存】，退出编辑后使用主界面【初始化 / 启动】。修改配置、放弃修改、语言与配方切换继续沿用原入口。

## 轴、VPP 和其他对象

轴节点先选轴页面上的实际轴，再选它绑定的 Table 和 Index。只列出 ParameterSet / WorkMotor 关联到该轴的点位表；当前选中行不会决定流程位置。Index 显示点位序号、内部索引、备注与坐标。Offset 是显式输入，不会自动叠加视觉补偿。位置、指令位置、停止、回零及报警复位均调用同一个轴实例。回零遵循驱动的状态机，Goto 返回 false 不视为拒绝运动；取消时停轴并等待静止后才释放占用。

VPP 对象按 VPForm 原有的相机 / VPP 名称显示，使用持久化 VPP ID 定位。运行方法的 `TB:端口名` 输入和输出直接来自该 ToolBlock。执行方式遵循 VPP 内部工具配置；设计器不自行创建采集器或替换算法。`Accepted` 表示 OK / NG，可用于 NEXT / CASE 条件；算法异常、超时或取消走原报警处理。流程执行的 NG 不再额外弹出手动拍照的消息窗口。

存图方法使用该 VPP 页面已有的存图设置，RunId 绑定前一拍照节点的输出；单独读取 VPP 输出也需要对应的 RunId。若这个对象已被再次运行，旧编号会被拒绝，防止读取或保存另一产品的结果。未启用存图、没有图像或写入失败时，不返回虚假的成功路径。

补偿读取方法选择该 VPP 补偿表中的 Item，输出 Compensation、Min、Max。若运动需要补偿，把 Compensation 显式绑定到轴方法的 Offset。读取补偿本身不执行运动。编辑器可以浏览补偿草稿，正式运行读取主保存后的快照；未保存的相机绑定或 VPP 参数会阻止正式视觉调用。

其他现有能力同样按所属对象提供：DI 读取 / 稳定等待、DO 设置 / 状态读取、气缸动作与到位、实际设备连接 / 状态 / 支持的原始收发、扫码、气密结果、电阻多通道结果、3D 控制器、Modbus、已实例化 PLC、托盘穴位计算，以及 DataForm 生产记录保存。仪表专有方法由对应类声明，父类只提供通用能力。

流程基础对象保留取值、计算、计数、等待、人工输入、报警和产品周期管理。其他节点的输出选择器按模块 / 节点 / 字段展开；运行批次和产品周期隔离、重复保存保护及本地 CSV 存储继续复用原实现。

## 框架开发者的接入边界

核心契约位于 NPSDK 的 `IFlowObject`、`FlowMethod`、`FlowField` 和 `FlowCall`。

- `GetFlowMethods(includeDraft)` 只读取元数据，禁止连接硬件或执行业务。方法 ID、参数键和输出键保持稳定。
- `FlowMethod` 声明三语标题、类型化输入输出及绑定本实例的 Invoke；可选 ValidateInputs 检查表与点位等组合约束。
- UsesHardware 为 true 的方法必须提供独立的 Simulate；没有模拟实现时明确拒绝模拟，不能落入真实硬件方法。
- `FlowCall` 提供已解析输入、产品上下文与取消信号。阻塞通信尚未返回时保持资源占用，取消后不得发布迟到结果。
- AbstractDevice 和 VisionproInterface 提供虚方法；设备子类扩充自己的声明。既有 SDK 轴与 IO 通过薄适配器使用同一契约，不创建第二份驱动。
- 已注册模块本身或其已有字段实现 IFlowObject 后，可以进入目录。发现对象仅读取字段，不调用任意属性、构造器或未声明的 .NET 方法。DeviceControl、VPForm 等原有对象优先使用原来的稳定身份，避免重复列出共享实例。

新 MES 协议、自定义算法或特殊硬件仍需框架开发者先声明实际可调用的能力，应用工程师随后选择、传参和连接。此版没有伪造通用 MES 上传接口，也没有把整个 Form 的所有公开方法直接暴露为流程指令。

## 保存与旧工程

工程仍保存对象 ID、方法 ID、输入来源、节点布局、出口条件、超时与报警，不序列化实例或委托。MainForm Save 完成校验和写盘后发布运行版本；放弃修改恢复上次保存。

旧工程中的点位目标保留解析能力，避免已有流程直接丢失；新建节点的对象列表不再单独展示点位表。重新编辑时可改为轴对象及其绑定表。VPP 端口或 DataForm 字段改变后，保存 / 启动校验会要求重新确认节点输入，不会猜测补齐缺失字段或选择另一对象。

此版保持原有顺序流程和跨模块结果交换语义，尚未增加多产品自动队列、任意回跳重试或断电后自动续跑。现场硬件与 MES 协议仍需按实际设备联调。
