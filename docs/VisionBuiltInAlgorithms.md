# 新增标定和 VPP 的内置算法

现有相机页入口保持不变。在相机页点击“添加标定”或“添加 VPP”时，当前配方没有对应文件就建立标准算法草稿。已有文件若完全没有工具、端口、脚本、绑定和业务元数据，也会补齐成标准算法草稿；SDK 自带的空 ScriptData 不算业务内容。包含实际内容的 VPP 和正在编辑的草稿保持原样。

已有相机的空标定／VPP 可以直接点击“编辑 TB”补齐，无需删除相机或文件。补齐只更新内存，点击主界面“保存”后才落盘；放弃修改会恢复原空文件。程序启动、配方加载仍只读取算法，不自动替换生产算法。

## 添加标定

点击“添加标定”后，点击“编辑 TB”可以看到以下工具：

- `AcquireImage`：按相机页绑定的 SN 采图，采用本标定的曝光。
- `LocatePattern`：定位标定特征，输出原始图像的 `x/y`。先采图，在该工具中选择训练图像、框选特征并训练，然后即可沿用页面“拍照”和“添加标定点”。
- `Calibration`：N 点坐标标定工具。页面仍通过九组以上像素与机械坐标点执行“应用到本相机”，同时更新内置采点算法及该相机下的目标 VPP。
- `RotationCenter`：固定相机、固定 XY、吸嘴或工件随 R 轴旋转时的中心计算工具。

标定采点算法始终输出原始图像坐标，不会因为已经应用九点标定而将机械坐标再次作为像素采样。

### 旋转中心计算

在 `RotationCenter` 子工具块中，按同一采样顺序填写三个输入数组：

- `PixelX`：每次拍摄同一特征得到的 x。
- `PixelY`：对应的 y。
- `AnglesDegrees`：对应的 R 轴实际角度，单位为度。

至少需要三组有效采样，建议采用覆盖较充分角度范围的多组数据，并保留独立角度检查结果。采样期间相机和 XY 必须保持不动。

单独运行该子工具块，输出 `CenterX/CenterY` 和 `RmsError`，单位均为图像坐标单位（原始相机图像为像素）。算法按实际角度拟合 x/y 的正弦、余弦轨迹，支持仿射成像下的椭圆投影；重复角度、角度覆盖不足、非有限值、点位不动及长度不一致都会明确报错并清空旧结果。

本工具提供旋转中心计算，不执行轴运动，也不把像素中心直接当作机械轴坐标或自动加入运动补偿。机械坐标使用九点转换关系处理，具体吸嘴偏置和目标运动由应用流程决定。超出同一平面与仿射成像条件的装置需要另行验证模型。

## 添加 VPP

点击“添加 VPP”后，自带 `AcquireImage`、`Calibration` 和 `LocatePattern`，脚本已处理采集、定位及结果输出。应用人员只需训练特征，调整匹配分数、搜索区域和角度范围。

默认匹配分数为 0.8，最多寻找一个结果，搜索区域为整张图像。输出包括：

- `Accepted`、`MatchCount`、`Score`：本次匹配判定、数量和分数。
- `x/y/A`：定位位置及角度，A 的单位为度。未标定时 x/y 为原始图像坐标；标定后通过坐标转换输出机械坐标。
- `Calibrated`：是否已经使用有效的坐标标定。
- `OutputImage`：本次输入图像，方便离线检查。

模板始终在原始图像坐标下匹配，然后转换位置与方向，因此应用九点标定后无需重新按机械单位训练模板。失败、未训练或未匹配时不会沿用上一个产品的有效坐标。

相机 SN、曝光和错误语言由所属页面更新。`UseInputImage=true` 时使用 `InputImage` 进行离线调试；自动运行状态拒绝该模式，生产前应取消勾选并保存。创建模板不会连接相机，生成的 VPP 脚本只引用标准 VisionPro 运行库。

流程图调用不需要绑定上述内部采集、语言和离线调试端口。在 TB 中另加的业务输入仍会正常出现在流程节点参数中。

## 保存与配方

新增算法、训练、九点标定和旋转工具输入都留在当前配方的 VPP 草稿中，由主界面“保存”统一提交。编辑窗口确认只保留草稿，配方切换沿用已有的保存／放弃处理。机器级相机配置与标定点仍保存在原有配置位置，不增加配方选择入口。

```powershell
./tests/VisionRuntime/Run.ps1 -AssemblyDirectory '<构建输出目录>' -BuiltInOnly
```

专项回归覆盖生成工具、真实 PMAlign 训练运行、九点坐标转换、旋转中心与退化采样、失败清除旧结果、已有文件保护、序列化与快照隔离，以及实际新增入口产生主保存任务。`-BuiltInOnly` 在独立工作目录中执行，不连接相机或 PLC；完整旧回归仍沿用项目工作目录。实际采集、现场标定精度及运动补偿仍需设备联调。
