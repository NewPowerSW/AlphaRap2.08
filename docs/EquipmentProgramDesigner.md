# 整机自动化工程设计器：框架盘点与产品边界

状态：源码核查与实施设计，尚未实现本文件描述的整机设计器。前两版独立设计器已回滚。本文是后续实施依据；与旧的 FlowChart 提案冲突时，以本文的整机范围及现有页面集成为准。

## 产品目标

应用工程师在 AlphaRap 内配置一台设备：建立资源、创建型号、示教点位、编排工位、绑定数据、配置异常处理，完成本地生产记录后发布运行。以 NPSDK 的 Flow_Chart 和 Flow_BaseForm 为流程入口，将设备已有功能变成可选择、可组合的工程资源。

“少代码”覆盖整台设备的配置过程。已有驱动和动作由框架维护者封装一次，应用工程师反复使用；新厂商驱动、特殊协议、复杂算法仍由软件工程师开发。不能把要求工程师填写 C# 类名、方法名、表达式或数组下标的界面称为无代码设计器。

工程由六部分共同构成：机器资源、型号配方、工位流程、数据定义、运行策略、发布版本。Flow_Chart 是其中的编排入口，其他部分必须一起设计。

## 源码盘点的范围和证据

`diagnostics/inventory_equipment_framework.py` 根据 AlphaRap.csproj 的显式 Compile 项，生成 [资源清单](EquipmentFrameworkInventory.json)。当前静态清单包含 144 个源文件条目、32 个窗体类声明、3 个 Flow_BaseForm、123 个 Flow_Chart、5 种 AbstractDevice 子类、30 个配方/机器表声明、35 个输入、31 个输出、4 个气缸、1 个轴、1 个点位表、6 个 DataForm 数据集合。

这些数量是源码声明数量，包含未在当前启动入口创建的页面，不代表现场连接数或可运行的完整流程数。动态相机/VPP、动态设备实例、动态托盘列需要从加载后的配置目录获取。脚本不加载程序集、不实例化对象、不读取现场账号或连接设备；正则抽取不是 C# 语义分析器。

### 型号、输入与配方

- [ProductManagerForm](../AlphaRap/MenuForm/ProductManagerForm.cs) 的输入绑定到 `RecipeData/ProductSetting`：PRODUCTID、STEPID、RECIPEID、PORTID、SN1KeySub、SN2KeySub，另有两个启用开关。
- 型号文件名 `SysPara.RecipeName`、ProductSetting.RECIPEID 和 PRODUCTID 是不同概念，不能混成同一个“型号”字符串。模型选择器应显示文件型号和业务标识，持久化稳定 ModelId 及字段路径。
- [MiddleLayer.Recipe](../AlphaRap/Core/MiddleLayer.Recipe.cs) 在 IDLE 且视觉不忙时读取各 ModuleBaseForm 的配方，再加载对应型号的 VPP、视觉判据和托盘界面。
- [ModuleBaseForm](../AlphaRapLibrary/ModuleBaseForm.cs) 用窗体 Text/模块名作为 DataTable.Namespace，以表名和列名读写数据；GetRecipeValue 读取 DataRowVersion.Original。设计器须区分“编辑草稿”和“已提交运行值”，不能直接绑定未保存的文本框。
- 新建型号当前复制 XML；其 VPP 循环只生成路径，未执行复制。复制、删除和切换型号都需要资源依赖清单，不能认为复制 XML 就复制了完整工艺。OpenRecipe 也不是覆盖全部模块及 VPP 的原子事务，失败可能留下部分更新。

设计器应提供三类输入界面：工程师定义有类型/单位/范围的参数；操作员在允许的页面输入条码、工单、批次等；流程从 PLC、扫码或其他节点读取输入。三者通过同一个参数来源选择器进入流程。操作员输入应明确提交和取消，等待输入可超时，运行中编辑型号草稿不得影响本轮产品。

### 点位、轴与托盘

- [HardForm.Designer](../AlphaRap/MenuForm/HardForm.Designer.cs) 实际定义 `MTR_H1_X`，源码 Port 为 `0`；轴参数在 SDK 初始化时还会从保存文件加载，不能将源码 Port 当作现场最终轴号。
- `X1_PositionTable1.DataSet = RecipeData`；DataSet1 字段名为 `tb_H1_Srew1Post`，实际表名为 `tb_X1_Post`，列为 double X1 与 string Annotation。
- 该表 WorkMotor 为 null，但 ParameterSet 的 X1 列明确绑定 MTR_H1_X。资源发现必须读取 ParameterSet，不能只检查 WorkMotor，否则会漏掉现有点位。
- SDK `NP_PositionTable.StartBuiltinGoto()` 依赖界面 CurrentRow；表头显示 P1，但 DataRow 索引从 0 开始。需要在 NPSDK 内提供不依赖选中行的“读取点位/启动移动/检查完成/停止”接口。自动流程不得通过改变 UI 选中行或模拟点击来移动。
- [PlatFormSetting](../AlphaRap/MenuForm/PlatFormSetting.cs) 与 [TrayConfig](../AlphaRap/Classes/TrayConfig.cs) 已支持动态托盘。配方 PSet 含行列数、间距、3D 上下限、扭矩/圈数限值、角度加值等；不是一张只有 XY 坐标的点位表。

目标选择过程是“工位/轴 → 当前型号下有关联的点位表 → 点位名称或索引”。提供单轴移动与点位组移动两种明确动作，组移动才执行该行关联的全部轴。界面显示 P1 与内部索引 0 的对应关系；保存 PointId 和显示索引，插入/排序不改变原绑定。旧表没有 PointId 时，迁移先建立映射；动态索引输入则在每次执行前做范围检查，不能将其偷换成固定 PointId。

托盘动作需要“选择托盘 → 当前穴位/行列 → 基准点 → 行列间距与方向 → 计算目标点”。行列数量虽在旧表中采用 double，工程界面须按正整数校验；定义原点、坐标系、遍历顺序、空穴/NG 跳过、换盘复位。视觉偏移作为显式选择的输入参与坐标计算，保留补偿范围及应用记录；不自动把补偿加到所有视觉或运动动作。

### 设备对象与通信

[DeviceControl](../AlphaRap/Controls/DeviceControl.cs) 已有设备类型发现、多个实际实例、参数编辑和 XML 保存。类型清单为 ScannerKeyenceTcp、ATEQ_F620、HIOKI_RM3545、Keyence3DTcp、ModBus_RTU。实例身份应来自资源目录，连接由设备会话复用；浏览动作目录不新建设备、不触发 Open。

还存在 Device 目录外的能力：[Gantry](../AlphaRap/TaskProcess/Gantry.cs) 的 INOVANCE PLC、MiddleLayer 的 Atlas 对象，以及 Classes 中 FFU、MTF6000 等封装。它们是待适配资源候选，不意味着每个类都已在当前设备上启用。只扫描 AbstractDevice 会漏掉这部分功能。

动作目录按“功能 → 已配置实例 → 动作”组织，方法签名放在高级说明中。例如扫码一次、读取气密结果、读取电阻结果、3D 触发/切程序、PLC 读写。HIOKI 的 ref 参数应映射为具名结果，Modbus 字节数组提供协议解析动作；事件回调不出现在普通动作菜单。设备异步事件必须携带会话/请求标识，防止上一条消息被当成本次结果。

### IO、气缸、手动页与常驻逻辑

[ManualForm](../AlphaRap/MenuForm/ManualForm.cs) 组合 DI、DO、气缸、输送线和 SMEMA。SDK 气缸 On/Off 的 bool 是本次到位检查结果；Flow_Chart 的 IDLE 会再次调用回调。这类动作需要“发出一次 → 等待到位”，不能简单将 false 当作故障，也不能把每次轮询都当作新动作。

IO 读取与等待分开；等待可选电平、进入节点后的边沿、稳定保持时间、超时。PLC 地址通过资源标签定义类型、长度、字节序、有效期；通信失败与合法值 0 必须区分。

手动测试、流程单步、自动运行使用同一资源和动作实现，统一资源占用与前置条件。现有 IO 刷新和电机保护由 [FlowControl](../AlphaRap/Controls/FlowControl.cs) 周期执行，不能挂在某个容易暂停的业务节点下。门、急停、复位等应进入设备状态与硬件互锁约束，业务流程只引用其许可状态。

### 视觉、判据与标定

[VPForm](../AlphaRap/MenuForm/VPForm.cs) 管理机器级相机/VPP 配置及按型号保存的 VPP 文件；已有 GetVppStation 和 GetCompensationTable。VPP 本身有稳定 Id，可作为目录主键。标定点与应用状态又有独立配置，切换型号不能假定标定自然有效。

视觉节点应选择真实相机、真实 VPP 和已登记动作，列出实际 ToolBlock 输出名称/类型，支持图像引用、数值、文本、集合等。保留现有 [VisionproInterface](../AlphaRap/Vision/VisionproInterface.cs) 的 RunId 与 Busy 生命周期，等待同一请求的完成结果；显示失败、判定 NG、超时和取消的不同含义。图像采用受控引用与保存路径，避免把整幅图像重复复制到每个节点上下文。

### 数据保存、查询、上传及其他页面

- [DataForm](../AlphaRap/MenuForm/DataForm.cs) 已有 MESLOG、Alarm、LogRun、LogError、UserLogin、UserOperationLog 六个集合；SDK TypeCollection1 通过 Items 和位置数组保存，尚无类型化的生产表字段映射。
- [HomeForm](../AlphaRap/MenuForm/HomeForm.cs) 的生产信息通过 ProductionDataStore 另行保存，ProductionQueryForm 查询同一路径。必须把它们接到 DataForm 的生产表目录，保留现有查询与历史兼容，不再另加一套孤立 CSV 节点。
- [ProductionDataStore](../AlphaRap/Classes/ProductionDataStore.cs) 当天新增列会被旧文件表头丢弃，当前主页也先显示再保存。允许工程师配置字段之前，需要解决列版本、并发写入、显式保存结果和重复提交。
- [CheckForm](../AlphaRap/MenuForm/CheckForm.cs) 有六种设备状态的灯塔/蜂鸣器规则及维护模式配置；工程师应选择状态规则，不必为每条流程重复拼灯光输出。
- 生命周期维护页、权限/登录、操作日志、报警设置、语言设置、数据查询都应列入整机工程。它们有些属于全局服务/运维配置，不需要强行都变成串行流程节点。
- MES 作为可选上传能力，协议由适配器接入；本方案不受当前 MES 页布局约束。本地生产数据保存成功是基础验收，上传可在后续迭代实现。

## 统一的工程结构

设备工程包含以下内容，工程师在一个工程树中管理：

1. 机器资源：控制器、轴/轴组、DI/DO、气缸、输送线、相机、设备实例、通信标签；可复用资源模板。
2. 型号配方：型号身份、产品/工艺参数、点位表、托盘、视觉程序及判据、字段有效范围；支持复制及差异查看。
3. 工位与流程：现有 Gantry、UpConveryor、DownConveryor 对应的 Flow_BaseForm；初始化、自动、停止清理、异常恢复、手动测试等入口显式配置。
4. 数据中心：参数定义、节点输出、产品记录结构、DataForm 表结构、保存位置、查询与保留策略。
5. 设备策略：运行模式、资源互斥、互锁许可、报警、权限、灯塔、模拟输入。
6. 调试与发布：引用校验、模拟执行、单步/断点、等待原因、版本、备份/恢复和运行记录。

型号共用工艺主流程，通过配方参数改变点位、判据和启用功能。工艺拓扑确有区别时，显式配置型号的子流程版本；不为每个型号复制一整套独立图。流程引用“当前型号/工位/表/字段”，开始一轮时解析成已发布配方快照。

## 双击节点时应完成什么

一个有层次的属性窗口，固定布局维护在 Designer.cs/resx，复用可预览 UserControl：

1. 选择动作类别和实际对象。仅列出该对象支持的动作；显示对象未配置、连接状态及被谁占用。
2. 为每个输入选择来源：常量、当前型号字段、机器参数、操作员输入、当前产品、点位/托盘、IO/PLC 采样、流程节点输出、子流程入参。枚举、时间、数量、坐标、表行和资源各用适合的编辑器。
3. 展示具名输出及类型。工程师通过“工位 → 流程 → 节点 → 输出字段”选择，连线表示控制顺序，数据引用明确显示依赖。
4. 配置条件：左值来源、比较符、右值来源；支持 AND/OR 分组、范围、集合项、文本匹配。固定类型不兼容时立即提示，不要求填写脚本。
5. 配置成功、NG、故障、超时、取消的出口。条件不满足可继续等待直到超时；“判定一次”和“持续等待”分别选择。为多条件定义匹配顺序、默认分支和无匹配行为。
6. 选择报警表条目、有限重试、间隔、报警后的处理及恢复入口。绑定 NPSDK.Alarm.Show 通过框架适配层完成；重试必须符合动作性质，防止重复运动、重复扫码命令和重复保存。

普通工程师看到工艺名称、来源、单位、示例说明和问题定位；高级查看可见实际资源 ID、参数路径和方法签名。新功能封装一次即可出现在目录，无需为每个 Flow 写回调。

## 贯穿整台设备的数据与运行语义

### 节点间传递

输出保存为本次执行的不可变结果快照，至少标注工程/流程版本、RecipeVersion、CycleId、NodeId、ExecutionId、循环次数、状态、时间和类型。正常输入选择器可以查看其他 Flow 的输出，但可读取不等于已经有效。

- 同一路径已完成的节点，直接读取本周期结果。
- 未经过的条件分支没有结果，显示原因；发布时要求补默认值、选择结果合并节点或调整连线。
- 并行分支/不同工位，用显式等待/消息/队列/汇合交接，并按产品/托盘/穴位相关 ID 匹配，支持超时及停止取消。
- 循环每次有独立执行标识；不默认读取“最后一次”，需要最新值时由工程师明确选择窗口和有效期。
- 全局共享状态只用于明确的设备级信号；产品测量结果不可放入无周期隔离的全局字典。

多穴托盘和多产品同时在设备上流转时，设备运行实例、产品 CycleId、托盘 ID、穴位号各自独立；一次初始化不是一个产品周期，一轮托盘循环也不等于一个产品。

### 动作、资源与状态

在 NPSDK 内重构 Flow_Chart 的执行职责，Flow_BaseForm 保留工位入口和兼容接口，Flow_Chart 显示同一流程模型的状态；设计与运行不能使用两份配置模型。建立每工位受管理的执行会话，替代节点各建线程、UI 跨线程读写和全局可变结果。

动作有明确的开始、运行中、完成、故障和停止确认；开始只发一次。资源管理器控制轴/轴组、相机/采集、通信设备的占用，给定锁顺序，等待可取消。相机共用采集器及同一设备不同方法也可能争用资源。请求取消后未确认底层已结束前，不释放占用、不启动下一条动作。

保留 MiddleLayer 的启动/暂停/停止/初始化路由，明确接管现有 3 个 Flow_BaseForm。Up/Down 当前的 Initial 和 StartRun 为空，不能假定图上已有节点就会自动启动；迁移必须选定入口并测试。停止清理、手动取消、输送线恢复快照、报警策略都须纳入同一状态机。常驻 IO 刷新和保护独立运行。

### 本地保存

工程师在 DataForm 选择或定义生产表，设置具名字段类型、单位、必填项和来源；输出字段无需依赖 string[] 顺序。统一保存适配层连接现有存储与查询，生产记录至少包含 RecordId、CycleId、型号/配方/流程版本、产品码、结果、测量值和时间。

节点返回“已保存”的前提是本地持久化成功，返回 RecordId、路径/表及保存时间。失败走明确异常出口，不能继续显示为已保存。并发写入串行化；字段增加产生 schema 版本，禁止静默丢列。重试按 RecordId 去重。CSV 可作为兼容/导出格式；如果需要断电恢复和补传队列，优先在同一数据服务下增加事务存储，避免在各个节点自行拼文件。

上传绑定同一条已保存记录。未知回执、业务拒绝、传输失败分开；补传保留关联 ID。当前阶段以本地闭环为必需，上传作为扩展，不阻塞本地数据设计。

## 设计保存、重新加载与型号切换

工程草稿、发布包和生产运行数据分开保存：

- 工程草稿保存节点位置/尺寸、连线、工位入口、动作版本、资源绑定、输入引用、输出定义、条件、超时、报警、子流程、数据表映射、当前编辑状态；用 schemaVersion 标记格式。
- 发布包固定工程版本、兼容的 SDK/动作版本、机器资源配置版本、型号配方及点位/VPP 依赖清单。保存先写临时文件并验证，再替换；跨文件按 manifest 提交，保留上版可恢复。
- 程序重启先加载配置和资源描述，再解析引用、校验、恢复设计画布。缺对象、缺 VPP、点位删除、字段改类型都定位到具体节点，阻止发布/启动；不静默降级为 0 或任意默认对象。
- 重启恢复设计和追溯记录，不自动恢复中断的物理运动。恢复动作从设备状态检查、重新初始化或明确恢复入口进入。
- 型号切换先验证目标型号所有参数、点位、托盘、VPP 和表结构引用，成功才整体提交并刷新界面；失败保持原有效快照。运行/停止未结束时不切换。
- 引用使用稳定 ID 和 schema 路径，显示名称可改；旧控件 Name、表名和列名作为兼容映射。用户名称和业务键不翻译；界面文案遵守 [语言机制](Localization.md)。

## 实施边界与优先级

### P0：先形成一个真实、可验收的整机闭环

1. 资源目录从既有页面/配置读取：型号参数、轴点位、托盘、IO/气缸、实际 Device 实例、相机/VPP、DataForm 表；先读配置，不连硬件。
2. NPSDK 内建立流程定义、类型化绑定、执行会话和资源占用；原 3 个 Flow_BaseForm 都能显示/编辑同一设计模型，旧业务回调逐节点分类迁移。
3. 双击 Flow_Chart 完成选择资源/动作、数据来源、条件、超时和报警；实现点位和型号参数选择器。
4. 完成“当前型号 → 操作员/到位输入 → 扫码 → 点位移动 → 视觉/测试 → 判定 → DataForm 本地保存”的一条实链；需要新建的生产表明确为工程定义，不伪称现有现场表。
5. 保存后关闭、重启、加载，相同设计及绑定恢复；切换另一型号读取各自点位/判据；缺失引用明确报错。

### P1：减少重复工程劳动
