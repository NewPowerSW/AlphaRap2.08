# 按产品 SN 保存 VPP 照片

## 拖拽流程

1. 在视觉页选定相机与 VPP，勾选“存图”，勾选“原图”或“截图”，填写“存图路径”。
2. 在流程的“拍照并运行当前 VPP”节点，将“产品 SN”绑定到当前产品记录的 SN，或与该产品对应的扫码节点输出。转盘上有多个产品时，使用当前载具/穴位的产品记录，不使用后来被下一件覆盖的全局条码。
3. 选择“照片格式”：BMP 或 JPG。
4. 点击主界面“保存”，保存 VPP 设置及流程绑定。
5. 执行拍照节点，判定完成后自动按该 VPP 已保存的设置存图。OK/NG 都保留本次 SN；节点输出“本次产品 SN”和“照片文件路径”，可以绑定到生产表或日志模块。

示例：`D:\VisionImages\TakePCBA\SN001_20261029_223015_1234567.jpg`。
时间为触发拍照的本地时间。JPG 使用真正 JPEG 编码；不是只修改扩展名。

## 目录与兼容

- “存图路径”留空时，使用当前配方 VPP 文件所在目录下的 `Images`。
- 只保存原图或截图时，直接写入配置目录；两者都保存时，分别写入该目录下的 `Original` 和 `Snapshot`，文件名都保持 `SN_时间.扩展名`。
- SN 在触发时固定到运行编号上。后续扫码、配方界面文字或其他节点不会修改该次 SN；旧运行编号也不能保存下一次照片。
- SN 中 Windows 文件名不允许的字符仅在文件名中替换为下划线，节点输出的产品 SN 保持原始业务值（去除首尾空白）。
- 旧流程未配置 SN、格式时，默认时间命名和 BMP，不需要删除重建节点。主保存及重新加载保持原有绑定。
- 已有的显式存图节点可以继续使用；同一拍照结果返回已保存路径，不重复写文件。
- 同名文件不覆盖。两类照片同时保存失败时，撤回本次已写出的部分照片，保留重试机会。
- 自动删除按 VPP 的保留天数清理 BMP/JPG/JPEG；模拟运行不保存实体照片。

## 代码调用

```csharp
bool CaptureProduct(VpStation station, string productSN)
{
    return station.RunAndWait(10000, productSN, "jpg");
}
```

调用方传入当前产品的 SN。异步调用可使用 `station.TryRunTB(out runId, productSN, "jpg")`，完成后调用 `station.SaveLastImage(runId)`，由接口检查同一运行编号；同步 `RunAndWait` 已按启用的 VPP 设置自动保存。照片路径可通过 `station.LastRunResult.ImagePath` 获取。
