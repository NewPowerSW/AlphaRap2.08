# FlowChat 模块工具箱与代码节点实施计划

实施计划与交付记录 · 2026-10-25。第一版已实现工具箱、编译代码模块、实际资源绑定和主 Save 生成源码。使用入口、实际接口和验证边界以 [工具箱使用说明](FlowToolboxUsage.md) 为准；下文保留分阶段设计及验收目标。

核查基线：AlphaRap `19fbf37`；发布核心 NPSDK `4e21ed45`，来源及校验见 [SDK 引用说明](../SDK/README.md)。本文提到的新类名和接口为建议名称，以实现阶段的最小设计为准。

## 1. 目标与第一版交付

应用工程师在现有流程页面，从分组工具箱拖入功能模块，绑定现有轴、IO、设备、VPP、参数和节点数据，连线后运行。软件工程师可以继承轻量业务节点基类，按原 FlowChat 的返回值习惯编写可复用模块；模块编译并登记后进入工具箱。

第一版交付一个完整闭环：**动态资源配置 → 工具箱拖入节点 → 绑定真实对象与输入输出 → 混合运行 → 主 Save → 重新加载**。画布仍使用 NPSDK `Flow_Chart`，所有 `Flow_BaseForm` 派生窗体共用入口；代码模块通过现有 Action 调用路径接入同一运行器。

已有配置节点和脚本节点继续工作。常规操作逐步以工具箱为入口，脚本保留给高级计算。新设备协议或新工艺能力仍由开发人员封装一次，新增同类轴、IO、VPP 实例只修改绑定。

## 2. 应用工程师看到的操作

1. 沿用轴、IO、视觉、Device 等原页面建立实际对象，使用 ProductManagerForm 管理配方。
2. 在流程页面左侧工具箱展开“运动、IO、视觉、设备、数据、自定义工艺”，拖入具体动作，例如“移动到点位”或“点胶检测”。
3. 双击节点，在同一窗口配置业务参数、实际资源、输入输出来源、出口去向和运行设置。拖入时已确定动作，不重复进行多层功能选择。
4. 使用现有 MainForm Save 保存，通过原初始化、启动、停止及节点调试入口运行。

“点胶检测”示例模块的配置项：运动轴、该轴绑定表中的目标点位、点胶阀输出、到位输入、检测 VPP、VPP 高度输出、合格范围、NEXT/CASE 去向。模块自己的输入可以绑定 Setting、Recipe、固定值或其他节点输出。

工具箱仅分“功能组 → 具体动作”两层。代码节点的普通属性界面以绑定和参数为主；模块源码由开发人员在项目中维护，应用工程师无需编辑源码或重新定义端口。

## 3. 保持一致的设计约定

- **一个运行器**：配置节点、代码节点和脚本节点使用现有运行会话、数据隔离、报警和调试机制。
- **一个对象来源**：轴、IO、设备和 VPP 由原页面或外部应用创建，模块通过已登记的稳定资源身份访问它们。
- **一个出口决策来源**：代码模块返回 NEXT/CASE 时，界面只配置去向；普通配置节点继续使用条件判定。超时与异常统一报警，不自动作为业务 CASE。
- **独立节点状态**：模块类型定义可复用；每个节点的执行状态、计时和输出独立，每次进入重新初始化。
- **沿用作用域**：流程定义与资源绑定继续属于机器 Setting；点位、Recipe 常量及 VPP 算法跟随当前配方。不同工艺图随配方切换属于后续单独设计。
- **统一保存**：节点确定只提交草稿，MainForm Save 负责校验、文件提交和发布；放弃修改及失败回滚覆盖新绑定。
- **统一语言与布局**：界面提供中文、英文、西班牙文，用户名称、业务键及代码保持原值；固定布局进入 Designer/resx，实际验证 VS 设计器和 EXE。

## 4. 已有基础及明确缺口

可直接复用的基础：

- NPSDK `IFlowObject / FlowMethod / FlowField / FlowCall`：对象方法、类型化输入输出、三语标题、校验、模拟与取消上下文。
- [FlowResources](../AlphaRap/FlowProgramming/FlowResources.cs)：收集已有对象；动态轴/IO 使用资源 ID，轴带自己的 BoundPoints。
- [VPForm.GetFlowStations](../AlphaRap/MenuForm/VPForm.cs)：按 VPP 稳定 ID 枚举当前实例。
- [FlowActions](../AlphaRap/FlowProgramming/FlowActions.cs)：方法解析、输入输出检查及脚本内部受控调用。
- [FlowPrograms](../AlphaRap/FlowProgramming/FlowPrograms.cs)：所有 Flow_BaseForm 的控制器、运行前资源快照、节点创建、连接和草稿。
- [ProjectConfiguration](../AlphaRap/Configuration/ProjectConfiguration.cs)：主保存事务、发布及放弃修改。

本次需要补齐的缺口：

- 当前没有分组工具箱的拖放创建，已有拖动主要用于移动已存在节点。
- 当前对象发现面向已创建实例，没有代码模块类型目录和按节点创建执行实例的工厂。
- 受控内部调用目前主要面向脚本，缺少给代码模块使用的类型化资源接口。
- 尚无“模块业务字段 → 所选 VPP 实际端口”的持久映射。
- 硬件删除已有引用检查；VPP 删除及新模块内部资源依赖需要统一纳入检查。
- 原 FlowChartRun 回调不能直接与 Program 节点逐节点混跑，需要适配其等待和出口语义。

## 5. 分阶段实施

### 阶段 1：固定代码模块契约

交付：开发人员可以用一个小类声明模块及其业务逻辑。

拟修改内容：

- 在 NPSDK 增加轻量 `FlowCodeNode<TInputs,TOutputs>`，复用已有方法契约，隐藏字典转换和调用样板。
- 声明稳定 ModuleId、契约版本、分组、三语标题、明确的输入输出和资源角色。
- 首版参数面板支持文本、布尔、整数、数值、枚举及明确的资源/点位引用；图像沿用受控引用。复杂集合或自定义对象需要显式转换与编辑支持，不假定任意 C# 类型都能自动生成界面。
- 保留 `IDLE / NEXT / CASE1～3 / End` 的使用习惯，提供一次进入、等待检查及取消收尾的明确边界；整机初始化与节点进入分别处理。
- 模块目录保存定义和工厂，浏览时只读取元数据，运行时才建立独立节点执行实例。首版模块随项目编译发布，外部模块程序集在启动时明确登记。
- 宿主限定项目程序集和已登记扩展程序集的发现范围，自动发现继承基类并声明有效元数据的具体模块类型，扫描一次后缓存。开发者无需逐个手写工具箱条目，发现过程不调用模块构造函数。

验收：同一模块创建两个节点，状态和输出互不串用；模块发现不创建硬件或执行动作；纯计算模块能声明输入输出并通过类型校验。

### 阶段 2：完成动态资源绑定与访问

交付：代码模块可以复用页面动态创建和外部应用登记的实际对象。

拟修改内容：

- 模块声明资源角色，例如“取料轴、到位输入、点胶阀、检测视觉”。节点保存角色到资源 ID 的绑定，界面按能力过滤候选。
- 增加小型外部资源登记接口：宿主提供稳定 ID、所需能力和当前实例解析方式；浏览不连接硬件，注销或重建时使旧绑定句柄失效。
- 将脚本内部调用收敛成公共受控入口，为模块提供易读的轴、输入、输出、视觉接口；默认逐次通过同一调用入口获取真实硬件占用。
- 启动前解析当前实例并固定本次运行的资源与配方上下文；停机、更换资源或配方切换后，下次运行重新解析，模块不跨运行缓存 Control、ToolBlock 或端口对象。
- 轴点位只访问其绑定表。首版保留原 Index 语义并明确显示“按索引”；为点位表补充结构变更通知和配方作用域内的结构修订记录，插入、删除、重排后标记受影响绑定需重新确认。主保存和启动均阻止未确认绑定；动态 Index 无法精确分析时按整表保守处理。固定 PointId 及旧表迁移另行设计，避免悄悄改变现有索引含义。
- 在节点内保存 VPP 业务字段映射，例如“检测高度 → TB:MeasuredHeight”，包含类型约束；换配方后重新校验。视觉结果关联本次请求，不读取未经校验的最新结果。
- 将代码模块的全部资源依赖和 VPP/相机引用纳入统一删除反查，包含草稿节点；缺失资源保留绑定并说明修复位置。

验收：新增同类轴、IO、VPP 后不修改模块 DLL 即可选择；改名、放弃修改重建实例、退出重启后仍正确绑定；输入不能绑定输出、点位不能绑定别的轴；点位增删重排后未确认的绑定不能保存或启动，确认状态可持久化并按配方核对；VPP 缺端口或端口类型变化时定位具体节点；引用中的资源不能被删除。

### 阶段 3：接入现有运行器与返回值适配

交付：代码节点、配置节点和脚本节点能在同一流程内执行。

拟修改内容：

- 代码模块适配成现有 Action，调用管线沿用输入校验、资源调用、输出校验和结果发布。
- 既有 Legacy/Program/Disabled 模式保持；原 FlowChartRun 事件回调按受控资源与状态规则逐步迁移，不宣称未经审查即可自动转成新代码模块。
- `IDLE` 由适配器进行可取消等待；一次进入只发一次动作，轮询只检查完成状态。旧回调迁移时逐个检查副作用，不能直接包装一个会重复点胶的回调。
- 当前 Action 返回字典，之后会进入出口条件等待，因此增加可选的“输出＋最终出口”适配结果/执行接点，同时保留原 Action 调用接口。代码节点直接采用最终 NEXT/CASE 并跳过外层条件轮询，界面只编辑去向。默认模板只有 NEXT，其他出口由模块声明并明确配置；可能返回而未配置的出口在保存/启动校验时报错，显式选择结束仍有效。
- `End` 在发布本节点最终输出后直接结束当前流程，绕过普通 NEXT/CASE 目标查找，不隐式结束整台设备。
- 暂停首版沿用当前运行器的节点边界语义：阻止后续节点进入，已经启动的动作及其 IDLE 检查继续，动作和条件等待的超时继续计时；节点执行前的调试暂停不计动作超时。恢复不重发进入动作。需要动作内部暂停或暂停停止计时的模块，在补充明确的设备/运行器契约后开放。
- 停止、超时与报警继续统一处理。超时不跳 CASE；取消后等待实际动作结束，再释放资源；拒绝迟到输出。代码模块必须遵守受控调用和协作取消契约，任意 C# 或外部设备无法被框架强制安全终止。无法确认动作结束时保留占用、阻止重新启动并给出诊断，超时不等于物理设备已停止。
- 现有资源门不可重入，首版代码模块外层不额外重复获取硬件锁。需要连续独占一组资源时，预先声明整组、按一致顺序一次获取、内部调用复用租约；该组合策略单独验证后开放。

验收：等待期间不重复发送运动、扫码或点胶命令；两节点争用同一轴/相机可正确等待和取消；内部调用不把自己锁死；代码 CASE 不被 NEXT 无条件出口或其他界面条件覆盖，End 发布输出后结束当前流程；暂停阻止后续节点且当前动作超时按既有规则计时，恢复不重发；取消未完成时不能抢占资源或重新启动；旧节点与脚本回归通过。

### 阶段 4：工具箱与节点编辑体验

交付：应用工程师能够直接拖入模块并完成配置。

拟修改内容：

- 流程页面增加可搜索的分组工具箱，列出内置动作和已登记代码模块；分类与描述使用现有语言机制。
- 拖放到当前 Flow_BaseForm 的有效画布，正确处理容器、滚动、坐标、节点身份和删除菜单。复用现有节点创建与连线显示。
- 双击使用现有节点窗口，先显示业务参数与资源绑定，再显示输入输出、下一步、超时调试；高级元数据按需展开。
- 模块缺失、版本不匹配或资源不可用时显示具体原因，保留原值，不自动改成第一个候选。
- 源码由开发人员在项目中维护；可提供源码位置说明，普通应用流程不要求编译脚本或维护端口表。

验收：在既有和新建 Flow_BaseForm 中都能拖入、绑定、连线、右键删除；中文、英文、西班牙文切换不丢草稿；VS 设计器实际重开及 EXE 布局检查通过。

### 阶段 5：保存、迁移和配方一致性

交付：工具箱生成的流程可可靠保存和恢复，旧工程仍可使用。

拟修改内容：

- FlowStep 增加可选代码模块定义、契约版本、资源角色绑定及 VPP 字段映射；配置中不保存实例、委托、线程或运行计时状态。
- 新工程格式升级为版本 3，新程序读取旧版本 1/2 并保留原语义；仅在主保存成功时迁移。当前旧程序拒绝不支持版本，利用版本门禁防止未知字段被旧版回存丢失。
- 新字段同时进入保存、加载、Snapshot、草稿克隆、发布和放弃路径。模块缺失或契约升级不兼容时保留占位和绑定，禁止相关流程启动。
- 继续使用 MainForm Save 的统一提交和回滚；不另设工具箱保存入口。模块程序集发布由开发流程负责，主 Save 只保存工程配置。
- ProductManagerForm 切换后重新检查点位、Recipe 输入和 VPP 字段；Setting 保持独立。切换中断或校验失败时禁止带不完整资源启动，不将当前配方流程改成另一套独立目录。

验收：旧文件运行语义保持；新文件关闭重启后布局、模块、绑定、出口一致；取消、写入失败、晚阶段替换失败不误报保存；放弃能恢复完整配置；缺 DLL/契约版本不符有明确诊断；旧程序不能回存新格式。

### 阶段 6：示例、调试与交付

交付：可演示、可调试、可按说明重复完成的混合流程。

示例链路：读取输入 → 移动到轴绑定点位 → 执行已绑定 VPP → 代码重量/高度判定 → NEXT/CASE → DataForm 本地保存。示例对象由测试配置创建，用户选择自己的实际资源，不自动占用现场通道。

拟修改内容：

- 提供一个纯计算代码模块和一个包含轴、输入、VPP 绑定的示例模块，证明开发和应用两端的完整流程。
- 复用节点执行前断点、单步、继续和输入输出快照；源码行级调试使用匹配 DLL/PDB 和 Visual Studio。节点暂停不宣称为内置 C# 行级调试器。
- 编写模块开发说明、应用工程师操作说明和常见绑定错误修复说明。
- 完成回归、隔离模拟和实际设计器验证后，再进行已确认工况的现场动作验收。

验收：应用工程师按说明完成拖拽、绑定、保存、重新加载、模拟运行及数据核对，常规操作不编辑 C#；同模块重复使用输出独立；真实设备结果与模拟验证分别记录。

## 7. 必须通过的评审与验收门槛

- 阶段 1～3 先用自动测试证明代码节点契约、资源绑定和运行语义，之后进入工具箱界面开发。
- SDK 与宿主继续使用同一发布核心 DLL；保留当前 .NET Framework 目标和已有驱动接口。
- 每次新增端口、绑定或序列化字段都覆盖保存、加载、草稿、取消和失败回滚。
- 复用现有流程、视觉、三语、配方、启动、统一保存和设计器检查，新增模块发现、状态隔离、动态资源重建、锁竞争和格式迁移用例。
- 实际重开 VS 设计器；实际查看 EXE 工具箱与节点窗口。离屏渲染探针与源码扫描只作为补充证据。
- 每阶段形成独立、可回退的源码提交；修改 SDK 时先提交 SDK 源码，再发布固定 DLL 和宿主提交。推送后核对远端并说明验证结果。
- 回退保留“程序＋核心 DLL＋配置备份”的匹配版本；新格式工程恢复原备份后再交给旧程序，不只替换单个 DLL。

## 8. 可行性判断与边界

可行性较高：对象方法契约、动态资源目录、运行器、主保存和三语机制已存在。工具箱只是新的使用入口，主要工程量在代码模块开发契约、资源生命周期及旧返回值适配。

较早验证的风险是：IDLE 导致动作重复触发、组合资源重复加锁、VPP 切配方后端口改变、点位索引重排、旧格式回存丢字段。将这些放在前置阶段验证，避免先完成界面才发现运行规则不成立。

第一版聚焦已部署模块的发现与混合流程闭环。DLL 运行中热替换、任意方法自动开放、整套脚本 IDE、复杂并行调度，需在基本闭环验证后单独评估。

转盘上的多产品跟随、断电恢复、装盘归档及可靠 MES 补传仍需要产品数据服务。工具箱将来可以提供这些服务的节点，但不能把工具箱完成等同于这些业务已实现；本期本地保存复用 DataForm。

## 9. 第一版的实际交付

代码模块基类、typed 轴/IO/VPP 访问、V3 工程模型和最终出口接口已进入 NPSDK。AlphaRap 工具箱同时列出实际对象已声明的动作和已部署代码模块，所有 Flow_BaseForm 共用拖放入口。

本工程提供“重量判定”和“到位后视觉测高”模块。后者将资源角色绑定到实际轴、产品到位输入和 VPP，高度端口显式映射，目标点位根据 ResourceSlot 元数据只列所属轴表。代码出口只配置去向，不再套外层条件。

主 Save 从同一完整快照保存 XML、生成所属 Form 的 `.Flow.g.cs` 和所有权清单；已删除节点不再生成方法、参数或连接。静态 Form 生成 partial 定义，动态通用页生成关联的独立定义类。手写代码保留，外部手改冲突时拒绝覆盖，晚阶段失败回滚整个事务。

生成文件提供可编译的流程定义，正常加载仍以 XML 为准，调度继续使用原运行器。保存配置不等于编译 EXE；模块实现修改需编译部署，没有增加运行时 DLL 热替换。

点位保护采用按配方的内容签名，没有改动 NP_PositionTable 的底层通知机制。点位数值、注释或行序改变后需要打开节点确认并主 Save。这比只检测行结构更保守；后续若引入稳定 PointId，可进一步减少重确认。

自动回归已覆盖工具箱、混合运行、实际对象租约、取消收拢、三语草稿、配方和保存，以及源码编译往返、删除、失败回滚和手改保护。现场硬件动作和 Visual Studio 交互式重开全部设计器仍需在设备环境验收，不能用探针通过代替。
