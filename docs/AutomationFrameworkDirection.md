# AlphaRap 自动化框架的目标与简化建议

评审日期：2026-10-23；功能状态更新：2026-10-24。依据 AlphaRap 代码、NPSDK FlowChart 核心实现和连续需求，重点复核资源配置、节点编辑、执行、数据流转、配方及保存。本文件记录产品方向和实施边界：P0 参数与绑定交互已落地，随后补充了小段脚本与节点调试；完整工艺复用和产品调度仍待后续实现。外部 NPSDK 运动控件目录存在其他未提交修改，不能把那些源码变更等同于宿主已交付 DLL 的能力。

## 产品定位

目标是给应用工程师使用的设备工艺搭建平台。框架开发者先把驱动、通信协议和常用工艺动作接好；应用工程师配置现场对象、配方与点位，然后用 NPSDK FlowChat 拖拽编排整机流程。运行、调试、报警、数据传递和本地记录保存由同一框架承接。

工程师日常应只需要理解三件事：设备上有什么对象、这一步要做什么、完成后往哪里走。其交付物应是可保存和重载的设备工程，无需为每台设备重复编写扫码、等待、搬运、检测和保存代码。新设备协议及特殊算法仍由框架开发者提供一次经过验证的能力，不能承诺任意未知设备都自动实现零代码。

前一阶段把“对象方法可以被选择”推进得较快，大量沿用通用参数表和运行器术语。本阶段先改为业务参数行和统一数据绑定，减少填写内部字段的操作；产品周期、循环、完整工艺复用和调试解释仍需继续收敛。

必须保留的约束：

- NPSDK Flow_Chart / Flow_BaseForm 继续作为流程核心，所有派生窗体适用，不限定工位数量。
- 轴、IO、Device、相机/VPP、托盘和 DataForm 使用页面上已经配置的同一实际对象，不为流程再创建一套对象或驱动连接。
- 轴只访问自身绑定表；VPP 只来自 VPForm 的真实配置；设备只展示自己已声明且实际支持的能力。
- ProductManagerForm 是配方唯一入口；Setting 独立；配置文件统一由 MainForm Save 保存。生产记录在运行中由 DataForm 保存，二者用途不同。
- 三语标题与内部业务键分离，语言切换保留编辑值；组合控件固定布局可在 WinForms 设计器预览。
- NEXT / CASE1 / CASE2 / CASE3 沿用原生出口，每条独立判断；默认仅 NEXT，额外 CASE 手动添加，超时独立报警。

## 已完成的 P0 交互

- 参数按业务含义显示，文字 / 数值直接输入，布尔值选是 / 否，轴点位与表中参数直接选择。字段仍由实际对象声明，不增加一套动作实现。
- 每行使用一个【绑定数据】入口，在同一窗口搜索固定值、机器设置、当前配方和节点结果，并按目标字段类型筛选。失效旧选项或引用保留供修正，不自动选第一项。
- 轴移动默认只显示目标点位，偏移和到位误差按【显示高级参数】展开；旧非默认高级值或已有绑定会自动显示。语言切换保留草稿，取消不修改原节点。
- 视觉存图和读取输出选择同一 VPP 的【来源拍照节点】，框架绑定其执行结果编号；普通条件显示业务结果名，内部运行编号默认收起。

这些改动使用原有对象、方法、输入来源和运行校验，保留主 Save、ProductManagerForm 配方切换及执行周期规则。

## 已补充的小段脚本与节点调试

节点目前可选【现有功能】【自定义 C#】【仅判断条件】。常用工艺继续选择实际对象的方法，特殊计算才使用同一窗口内的小段 C# 5；输入 / 输出通过具名类型端口绑定。脚本可从目录插入真实对象调用，受控调用沿用原有校验、模拟、取消和占用，节点会等待全部已登记调用完成。

同一运行器已支持入口停驻、工程节点断点、单步执行节点、继续到下一断点及输入 / 输出 / 出口观察。入口仍是主界面原有初始化和启动按钮；不再增加另一套启动流程。VS 的行断点与 F10 / F11 用于脚本内部语句，和节点调试各自独立。

脚本及节点断点由 Main Save 保存；脚本属于机器级工程，配方差异使用 Recipe 输入绑定。普通 C# 仍是同进程代码，不是安全沙箱；取消不能强制终止不合作的代码或硬件。使用方式和具体边界见[脚本与调试说明](FlowScripts.md)。这些功能不代表产品与循环分离、重试、子流程、“本件记录”或多产品调度已经实现。

## 复杂性的来源与后续差距

### 1. 参数描述面向代码，编辑器只能照着字段显示

原 FlowField 主要是 Name、Type、DefaultValue 和 Options，通用表格直接把 Index、Offset、Tolerance、Value、Int32、Double 暴露给工程师。当前已增加三语 DisplayName / Help、明确单位 Unit、高级标记和来源节点约束；节点使用可在设计器预览的业务参数行，内部类型继续用于校验。

实现：[FlowNodeForm.cs](../AlphaRap/FlowProgramming/FlowNodeForm.cs)、[FlowInputRow.cs](../AlphaRap/FlowProgramming/FlowInputRow.cs)、[对象接入契约](FlowObjectMethods.md#框架开发者的接入边界)。

已保留稳定字段键，并按选项、布尔、自由输入和结构化引用复用编辑方式。后续可继续补充可见范围约束、来源定位和工艺说明，仍由同一个对象声明提供，不为每个动作另开特殊窗口或大型类型判断。

轴移动的常用设置应是“轴：X轴；点位：拍照位；完成：到位后继续”，偏移及到位误差按需展开。点位旁展示当前配方坐标和备注，原始索引在详情中可见。实际物理单位取轴的配置，不猜测所有轴都使用毫米。

### 2. 数据选择器一次展示了过多不相关内容

原输入需要先选来源类型再打开选择窗口，条件列表混合大量参数和运行身份。本阶段已合并为参数旁的【绑定数据】，提供业务名称搜索和类型筛选；条件使用业务字段名称，按左侧类型筛选右侧候选，内部身份默认隐藏，已有高级引用继续保留。输出引用校验仍主要确认字段存在，不能据此保证运行到该位置时生产者已经完成。

实现与待改进边界：[FlowSourceForm.cs](../AlphaRap/FlowProgramming/FlowSourceForm.cs)、[FlowConditionRow.cs](../AlphaRap/FlowProgramming/FlowConditionRow.cs)、[FlowResources.cs](../AlphaRap/FlowProgramming/FlowResources.cs)、[FlowPrograms.cs](../AlphaRap/FlowProgramming/FlowPrograms.cs)、[FlowActions.cs](../AlphaRap/FlowProgramming/FlowActions.cs)。

后续需要增加路径与依赖提示：全部模块仍可查找，但标出可能尚未执行的节点和跨模块等待关系。当前类型筛选是编辑推荐，不代替执行前的数值范围、整数性或结果有效期检查，不能通过把缺失输出变成空串或零来简化界面。

### 3. 读取一次、等待变化和动作完成容易混淆

io.read 只读取一次；io.wait 才持续读取并检查稳定时间。运行器的出口等待会重算条件，但不会重新执行动作；CurrentResult 是动作完成时的一份结果。如果一次读取返回 false，再等待该份 Value 变成 true，不会得到新的输入采样。

证据：[FlowIoObject.cs](../AlphaRap/FlowProgramming/FlowIoObject.cs#L18)、[FlowProgramRuntime.cs](https://github.com/JeffreyWub/NPSDK/blob/codex/flowchart-designer-20261022/NPSDK/FlowChart/FlowProgramRuntime.cs#L240)、[出口等待](https://github.com/JeffreyWub/NPSDK/blob/codex/flowchart-designer-20261022/NPSDK/FlowChart/FlowProgramRuntime.cs#L273)。

当前通过业务标签与帮助说明两种动作的区别，等待输入使用【等待状态】，稳定保持时间作为高级参数；默认 NEXT 仍可无条件继续。下一步需要在运行诊断中说明“等待什么”和“实际读到什么”。轴、气缸、扫码、视觉等动作仍由各自实现定义完成标准，保留动作只发送一次、等待只检查状态的运行原则，不能为了刷新条件反复触发运动、拍照或扫码。

### 4. 循环执行与产品身份绑得过紧

当前运行器用 visited 集合拒绝重复节点，经过 cycle.begin 才清空访问记录。开始产品周期同时改变 CycleId，结果又按 RunId + CycleId 隔离。这使同一产品的重拍、有限重试或穴位遍历需要理解产品周期机制。托盘方法目前只计算单个索引的偏移，不是完整的托盘遍历动作。

证据：[FlowProgramRuntime.Run](https://github.com/JeffreyWub/NPSDK/blob/codex/flowchart-designer-20261022/NPSDK/FlowChart/FlowProgramRuntime.cs#L198)、[FlowTrayMethods.cs](../AlphaRap/FlowProgramming/FlowTrayMethods.cs#L10)、[FlowUtilityObject.cs](../AlphaRap/FlowProgramming/FlowUtilityObject.cs#L29)。

建议分别定义设备运行批次、当前产品、循环迭代和本次动作调用。工程师看到“遍历托盘”“重试最多几次”“调用子流程”“本件结束”；框架负责身份与结果有效期。普通回跳不能自动当成新产品，也不能直接删除旧结果保护。重试要显式配置次数与允许重复的动作，避免隐式重发命令。跨工位用明确的产品交接携带上下文；多载具并行留在后续阶段，不能只靠全局变量拼接。

### 5. 视觉的正确性约束需要保留，但不应要求手填运行编号

保存照片和读取指定 VPP 输出底层仍绑定 RunId，用来拒绝被新拍照覆盖的旧结果。界面现已改成【来源拍照节点】，候选限定为当前实际 VPP 的拍照执行节点，框架自动绑定其结果编号。现有存图仍使用本站最近图像，过期运行不能继续使用，选择节点不等于保留了历史照片。

实现：[VisionFlowMethods.cs](../AlphaRap/Vision/VisionFlowMethods.cs)、[来源选择器](../AlphaRap/FlowProgramming/FlowSourceForm.cs)。

多次拍照时仍需明确选择来源。后续如果需要延后存图，再设计有生命周期的图像结果句柄；不能用无限保留图像或错误使用最近图像解决问题。视觉补偿仍由工程师显式绑定到轴高级参数中的附加偏移，不自动附加运动。

### 6. 点位索引与配置状态仍让工程师承担额外核对

当前固定点位绑定使用整数索引；点位删除会改变后续索引。存在“绑定仍有效但指向另一行”的风险。旧页面与新增组合页面同时存在、各模块的 Legacy/Program/Disabled 模式也增加了工程入口选择。

证据：[FlowAxisObject.cs](../AlphaRap/FlowProgramming/FlowAxisObject.cs#L42)、[点位使用说明](HardwareResources.md)、[Flow.cs](../AlphaRap/MenuForm/Flow.cs#L114)。

建议固定点以名称和稳定身份选择，动态遍历仍保留明确的索引语义；旧索引绑定在删行或重排时列出受影响节点，要求确认，不能静默迁移。轴页面显示唯一有效对象及点位；旧布局作为同一对象的兼容视图逐步收起。新工程默认使用配置流程，旧回调模式移到迁移设置，保留禁止混跑保护。

## 用一套简单的产品操作模型承接现有能力

资源配置、流程设计、生产运行三个工作阶段共用同一工程。轴仍在轴页，IO 仍在 IO 页，VPP 仍在 VPForm，配方仍在 ProductManagerForm；不增加一个要求工程师重复录入信息的资源管理中心。流程中可查看来源并跳回对应页面，未配置对象时直接引导到该页面。

流程页保留 NPSDK FlowChat。左侧列常用动作或实际资源，中间编排流程，选中/双击节点在同一属性区域编辑。资源、动作、参数、NEXT 是常用内容；高级参数按需展开。删除继续使用命中对象的右键菜单。普通顺序节点自动连接到下一步，仍允许手动更改 NEXT；CASE 显示业务名称并保留原生编号，例如“CASE1：不合格”。

“轴移动、等待信号、气缸到位、扫码、视觉检测、保存本件记录”应先做好，原始收发、运行编号和底层接口留给高级使用。常用业务动作是原有实际对象能力的清晰入口，不创建第二套设备执行实现。

## 数据只向工程师解释用途，不暴露存储版本

- 机器设置：Setting 中的机器级参数，换配方不变。保留“设置表值”对真实表行的修改，主 Save 决定是否落盘，放弃恢复已保存值。
- 配方参数：当前型号的点位、托盘行列、视觉程序与工艺参数，由 ProductManagerForm 切换。
- 本件结果：条码、检测值、判定、照片路径和节点结果，跟随当前产品，结束时按明确消费者边界释放。

三类用途在同一个数据选择器中分组，不再分别增加许多管理页面。计数、暂存值可在当前流程/产品的高级数据中使用；不要把每一次测量都写进 Setting。上面是推荐的业务用法，不撤销用户已要求的实际表值读写功能。

DataForm 继续定义本地生产表。常见节点可让工程师明确确认一次结果映射，例如“扫码结果→条码”“视觉结果→检测值/判定”；后续“保存本件记录”读取这份产品记录，避免每个保存节点重复选择大量来源。自动建议映射必须可见、可改，不以相似名字静默绑定。保存成功后再走 NEXT；失败保留本件数据、给出可定位原因。需要随后上传时继续使用同一已保存记录，不能提前释放上下文。

## 内部结构建议

保留已建立的 IFlowObject / FlowMethod 能力声明和 FlowActions 统一执行方向。每种对象声明本身真实支持的动作，参数元数据同时驱动编辑器与校验；执行器只负责调度、数据、超时、取消及资源占用。厂商差异由具体驱动/对象实现，不集中堆进节点窗口的 switch。

逐步减少控件树承担的运行身份发现。项目内保持一份稳定实例登记，轴页、IO 页、DeviceControl、VPForm 和 FlowChat 都引用它。NPSDK 组合控件作为显示和手动操作入口，设备服务的生命周期最终由设备工程管理，不能因换页/关闭视图误建或丢失连接。这是内部职责调整，不要求工程师新增另一套资源配置。

草稿与运行版本、取消后迟到结果隔离、资源占用和保存事务应继续由框架执行。工程师界面只提示“有未保存修改”“当前使用哪一版”“哪个节点正在占用对象”，不要求理解 DataRow 的 Current/Original 或租约实现。

配方切换建议采用先预检、后整体切换的方式，校验参数、绑定点位及 VPP 依赖；失败保持原有效配方并列出具体缺项。当前 OpenRecipe 会逐模块修改内存，异常后回落到默认 Recipe 路径，尚不是整体切换事务。这会让工程师难以判断当前各对象究竟加载了哪份内容。可复用主 Save 的整体提交思路，但不新增配方入口。证据：[MiddleLayer.Recipe.cs](../AlphaRap/Core/MiddleLayer.Recipe.cs#L33)、[ProjectConfiguration.cs](../AlphaRap/Configuration/ProjectConfiguration.cs#L29)。

## 优化顺序

### P0：先让已有功能容易理解

1. 已用业务参数行替换输入通用表，提供显示名、说明、明确单位及高级折叠；后续继续完善范围和工艺说明。
2. 已合并绑定入口，提供分组、搜索与类型推荐，并实现同一 VPP 的拍照节点选择；来源页面定位及执行依赖推荐仍待完成。
3. 已在参数、帮助和使用说明中明确读取一次、等待到位和业务分支；运行时等待原因与实际值诊断仍待增强。
4. 原 Save 与配方入口保持不变；模块的 Legacy / Program / Disabled 迁移模式继续保留。节点三种执行方式使用同一运行器，迁移入口和运行版本提示仍需后续精简。

### P1：形成完整设备工艺的执行闭环

1. 分开产品与循环，提供有限重试、托盘遍历、子流程及明确产品交接；先完成单产品流程，再扩展并行。
2. 提供“本件记录”和可确认的字段映射，统一 DataForm 保存及后续上传的结果来源。
3. 已有同一执行器下的节点断点、单步及本次输入 / 输出 / 出口观察；后续继续补充未满足条件、实时等待原因、资源占用者和用时，保留原权限及硬件状态检查。
4. 补齐点位删改/重排引用保护和配方整体切换失败保护。

### P2：提高复用和长期维护能力

1. 将调试通过的扫码、检测、搬运和保存流程做成可参数化子流程/模板，内部节点仍可查看，避免黑盒套黑盒。
2. 分开应用工程师编辑视图与操作员运行视图；扩充工程版本、差异查看和可恢复的项目导出。
3. 逐步收敛控件/驱动职责及旧工程兼容层，不继续新增无关大模块，不一次替换整个 NPSDK 执行基础。

## 下一版的验收方式

先交付一条完整工艺：等待有料 → 夹紧并到位 → 移动至拍照位 → 扫码 → 执行指定 VPP → 按合格/不合格走 NEXT/CASE → 保存本件记录 → 本件结束。

由不了解内部类名和运行编号的应用工程师，只通过资源页、配方页和 FlowChat 完成配置。验收必须覆盖：

- 不修改 C#，不填写内部对象路径或 RunId/CycleId；每个选择能追溯到真实页面对象。
- 条件不满足时能够直接看到当前值与期望值，分清实时等待和已完成动作结果。
- 同一产品重拍或遍历多个穴位时条码不丢失、结果不串入下一件；数据缺失不能静默变零。
- 插入/删除/重排点位时不静默改变固定点位目标；切换配方后使用该型号的点位和视觉内容。
- 主 Save、放弃修改、重新启动和切换语言后工程一致；配方加载失败保留上一有效配置。
- 本地生产记录的条码、型号、判定和测量值一致，保存失败可诊断；模拟记录明确标记。

既有回归测试用于保护底层行为，不能代替上述应用工程师操作验收。下一步优先完成这条纵向工艺，边做边删掉不必要的交互，再扩充其他动作。

## 本次交付边界
