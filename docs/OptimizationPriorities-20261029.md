# 自动化框架后续优化优先级

日期：2026-10-29。依据当前 AlphaRap ca9ed90、NPSDK 10f9fbf 及近期使用问题，重点核对流程、数据、保存与界面入口。以下为建议，并非已实现能力。

现有基础：统一主保存、语言/配方入口、原生代码与拖拽混合节点、动态日志模块，以及 Gantry 心跳页的唯一文档试点。现有离线回归不代替实机长期运行、MES 联调和性能测量。

## P0：先保证可信运行

### 1. 把产品随行数据做成独立能力

当前基础：已有节点输出、CycleId、生产记录与日志；FlowResultHub 是运行期内存结果，Reset 会失效旧结果。它还不能代替转盘上每件产品的持久随行卡。

建议工作：建立稳定 ProductId，将条码、治具/穴位、当前工位、工序结果关联起来。扫码、点胶、称重、AOI 都读写同一产品；确认实际转位完成后才更新位置映射。

完成标准：两件以上产品并行不串数据；停机后可恢复在制记录并确认实际位置；节点重试不会把结果写给下一件。

代码依据：NPSDK/FlowChart/FlowProgramRuntime.cs；AlphaRap/FlowProgramming/FlowProductionData.cs

### 2. 把唯一流程文档从心跳试点推广到全部流程页

当前基础：Gantry 心跳页已有文档归属和 VS 只读预览；其他页面仍保留源码布局和旧配置兼容路径。

建议工作：统一 PageId、NodeId、ResourceId 和修订号。删除、移动、连线、入口修改只经过同一组命令；VS 提供同源预览或打开同一编辑器。首次迁移显式确认、保留备份。

完成标准：所有 Flow_BaseForm 页面保存重开后节点和连接一致；删除不会复活；改显示名、切语言和改容器 Name 不破坏身份；VS 未保存编辑的冲突有明确提示。

代码依据：AlphaRap/FlowProgramming/FlowDocumentPages.cs；FlowControlSource.cs；docs/FlowDocumentPilot.md

### 3. 收拢整机、流程组和节点的状态判定

当前基础：已有初始化重试、多入口、暂停、停止和资源归还屏障，并有相关回归；仍需要将这些规则作为统一状态契约，避免各界面再推导另一套状态。

建议工作：明确初始化中、初始化故障待重试、运行、暂停、停止中、待机的转换。初始化继续仍用初始化按钮；明确停止后结束会话，再初始化从入口开始。硬件状态由实际动作处理。

完成标准：显示待机时没有遗留执行任务；暂停计时按约定处理；停止清理流程计时和续跑点，但不误删产品履历；不重新引入全机轴/IO 就绪扫描。

代码依据：AlphaRap/FlowProgramming/FlowPrograms.cs；Core/MiddleLayer.RunControl.cs；NPSDK FlowProgramGroup/FlowProgramRuntime

### 4. 补齐本地结案、MES 待传和恢复闭环

当前基础：已有生产 CSV、日志追加和原子配置保存；产品生产事实与 MES 待传任务尚需独立的持久事务边界。

建议工作：产品完成时先持久化结果与待传任务，再后台上传。使用业务记录身份、重试次数和服务器回执；应用重启恢复待传队列。配置保存与生产记录保存分别建模。

完成标准：断网和重启不丢待传记录；重复上传可识别；MES 失败不要求重做点胶、称重或其他物理动作；明确显示已保存、待上传、上传成功。

代码依据：AlphaRap/Classes/ProductionDataStore.cs；Configuration/ProjectConfiguration.cs；AlphaRap/MES

## P1：再让工程师容易上手

### 1. 让绑定入口直接解释数据从哪里来、到哪里去

当前基础：现有绑定窗口已支持节点结果、常量和类型过滤，但用户仍需要询问如何把扫码结果传到 PalletCode。

建议工作：显示 扫码节点 → 条码 → PalletCode 的来源说明、字段类型、最近有效值、产生时间和产品身份。缺失、过期或类型不匹配的来源在保存前定位到具体节点。

完成标准：工程师能独立完成扫码、测量到生产表/日志的绑定；不需要理解内部对象路径、方法 ID 或表达式；看不到旧周期残留值。

代码依据：AlphaRap/FlowProgramming/FlowSourceForm.cs；FlowInputRow.cs；FlowActions.cs

### 2. 让代码节点和拖拽节点共用数据契约

当前基础：拖拽设备方法可声明 Barcode 等类型化输出；原生 ResultType 方法主要声明出口，不会自动导出局部变量。

建议工作：保留原生方法签名，提供统一的具名输入、输出和产品上下文访问接口；公开业务输出进入同一绑定目录。开发人员只实现能力，不再另写工具箱登记工程。

完成标准：扫码写在 C# 或拖拽动作中都能以同样方式绑定 Barcode；异常、取消、模拟及资源归属有统一约定；删除节点不删除共享函数。

代码依据：AlphaRap/FlowProgramming/FlowNativeMethods.cs；Devices/DeviceFlowMethods.cs；NPSDK IFlowObject

### 3. 精简参数编辑并补齐撤销、引用检查和操作反馈

当前基础：已有单层日志编辑、右键删除、输入绑定和条件页；新增行依赖星号空白行，表与日志、草稿与已保存的区别仍不直观。

建议工作：提供清晰的新增字段入口、单位/说明、按业务命名和适当默认值；统一撤销/重做、复制及删除引用检查；显示未保存状态和本次将保存的内容。

完成标准：常用配置不依赖口头说明；取消、放弃、保存失败不丢草稿；操作面板只展示当前动作相关参数；语言切换不重建输入。

代码依据：AlphaRap/Configuration/LogModulesForm.cs；FlowNodeForm.cs；Configuration/ProjectConfiguration.cs

### 4. 完善节点履历和工程师离线验收

当前基础：已有断点、单步和输入/输出观察面板；需要在现有基础上增加能按产品与失败节点追溯的执行履历。

建议工作：记录节点版本、产品身份、实际输入/输出、耗时、出口和异常原因。提供可控的模拟扫码、超时、断网、重复触发场景；诊断查看不能重新执行动作。

完成标准：能回答 哪件产品、哪个节点、用了什么值、为什么走 CASE1；工程师无硬件也能跑通示例流程，实机验收单独确认。

代码依据：AlphaRap/FlowProgramming/FlowDebugPanel.cs；FlowDebugText.cs；tests/FlowProgramming

## P2：持续改善扩展与维护

### 1. 统一能力目录和页面导航注册

当前基础：IFlowObject 和继承方法发现已经具备基础，但类别、窗体遍历和导航仍有集中维护点；物料管理入口问题体现了页面、标题、权限和导航容易遗漏同步。

建议工作：由能力描述提供类别、方法、输入/输出和显示元数据；页面注册统一声明标题、图标、权限键和路由。继续只暴露真实支持的功能。

完成标准：扩展 AbstractDevice、轴或 IO 主要新增继承类与能力元数据；新增页面不需要分别修改多份菜单；不为未支持驱动显示可执行假选项。

代码依据：AlphaRap/FlowProgramming/FlowResources.cs；FlowInheritedMethods.cs；MainForm.Frame.cs

### 2. 逐步隔离运行内核与 WinForms 控件

当前基础：当前实现依赖 Form、控件树及 MiddleLayer 静态对象，适合兼容现有程序，但增加独立测试和资源生命周期管理的成本。

建议工作：逐步拆成流程模型与命令、执行会话、资源适配、数据服务、界面呈现；保留既有外部入口。调度复用同一个内核，UI 订阅快照。

完成标准：核心运行测试不必创建窗口；释放页面不留下执行任务或静态事件；多工位共用资源时明确互斥、取消和归还。

代码依据：AlphaRap/FlowProgramming/FlowPrograms.cs；FlowResources.cs；Core/MiddleLayer.cs

### 3. 把性能和发布兼容变成可测量的工程能力

当前基础：已有离线回归、SDK 校验值和配置事务；尚不能用这些替代长期运行、真实驱动和性能剖析。

建议工作：按已保存修订缓存资源描述、批量刷新可见 UI；先测量轮询、磁盘、线程和刷新成本。构建 EXE/SDK/配置版本清单，升级提供备份与迁移验证。

完成标准：有可重复的长时间运行与故障恢复报告；内存、句柄及 UI 延迟有测量数据；升级不覆盖现场配置、报警表或原类库。

代码依据：SDK/README.md；tests/FlowProgramming；tests/MainDashboard；Configuration/ProjectConfiguration.cs

## 第一条验收链

以点胶转盘作为贯通样例：扫码建立 ProductId → 关联治具/穴位 → 点胶 → 称重 → AOI → 装盘 → 本地结案与 MES 待传 → 上传回执。验证多件并行不串件、故障重试不重复物理动作、停止重启可确认在制状态、断网重传不丢数据。

优先把这一条链做可靠，同时将唯一流程模型推广到实际使用页面；随后改善绑定和代码节点数据契约，再推进目录、分层、性能与统一发布。
