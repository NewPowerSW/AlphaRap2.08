# 删除源码页面后的配置兼容

## 删除选项卡或容器

重新加载时，以当前 Form 的实际控件结构为准：

- 原容器已经删除，其中的旧节点从流程草稿清理，不恢复选项卡，不添加“待处理”等替代页面。
- 同时移除这些节点的初始化/自动启动入口，并清理其他节点指向它们的 NEXT、CASE1、CASE2、CASE3 连线。
- 使用原有 RemovedControls 删除标记，主保存后重新加载不会从旧配置重新创建这些节点。
- 不自动选择其他流程替代被删入口，包括 Legacy 旧配置的首次导入。剩余流程需要启动时，请明确选择入口。
- 同一个源码节点只是移动到其他仍存在的容器时，按准确的源码控件身份保留该节点、ID 和坐标。不按相似名称或列表顺序猜测容器。
- 容器路径重名、目标已释放或目标类型不能承载流程节点时，同样不进行错误的控件挂载。

其他动作若仍读取被删节点的输出，保留其原绑定以显示缺失来源；不会改成固定值或其他节点的输出。相关流程保存/执行前需要明确重新绑定。这也适用于已删除资源的方法、参数和输出字段。

## 保存与重新加载

自动清理只发生在内存草稿中。配置落盘仍使用 MainForm【保存】，不会在启动时直接覆盖现场 XML。主保存成功后，清理后的节点、入口、连线及删除标记进入同一保存事务。

容器身份仍使用 Name 路径；用户名称、节点 ID 和数据键不参与翻译。异常诊断沿用 Chinese、English、Español。ProductManagerForm 配方切换、Recipe/Setting 作用域不变。

## 删除整个 Flow_BaseForm 派生 Form

旧配置不会自动创建已经从应用删除的源码派生 Form，也不会调度其流程。未加载模块的旧定义仍保留在原工程文件中；其他模块使用其输出时必须解除或重新绑定。

通过界面新增的通用 Flow_BaseForm 是配置定义的模块，仍按配置恢复；不能和被删除的源码派生 Form 混为一类。手工删除源码类时，仍需要维护应用代码中对该类型、实例字段和业务方法的直接引用。

## 回归范围

专项测试覆盖删除嵌套选项卡、清理节点/入口/连线、主保存前不改磁盘、清理后保存重载、Legacy 入口不误替换、源码节点移动、重名路径、不兼容容器类型，以及缺失派生 Form 不创建不执行。继续执行资源绑定、配方、统一保存事务、源码生成和 WinForms 设计器回归；使用离线夹具，不执行真实设备动作。
