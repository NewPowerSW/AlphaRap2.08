# Flow_Chart 执行与停止

`FlowChart_Run` 保留现有入口、`ResultType` 和 `Next / Casse1 / Casse2 / Casse3` 属性。一条可达流程共用一个执行任务，节点切换不再释放、复用 BackgroundWorker，也不再为每个出口创建专用线程。

## 启动与链接

- 启动前冻结可达节点的回调与链接。运行期间编辑链接只影响下一次启动。
- 同一会话的重复启动直接返回；共享下游节点的不同入口不能同时占用同一图。
- 启动前拒绝已释放、跨窗体、编辑中、已托管、没有回调或绑定多个回调的节点。
- `NEXT` 未连接仍表示结束，以兼容现有流程；选中的 `CASE1/2/3` 未连接会记录故障，不能静默结束。
- 绘制连线不再清除已失效的链接，避免绘图把配置错误变成正常结束。
- `LastRunError` 提供最近一次诊断，错误进入模块报警日志，后台线程不弹模态窗口。旧 `Do_work` 入口转交会话；旧 `method` 完成回调保留签名但不再启动节点。

## 停止与网络阻塞

`Module_StopRun` 先撤销待派发的启动，再请求正在执行的旧式流程取消。已进入启动回调的工位在回调返回后会补发停止。启动回调部分失败时尝试停止全部工位；运行和报警日志使用线程安全的有界队列。

`IsStopping` 表示已请求停止；`IsLegacyRunning` 和 `task` 表示调用是否真正退出。同步网络调用仍在阻塞时，任务保持占用，拒绝重启，不把“已请求停止”当作“已完成停止”。已取消会话不会因全局标志被清除而恢复，也不会执行旧结果的下一节点。

支持取消的网络或等待操作应使用 `Flow_Chart.CurrentExecutionToken`。同步封装在调用前后使用 `Flow_Chart.ThrowIfExecutionStopped()`，避免旧读取返回后继续写入。现有汇川 `INOVANCE` 的四个底层读写入口已接入这个检查。检查不会回滚已经发送给 PLC 的命令。

当前 `StandardModbusApi.dll` 封装未暴露取消或超时设置。本实现不会强行终止其 native 调用，也不会在超时后释放占用并允许新的设备命令与旧请求并发。若厂商 DLL 永久不返回，流程保持停止中；彻底限制这类阻塞，需要依据厂商接口设置通信超时或换用可取消的通信实现，并进行断网现场验证。自定义工位 `StopRun` 也应及时返回；本改动不隔离任意阻塞的工位停止回调。

`IsPause / IsStop` 参数沿用现有语义：显式禁用普通停止的流程不响应停止按钮，但释放控件仍会撤销会话。暂停等待采用异步等待，IDLE 每 50 ms 重试一次；暂停时冻结计时，恢复不重复已完成的节点回调。

## 验证

可重复运行的专项检查：

```powershell
./tests/FlowLegacyExecution/Run.ps1 -Repeat 20
./tests/FlowMachineCommands/Run.ps1
```

旧式执行专项包含 14 项，覆盖重复启动、阻塞请求停止、取消回调阻塞、共享节点、链接快照、错误出口、暂停恢复、控件释放和异常恢复；整机启停专项包含 4 项。Debug/x64 构建通过。

本地 SDK 既有回归中，原生事件/并行入口 34 项和代码节点 13 项通过。旧套件中依赖 `elapsedTime` 子控件的 1 项界面检查已不适用于动态绘制，未计入；由本项目当前设计器套件的右上角像素检查替代。设计器套件为 58/59，剩余失败是工作区原有 `FlowDataMethods.cs` 的项目类型标记。

没有连接 PLC、相机或运动控制器，也未验证实际断网、厂商调用超时和整机停机时序。本次不增加持久化设置，不改变语言、配方切换及 MainForm Save 入口。
