# 框架五项基础边界（7.0）

## 账号

`AccountService` 负责参数化查询、认证及管理员权限检查。新增凭据采用 PBKDF2-SHA256、600000 次迭代、16 字节随机盐和 32 字节派生值，格式为 `np1$成本$盐$派生值`。验证拒绝未知版本、错误长度和无界迭代成本。

旧 MDB 的 `Password` 短列保持兼容；仅在正确验证旧密码后增加 `PasswordHash` MEMO 列，在同一数据库事务中写入哈希并清空旧密码。错误登录不迁移，已有哈希不回退到空的旧密码。公开用户列表不包含凭据；指纹回调按绑定用户名重新确认身份，不读取密码。取消登录会撤销尚未返回的界面认证结果。

现有操作员空密码政策保持兼容；不意味着所有旧账号已经安全。部署后应更新弱密码和控制数据库访问。迁移不会清理历史备份、磁盘空闲页或外部复制件。账号 CRUD 仍是即时业务动作，权限映射配置仍走主保存。

## 机器状态

`MachineState` 原子发布不可变的模式、自动会话标记和修订号。初始化、启动、暂停、请求停止与完成停止走同一存储；停止失败保持 `STOPPING`。需要一致组合时读取一次 `MachineState.Global.Current`。

旧 `SysPara.SystemMode/SystemRun` 赋值源码仍可编译，但组合会被规范化。它们已从字段变为属性；旧二进制插件必须随 7.0 重新编译。兼容入口不代表可以绕过宿主的初始化、占用与恢复封锁检查。

## 配方

ProductManagerForm 仍是选择入口，Setting 不随配方切换。整份 XML 只读取一次；所有模块从同一字节快照准备候选数据。应用可通过 `ModuleConfiguration.ValidateRecipe` 校验候选表。本站视觉判据在应用前验证，VPP 从独立字节快照加载；已有算法或已配置工位缺少目标 VPP 时拒绝切换。未配置且从未加载算法的兼容工位允许没有 VPP。

所有准备通过后应用模块数据和视觉对象，最后提交 INI 配方选择与身份。准备、应用或选择写入失败时逆序恢复，保留表实例、草稿 Original 版本和旧视觉对象。补偿失败会禁止运行。启动配方加载失败时不自动换为默认型号，不开启伺服，也不允许初始化/启动；修复后通过配方页重新加载。界面刷新失败单独记录，不伪装成配方未提交。

## 任务与关闭

`ApplicationTasks` 观察扫描、报警、编排流程、手动任务、设备操作、登录和旧日志写入。停止回调分别派发，阻塞的回调不会挡住其他回调。原任务与已发出的停止回调都结束前保留占用，异常可从 `Failures` 查看。

主窗口先取消关闭，异步等待宿主关停，再关闭窗口。应用完成整机停止、报警/扫描退出和日志排空后才释放模型、关闭伺服及连接。停止失败可保留窗口重试。旧 `Shutdown()` 仅作为程序最终清理和同步兼容入口；WinForms 事件应使用 `ShutdownAsync()`。此处不强杀进程、线程或厂商 DLL；原生调用无法返回时仍会保留停止中的占用，必须依靠设备侧超时或后续隔离策略处理。

`LogManagement` 改为唯一受监督写入者，批次写入成功才移除队列。写入失败可观察并在关停时重试；50000 条积压上限达到时明确报错。它不提供进程崩溃前内存日志的持久保障。

## 文件事务

MainForm Save 沿用配置参与者协议。正式替换前，在工作目录 `.np-transactions/<事务ID>` 持久保存清单、原始/候选文件摘要和 Windows DPAPI 当前用户加密的旧文件；暂存文件与清单显式刷新。正式文件不再额外生成普通 `.bak`。

所有目标替换完才记录 `Committed`，再执行参与者内存发布。下次 `ApplicationHost.Initialize` 在读取模型前处理事务：`Prepared` 恢复整套旧文件，`Committed/Published` 校验整套新文件。未知外部修改、损坏清单或无法解密的备份保留现场并阻止启动，不猜测覆盖。恢复需使用原 Windows 用户配置文件，且工作目录与原应用一致；事务目录必须随配置保留，不能作为普通缓存删除。

磁盘已提交而内存发布失败时，不尝试虚假的内存回滚；设置 `RecoveryRequired` 并拒绝运行、保存及配方切换，重启加载完整提交版本。保存期间也会检测目标文件的外部修改。配置目录本身仍须由可信账户管理。

## 验证边界

`tests/PriorityFramework/Run.ps1` 使用新建 MDB、独立状态/任务和测试子进程。覆盖错误认证与迁移、SQL 输入隔离、角色检查、状态组合、阻塞工作/回调、配方补偿、Original 版本、Prepared/首文件替换/Committed 三处进程退出恢复、发布失败封锁与外部文件冲突。

进程退出测试不等于真实断电验收；未验证设备运动、实际相机/PLC、硬件急停、驱动阻塞返回或 Visual Studio 交互式设计器。发布前仍需在仿真和实际设备上验证完整启停与换型。

2026-11-15 的隔离交付验证：源码 Debug/x64、7.0.0 框架包、独立包引用 Release/x64 应用构建通过。五项专项 21/21、配置参与者 12/12、无窗口模块 10/10、整机启停 13/13、旧流程 14/14、流程命令 7/7、设计构造检查 60/60 通过；真实主窗口启动、18 项统一保存与 4 项源码生成检查通过。启动测试现在先创建明确的隔离配方，不再依赖缺文件时加载默认值。

完整流程回归为 182/185；仍有三项原有界面控件定位检查在 `Enumerable.Single` 失败：原生事件页工具刷新、日志编辑器三语草稿、继承页与动态模块工具栏。它们未在本轮五项范围内修复，不能把这份结果称为完整流程全通过。
