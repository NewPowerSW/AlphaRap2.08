# 整机运行控制

本轮收敛 AlphaRap 的整机命令入口，复用 NPSDK 的流程模型、运行器和实际设备对象。配置保存仍使用主 Save，配方仍由 ProductManagerForm 切换；本轮没有增加配置文件或独立保存入口。

## 启动与初始化

`MiddleLayer.InitialAsync()` 和 `StartRunAsync()` 返回 `Task<bool>`，表示请求是否完成有效派发，不表示整段工艺已经执行完成。原有 `Initial()`、`StartRun()` 和暂停按钮入口继续使用，调用不阻塞 UI。需要等待派发的调用方使用异步接口或 `MachineCommandCompletion`。

初始化清理及旧流程自动启动准备不再使用固定 200/500 ms 延时，改为等待旧流程和准备工作实际退出。普通空闲初始化和自动启动不会因此停止无关电机。运行中的重新初始化及显式停止会执行完整的硬件停止步骤。

每次命令持有代次。停止同步撤销旧代次和 SDK 排队派发资格，旧的初始化、报警复位或暂停回调即使迟到返回，也不能重新下发启动或恢复输出。SDK 新增异步初始化和启动接口，保留原有入口。

启动派发尚未完成时收到报警暂停，按完整停止处理，撤销本次部分启动；暂停命令本身未结束时的重复暂停合并处理。派发结束后若报警仍有效，不发布自动运行成功。已经正常进入初始化会话的节点故障继续沿原检查点恢复规则处理。

## 停止状态

`RunMode.STOPPING` 追加在原枚举之后，保留原四种模式的数值。请求停止后立即清除自动运行标志，保持停止状态，直到停止回调、流程会话、手动操作、取消清理及在途准备工作全部退出。

`MachineStopCoordinator` 不依赖 WinForms 或具体驱动。各停止步骤独立派发，一个回调阻塞不会挡住其他回调。重复请求共用未完成的停止会话；完整停止可以向初始化清理追加电机和应用停止步骤。步骤按资源身份合并，显示名称相同的不同资源仍分别处理。

等待超过 5 秒时仅改变提示，不强杀线程、不释放占用，也不报告停止成功。主界面沿用现有状态牌显示“停止中”“等待停止”或“停止失败”，悬停查看等待类别或错误；流程页不增加状态条。三语切换沿用统一语言入口。

停止失败后保留错误和停止状态，启动、初始化、配方切换及维护编辑继续受阻。显式再次停止且清理成功后才能恢复待机。所有旧调用退出后才清除应用初始化标记，防止旧回调把设备重新标记为已就绪。

`MachineStopCompletion` 可等待整机软件停止完成。它确认的是软件任务和停止回调退出；电机或气缸是否已物理停止，仍依赖具体驱动能力、硬件反馈和实机验收。永不返回且不支持取消的底层调用会继续保持等待，需要在设备适配层增加明确的超时或中断能力。

## 取消与资源占用

托管流程停止立即置停止标记，在独立线程执行取消回调，避免同步取消使按钮或其他工位卡住。运行器完成任务同时等待底层动作及取消回调退出，在此之前拒绝重启。停止后不再执行下一节点或发布迟到结果；取消回调异常通过 `StopError` 和日志保留。

手动任务将排队、等待和取消清理全部计为占用。取消清理未结束前不创建新手动会话，停止期间也不接受手动执行。暂停发出的手动和电机停止任务有独立完成记录，整机停止会等待这些旧请求退出。

驱动及工位停止回调可能在后台线程执行。界面显示通过已有 UI 调度和状态通知更新；回调不应同步等待被它阻塞的 UI 线程。初始化恢复原有会话、已完成节点结果及报警清除规则继续保留。
