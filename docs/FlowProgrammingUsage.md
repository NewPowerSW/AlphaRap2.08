# 设备流程设计器使用说明

先在原轴、IO、视觉、设备、常量和数据页面配置实际对象，再在 FlowChat 中选择对象的方法、填写参数、设置下一步。当前节点只保留【现有功能】和【仅判断条件】；C# 脚本与代码模块已移除。工具箱和生成源码见 [FlowChat 功能工具箱](FlowToolboxUsage.md)，完整操作见 [AlphaRap 操作 SOP](AlphaRap操作SOP.md)。

## 打开与创建

复杂逻辑可使用当前 Form 的原生代码函数，自动进入本页【代码流程】工具箱，与普通动作共用运行和保存机制，见 [原生代码 FlowChat](NativeFlowEvents.md)。原生节点直接按函数返回值跳转，只配置出口目标。

机器处于 IDLE，用有流程页面权限的维护员或管理员进入【流程】，选择模块及初始化页／自动页，启用【编辑流程】。所有 `Flow_BaseForm` 派生页面共用此入口。

模块统一使用混合节点流程，不再选择旧流程或可配置流程。勾选【启用流程】参加机器运行，取消勾选停用该模块；变更统一由主【保存】提交。工具栏按实际内容收高，代码工具直接显示函数名，搜索和切换语言会保留选中条目。

从左侧工具箱拖入实际对象动作，或双击／按 Enter 添加；也可用【添加节点】再配置。拖动节点安排位置，功能和条件节点可双击或右键【属性编辑】；代码节点只通过右键属性维护流程设置，双击不打开编辑窗口。拖入对象动作已选好该对象和方法，普通新增仍需明确配置。

节点顶部两种方式：

- **现有功能**：在【动作设置】选择类别 → 实际对象 → 对象方法，动作完成后发布方法声明的输出。
- **仅判断条件**：不执行设备动作，在【下一步】读取有效数据并选择出口；没有独立采样或动作输出。

对象目录只列已有实例和其实际支持的方法。不存在轴、VPP 或 IO 时先回到对应页面建立；对象丢失时保留原身份供修正，不自动选择第一项或替换为零。开发者新增工具按 [继承类并自动生成工具](InheritedTools.md) 实现：普通公开业务方法自动发现，不另写工具箱登记工程。

## 参数怎么填

参数按业务名称和单位显示。文字、数值直接填，布尔选是／否，轴【目标点位】只从该轴唯一绑定表的有效行中选择。P1 的内部索引为 0；添加、删除、排序点位后重新核对绑定。

【显示高级参数】按需展开轴附加偏移、到位误差或输入稳定时间。已有非默认高级值及绑定会自动展开；收起不删除或重置数据。

参数旁【绑定数据】把固定值、机器 Setting、当前 Recipe、节点输出和上下文集中在同一搜索窗口，按字段类型筛选。选中后显示业务名称，稳定路径与身份自动保存。固定值可直接输入或从参数行右键【使用固定值】恢复。NEXT／CASE 两侧也可选择这些来源。

【读取输入】仅采样一次；需要等待变化时使用【等待输入稳定】并设置目标状态。重复比较前一次采样不会重新读 IO。

## 下一步、超时和报警

1. 新节点只有 NEXT，默认【无条件通过】。顺序执行只需选择跳转目标；【结束】表示本模块本次执行结束。
2. 需要判断时选【所有条件满足（AND）】或【任一条件满足（OR）】，填写左值、比较和右值。布尔可直接选 true／false，数值比较值不能为空。
3. 【+ 添加条件】增加条件行，行内右键删除。按需【添加 CASE】增加 CASE1～CASE3，每个出口独立设置条件及目标。
4. 动作执行一次后，按 NEXT → CASE1 → CASE2 → CASE3 选择首个满足条件的出口；均不满足则继续检查条件，不重复发送动作。无条件出口只能放最后，不能用无条件 NEXT 遮住 CASE。
5. 【超时与调试】设置超时毫秒、异常报警号和执行前断点。计时包含动作与出口等待；时间到独立报警，异常和超时不自动跳 CASE。

条件节点读取上游结果或其他有效来源，不重新触发上游动作。真实报警沿用 NPSDK.Alarm.Show；留空报警号使用框架兜底号，现场应绑定含义明确的报警。

## 常见对象怎么用

- 轴：选择轴页面真实对象，移动到其绑定表的点位；位置、停止、回零等使用同一实例。视觉或托盘偏移须显式绑定 Offset，不自动叠加。
- IO：DI 提供读取与稳定等待，DO 提供设置和状态读取；气缸在独立类别。显示名称沿用实际控件 Text，内部身份不因改名变化。
- VPP：选“相机名／VPP 名”并绑定真实 ToolBlock 字段。读输出／存图时选择同一 VPP 的【来源拍照节点】，自动引用 RunId；VPP 再运行后旧结果可能失效。
- 常量：选择 Setting 或 Recipe 的【读取常量值】／【设置表值】，选键、填新值，保留原类型。设置修改实际表行，停止后主保存才写文件；主保存【否】恢复已保存值。
- 托盘：按当前配方行列与间距计算穴位 OffsetX、OffsetY，再把结果绑定到对应轴 Offset。只计算偏移，不自动搬运或管理产品。
- Device／PLC：调用实际实例的方法；设备、轴和 IO 派生类的公开业务方法自动进入目录，新协议由开发者先实现一次，浏览目录不会另建或连接设备。
- 流程与数据：传值、计算、索引计数、等待、操作员输入、报警及产品周期管理。
- 本地保存：DataForm 定义生产字段后主保存；节点选择保存方法，把所有业务字段绑定完整，返回 RecordId 和 Path。

## 配方与数据传递

型号只从 ProductManagerForm 切换。流程与对象身份为机器配置；Recipe 常量、轴点位和 VPP 沿用当前配方，Setting 独立。先保存原页面资源和参数，启动使用已提交快照，运行中不换型。

下游参数点【绑定数据 → 节点结果】，选择来源模块、节点和字段，无需写取值代码。结果必须在当前运行和产品周期中完成；旧批次、取消、缺失或其他产品结果会报错。可通过【开始产品周期】关联条码，并在本件所有保存／上传完成后【结束产品周期并释放结果】；它不是转盘多产品跟随服务。

## 保存、重载、旧定义与删除

模块勾选【启用流程】，设置有节点页面的初始化及自动入口；没有节点的页面可保持【结束】，正式启动仍先主初始化。空模块可保存为待编排页面，无关模块取消启用。初始化、启动、暂停和停止沿用主界面按钮。

加载旧工程时，旧模式统一迁移为混合节点流程。保留已选入口、节点位置、连接和唯一原生事件绑定；缺少入口时仅推断原页面唯一的无入边原节点。存在多个起点或循环无法确定起点时，必须明确选择入口后再保存、运行。旧 Script／CodeModule、外部或多播事件等不能精确迁移的绑定仍须修复，不回退旧运行器。

节点【确定】只提交草稿，【取消】保留原定义。流程校验后主【保存】统一落盘并生成所属 Form 的 `.Flow.g.cs`；重新加载仍以机器 Setting 的 `FlowPrograms.xml` 为准。删除节点后再保存同步删除生成定义，不删除手写文件。语言切换只刷新文案，业务键、参数、对象名和编辑值保留。

旧 Script／Code 节点可加载但禁止保存为可执行配置及运行。打开时提示停用，不自动选择替代方式；明确选【现有功能】或【仅判断条件】重新配置，或解除引用后删除。取消不修改旧定义，不会自动转换脚本逻辑。

节点右键删除，有数据引用先解除；流程模块必须连同子容器均无 FlowChat 节点才允许删除。删除只是草稿，主保存后生效。【重新加载】只处理流程草稿；整套配置放弃使用主保存【否】。

## 调试

节点右键设断点并主保存，退出编辑，流程页开启【节点调试】，沿用主【初始化／启动】。先停入口，【单步执行节点】执行一个完整动作，【继续】到下一断点。观察输入输出与出口快照，不重新读硬件。

暂停在节点边界生效，开始的动作继续完成；停止请求取消并等待真实调用返回才释放资源。超时和取消仍需现场验证。当前不提供节点脚本编译或脚本行级调试入口；宿主方法调试由开发人员使用匹配 EXE、DLL、PDB 和 Visual Studio 完成。
