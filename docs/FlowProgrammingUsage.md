# 设备流程设计器使用说明

当前节点只有【C# 脚本】和【仅判断条件】。流程工具箱对应提供【C# 脚本】【条件节点】两项。设备对象仍在原页面配置，脚本通过其已声明方法调用；当前版本需要编写小段 C#，不承诺拖拽后完全免代码。

设备完整操作见 [AlphaRap 操作 SOP](AlphaRap操作SOP.md)，脚本接口及范例见 [节点 C# 脚本与调试](FlowScripts.md)，工具箱和生成源码见 [流程工具箱](FlowToolboxUsage.md)。

## 打开并准备流程

1. 运行完整程序，登录具有 Rapid／流程页面权限的维护员或管理员，设备处于 IDLE。
2. 进入【流程】，选择模块以及初始化／自动子页。新增通用模块使用【添加流程模块】。
3. 使用配置流程的模块设为【使用可配置流程】，无关模块设为【停用此流程模块】；勾选【编辑流程】。
4. 从【流程工具箱】拖入脚本或条件节点；双击条目、按 Enter 或【添加节点】也可添加。普通添加默认是脚本。

模块模式【保留原流程】使用原业务回调，不会把旧节点转换成脚本。同次机器运行采用配置流程时，其他模块须明确选配置流程或停用，不能混用原回调共同驱动设备。

## 编辑脚本节点

双击节点或右键【属性编辑】，在顶部选择【C# 脚本】。同级页面分别处理一件事：

- 【C# 脚本】：只写函数体，支持编译检查、源码行号和自动换行。
- 【输入输出】：定义端口、绑定输入、选择实际对象并插入方法。
- 【下一步】：设置 NEXT／CASE 的条件和目标。
- 【超时与调试】：设置超时毫秒、异常报警号和执行前断点。

新脚本默认有数值输入及输出 Value，示例为 `Outputs.Value = Inputs.Value;`。在【输入输出】用【+ 输入】【+ 输出】增加端口，实际行右键删除。端口类型为布尔、整数、数值、文本；端口名是稳定 C# 标识符，切换语言不改名。

每个输入在下方参数行填写固定值，或点击【绑定数据】，在同一窗口选择【机器设置】【当前配方】【节点结果】等来源。窗口支持搜索及类型筛选；旧失效引用保留供修正，不自动改成第一项或零。源码通过 `Inputs.名称` 读取这些值，通过 `Outputs.名称` 发布结果；所有声明输出都必须赋值。

需要实际设备时，在【输入输出】选【对象】→【方法】→【插入对象方法】。界面登记【已绑定对象】并回到源码页生成分行调用。输入字典初始使用对象默认值，需按工艺替换为 `Inputs.名称` 或正确固定值。使用 `Context.Get<T>(调用结果, "字段名")` 取出需发布的结果。生成调用不自动定义端口、不自动建立节点间绑定，也不执行硬件。

对象目录只含已有实例声明的方法。轴、IO、VPP、Device、托盘、常量表和 DataForm 的能力仍可调用；不通过反射开放全部 public 方法。全新协议仍由开发人员适配一次。轴运动调用的点位索引要对照该轴自己的绑定表核对，已删除的动作设置页及其专用点位选择器不再存在。

点击【编译检查】只检查源码和端口，不保存、不执行。节点【确定】只提交内存草稿，主界面【保存】成功后才成为运行版本；【取消】保留原节点。语言切换保留源码、端口、引用及编辑值。

## 条件节点与 NEXT／CASE

【仅判断条件】不执行脚本、不发送设备命令，只显示【下一步】【超时与调试】。它可以检查常量表、已完成节点结果或上下文；不会因等待条件而重新调用上游读取动作。

1. 默认只有 NEXT，初始【无条件通过】；为其【跳转目标】选下一节点或【结束】。
2. 需要判断时选【所有条件满足（AND）】或【任一条件满足（OR）】，编辑“左值—比较—右值”。布尔值可选 true／false，数值填写有效比较值；【+ 添加条件】增加同行条件，实际行右键删除。
3. 【添加 CASE】按需增加 CASE1～CASE3，每条独立设置条件和目标。新增第一个 CASE 时，无条件 NEXT 转入条件编辑；已有单个布尔比较时，CASE1 可带入相反值，仍应逐项核对。
4. 按 NEXT→CASE1→CASE2→CASE3 选择第一个满足的出口。无条件出口只能放在最后一个已配置出口，作为默认去向。
5. 脚本只执行一次。出口都不满足时继续检查条件，不重新执行脚本或重新采样设备。旧采样结果不会自行变化；需要等输入时，应在脚本中调用对象的等待方法。
6. 超时从节点开始，包含脚本执行和条件等待。时间到请求报警，不需要超时条件；异常和超时停止当前模块，不自动跳 CASE。报警号留空使用框架兜底报警，现场应选择合适报警号。

脚本输出 Accepted 等业务键可用于当前节点条件；条件节点没有自己的动作结果，应选上游【节点结果】或其他有效来源。删除 CASE 使用其右键菜单，NEXT 保留。

## 配方、常量和实际对象

型号只从 ProductManagerForm 切换。流程 XML、脚本及对象身份属于机器配置，不随配方复制。脚本输入可绑定 RecipeData／SettingData、ProductSetting 及常量表；运行使用已提交参数和点位快照，未保存页面草稿不会自动参与生产。

Setting 常量不随换型；Recipe 常量随当前型号切换。直接在输入【绑定数据】或条件中选择对应键，无需专门添加读取节点。需要设置实际表值时，脚本选择 Setting／Recipe 对象的【设置表值】并插入调用；调用修改实际表行，不改类型、不自动写配置文件。停止后主【保存】落盘，主保存【否】恢复已保存值。

轴、IO、相机、VPP 和 Device 必须先在原页面存在。对象显示名称可变，引用使用稳定身份。删除绑定或实际对象前先处理脚本调用和数据引用；改索引、点位或 VPP 字段后核对相关源码和输入，不自动替换其他对象。

视觉调用选择实际“相机名／VPP 名”。拍照调用返回的 `RunId` 用于同一 VPP 的读取输出或保存照片方法。跨节点使用时，在拍照脚本声明整数输出 RunId 并赋值；下游声明整数输入绑定它，再传给同一 VPP 的调用。源码插入不会自动完成该数据传递。VPP 再次运行可能使旧结果失效，当前没有无限图像历史缓存。

## 数据传递和保存

下游输入【绑定数据 → 节点结果】选择来源模块、节点和声明输出。稳定身份不受显示名称改变影响；只接受同一次运行和产品关联中已完成的结果。缺失、取消、旧批次或其他产品结果会报错，不当作零。

本地记录在【数据 → 生产表字段】定义后主保存。保存脚本在【输入输出】选【DataForm · Production】及【保存 DataForm 生产记录】，插入调用，为当前表的每个业务字段提供值。`await` 完成后返回字典包含 `RecordId` 和 `Path`，需继续传递时声明文本输出并赋值。完整示例见 [SOP 第11章](AlphaRap操作SOP.md#11-本地生产记录-查询和-mes)。

主【保存】保存配置；生产 CSV 在保存调用实际执行时写入，模拟也会写入并标记 Simulated。单次纯数据脚本重量判定见 [SOP 第13章](AlphaRap操作SOP.md#13-离线练习-纯脚本重量判定)。

## 保存、重载和旧定义

为每个配置模块设置【初始化入口】【自动入口】；没有初始化动作可设初始化入口【结束】，正式启动仍先主【初始化】。点击【校验】，修复错误后主【保存】，退出所有模块编辑，再用原【初始化】【启动】【暂停】【停止】。

工程保存在机器 Setting 目录的 `FlowPrograms.xml`，当前格式 V3。主保存同时生成所属 Form 的 `.Flow.g.cs` 和 manifest；由同一运行器执行，生成文件不是第二运行器，也不是手写代码入口。源码目录通过【查看生成源码】核对。手改受管理文件会阻止覆盖，删除节点后再次保存会同步移除生成定义。

【重新加载】处理流程草稿，不能代替全配置恢复。主保存【否】放弃统一配置草稿，【取消】或关闭确认窗保留草稿。重启只恢复设计，不恢复上次硬件动作。

旧 V1／V2／V3 定义可读，但 Action 和 Code 节点已停用，不能运行。打开旧节点时先显示提示，两种新模式都不自动选择。工程师须人工改为脚本／条件并核对输入与出口，或解除引用后删除；【取消】保持旧定义。没有自动迁移，不会把旧动作默默变成空脚本。原公共条件与异常出口也须按提示重新检查。

## 删除与调试

节点表面右键【删除节点】，有下游输出引用时先解除；会清理入口和相关连线。页签右键【删除流程模块】只允许整个 Form 没有节点时删除。删除只是草稿，主保存后生效；不删除手写 C# 类型。

节点右键【设置／取消断点】或在【超时与调试】勾选【执行前断点】，主保存。退出编辑，在流程页开启【节点调试】，沿用主【初始化】【启动】，先停在入口；【单步执行节点】执行整个节点，【继续】运行到下一断点。观察面板显示快照，不重新操作设备。节点前暂停不计入该节点超时。C# 内部逐行调试使用 VS 附加，见 [脚本调试](FlowScripts.md#节点调试与-c-行级调试)。

暂停沿用节点边界，已开始动作继续完成；停止请求取消并等待真实调用返回才释放资源。脚本应响应取消，不建立失控后台任务。当前未提供自动多产品调度、任意回跳重试、完整托盘遍历或通用 MES 持久待传队列。离线校验不代替现场联调；验证数量以本次交付记录为准。
